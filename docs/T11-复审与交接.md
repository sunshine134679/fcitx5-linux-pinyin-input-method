## 3. 必须整改的问题

这里的 P0 表示按原 backlog 定义，涉及清空正确性、持久屏蔽、并发安全或数据事实丢失的验收阻断项，不表示安全漏洞评级。

### R1 / P0：后台加载失败错误进入 Ready，丢失待决策事实

位置：`core/src/learning_writer.cpp:438–447`；`algorithm/pinyin/src/pinyin_candidate_provider.cpp:1511–1532`。

已复现：清空进入 Reloading，提交一个合法事实，然后让新代 `readState()` 失败。Writer 发布空快照、置 Ready、删除 PendingCommit。恢复存储后，相同 revision 不触发重载，flush 仍失败，刚才事实没有学习。

影响：未知屏蔽视图被当作“没有屏蔽”，可见性与数据保存契约同时失效。

目标结构：存储可用性与视图授权状态分开表达。读取失败不能获得 Ready 授权；保留有界、带世代的事实并支持受控重试。失败的 flush 和析构仍须有界结束，不能简单删除 Ready 赋值后把等待改成永久阻塞。恢复只能由成功且版本有效的新视图发布完成。

验收：读取失败期间不展示或授权未知候选；合法事实不因一次加载失败被整批清空；同 revision 的存储恢复可重试；独立读库验证保留事件恰好一次；永久失败时 flush/销毁有界。

### R2 / P0：Reloading 发布没有世代/版本复核

位置：`core/src/learning_writer.cpp:421–486`，尤其 482 行。

静态路径确认、尚未做受控交错复现：worker 读到 epoch1；输入观察到第二次 clear 的 epoch2；worker 获锁后直接将 revision 写回 epoch1 并发布旧快照。事件过滤只排除比读取结果旧的事实，不能保证 epoch2 事实按 epoch2 基线决策。

目标结构：后台结果携带明确的 observed epoch 与 captured version；发布前拒收陈旧结果。世代必须单调；只在对应世代的权威基线准备好后重放该代事实。复用正常发布所需的共同不变量，避免再增加互相不一致的重放分支。

验收：在“读取完成、发布之前”用栅栏插入二次 clear，并有同代新提交/屏蔽交错；旧结果被拒绝，revision 不回退，旧词不复活，新事实恰好一次。SQLite 与 LMDB 均覆盖。

### R3 / P0：清空后旧页仍能选择，占位项仍能删除持久化

位置：`algorithm/pinyin/src/pinyin_candidate_provider.cpp:1032–1048,1173,1275–1327`；Controller 路径在 `adapter/fcitx5/src/engine.cpp:788–805,852–864`。

两项均已复现：保留清空前页面/request，观察到 Reloading 后不调用 `provider.page()`，旧 `selectConfirmed` 仍成功；读取 None 占位页后调用 `remove(0)`，会持久保存“正在更新候选/ceshi”的屏蔽记录。

目标结构：所有候选动作使用同一当前授权边界，先观察资源世代和当前视图，再验证页面身份与消费范围。拒绝旧请求不能替换成选择新页同索引。None 只能展示，不具备提交、取字、删除、反馈、命令或学习资格。显式 Enter 原文行为按原契约保留。

验收：不先读取 page 的旧鼠标、空格、数字、取字、删除路径均零上屏、零消费、零持久化；None 所有动作零副作用；敏感/禁学零学习；命令仍经当前授权；合法选择消费范围与次数不变。

### R4 / P0：异步资源发布存在无锁读取；环境初始化仍有竞态

位置：`algorithm/pinyin/src/pinyin_shared_resources.cpp:486–492` 写 revision；头文件 `pinyin_shared_resources.h:52` 无锁读取，Provider 989 行调用。后台写端持锁不保护没有同一同步机制的读端，构成 C++ data race。静态确认，当前 TSAN 未能启动，不能声称动态检验通过。

另一个静态竞态在 `core/src/lmdb_environment.cpp:294–303`：RO 先创建但尚未初始化 slot，RW 同时看到 need_init=true；二者走 initialize 后，RW 因 else-if 不再执行升级，可能拿到仍只读的环境并打开失败。现有升级测试是串行，覆盖不到。

`core/src/personal_engine.cpp:1202,1289` 等位置还在取得生命周期门前读取可变 `env` 字段，需完整核对；不能只检查最终事务调用持锁。Writer 418 行对 `stopping_` 的锁外读也需纳入同步审查。

目标结构：明确共享资源发布同步机制；所有可变环境/DBI 访问在生命周期门内；初始化与满足调用者 RW 要求在同一受保护状态决策下完成。保持正常事务并发，不回退为一把全局串行锁。

验收：受控首次 RO/RW 初始化两个顺序均成功；真实 MAP_FULL/扩容时无活动事务升级锁；保持旧快照/环境持有人直到安全退出；TSAN/ASAN 在可运行环境验证。若 sanitizer 环境阻断，准确列未完成，不能用关闭检查器替代。

### R5 / P1：Reloading 队列在加载阶段无界，裁剪发生在重放之后

位置：`core/src/learning_writer.cpp:151–160,453–480`。

已复现：worker 暂停、clear、150 次合法 Chinese Commit，queuedEventsCount 为 150。入队只在 storageAvailable=false 时限额，Reloading 起初仍是 true；加载成功后才裁剪已完整决策的事件。

目标结构：加载/故障阶段在接受事实时执行明确容量策略，保留事件顺序并说明溢出语义；限制所有待处理容器与必要的在途批次，不能只改一个可见计数。重放准备移出输入互斥锁，发布只做短时间版本复核与交换。

验收：暂停/慢读/持续读失败时持续提交，暂存队列始终≤100；上限不降低200k持久容量。测试保留事实的独立持久化次数、顺序、恢复策略，并测输入锁阻塞与降级持续时间。

### R6 / P1：Ready 只由 page 懒观察，真实 UI 不会自动恢复

位置：`algorithm/pinyin/src/pinyin_candidate_provider.cpp:1459–1463`；`adapter/fcitx5/src/inputmethod.cpp:491–500,738–777`；Controller 保留页副本。

静态链路确认：文件轮询更新共享资源，未向活动 Controller/UI 发布 Ready；Provider page 的懒刷新不会主动更新 Controller 副本。新增测试手动读 page，不能证明停止输入后占位自动消失。

目标结构：通过现有事件循环或明确的完成通知，将有效就绪结果交给活动会话；输入线程负责 LibIME/Controller/UI 重建。携带会话寿命与世代校验，不能由后台线程直接改 UI。避免增加第二套候选顺序状态。

验收：加载中显示占位，释放后台屏障后不发送任何新按键，真实 Controller/Fcitx 事件循环自动发布原组合候选，光标不变；销毁、切焦点、敏感模式及再次 clear 后旧通知无效。

### R7 / P1：异步启学后的首提交仍 join 全库构造

位置：`algorithm/pinyin/src/pinyin_shared_resources.cpp:448–461`；Provider `learningWriter():1468–1472`。

静态链路确认：setter 启动线程，但提交/反馈会调用 ensureLearningWriter 并 join。当前测试把 join 放在计时之外；其 setter 断言是小于5000微秒，也不是汇报声称的小于1ms。

目标结构：输入动作不等待全库构造；初始化期间对允许保存的事实采用同一授权、世代与有界顺序语义。禁学/敏感不产生事实；不通过暂时丢弃合法事件换低延迟。

验收：50k/200k 合成库、加载栅栏未释放时，真实 Provider/Controller 的启学→首提交→下一键返回不等待后台；最终提交恰好学习一次，禁学切回后旧异步任务不越权。

### R8 / P1：Reloading 额外忽略全部 English/Raw，绕过统一政策

位置：`core/src/learning_writer.cpp:86–88`；原政策 `core/src/learning_policy.cpp:38–42`。

English 丢失已复现。Raw 也不能整体视为敏感：原政策允许 `hello` 这类英语原文学习，只忽略符合规则的原始拼音。事件 role 不能替代敏感/禁学权限。

目标结构：按统一学习政策暂存/决策，保留原文 Enter；敏感/禁学在事实入口拦截，命令不学习。

验收：正常与 Reloading 的 Chinese、English、Raw英文、Raw拼音、Command、禁学/敏感对照矩阵一致；依赖正频次的规则使用新代真实基线。

### R9 / P1：现有测试和基准尚不构成 T11 完整验收

涉及：`tests/core/learning_writer_concurrency_test.cpp`、`tests/core/lmdb_lifecycle_test.cpp`、`tests/core/personal_engine_benchmark.cpp`。

- 首提交测试没有加载屏障，事件可能发生在 Ready 后。
- 存储故障测试仅 INSERT trigger，不会触发 readState 失败。
- 扩容交错测试默认16MiB且记录量很小，未断言地图实际增长。
- 标为 pruning 的基准预置50k、Writer 默认上限200k，没有证明达到裁剪阈值。
- observer/clear 仅50k单次样本；缺200k独立加载与启学首提交场景。
- 缺原计划要求的预热、三轮、完整分位与降级持续时间/失败恢复证据。
- 当前另有 Provider 翻译断言失败，需先定位输入词库、配置、基线差异，再决定修复；不要批量更新断言。

验收：按下节矩阵建立确定性测试；保存新失败测试修复前红灯与修复后绿灯。遵守原性能门限，不能通过少测、改名、增大阈值或降低容量宣称通过。
