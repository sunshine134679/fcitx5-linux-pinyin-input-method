## 4. 已复现问题及具体解决方案

### R5 / P1：个人词典读取失败被当作空词典，后续保存可覆盖旧数据

**触发条件**：原词典存在，但打开时没有读取权限或发生 I/O 故障；之后界面允许添加/合并等操作。目录仍可写或读取故障解除时，保存会按空基线整体覆盖文件。

**根因与证据**：

- `algorithm/pinyin/src/user_dictionary.cpp:152`：`ifstream` 打开失败直接返回空对象，接口没有失败状态。
- `tools/settings/data_controller.cpp:84`：`loadDictionary()` 只返回 entries，丢失“空/失败”的区分。
- `tools/settings/pages/dictionary_page.cpp:341`：完成读取后把返回值当成功，恢复按钮操作。
- `tools/settings/data_controller.cpp:305`：根据内存 entries 重建整份词典并保存。
- 临时词典原有 1 条；设为不可读后读取返回 0 条；恢复权限并沿相同 DataController 保存添加后的集合，最终只有新增 1 条，原条目丢失。**该复现验证数据层，UI 的允许操作链路由代码核对，未对真实个人词典执行。**

**推荐修复**：为词典加载返回明确结果，区分不存在、成功、I/O 失败与解析诊断。失败时保留最后成功快照，禁止基于失败结果执行写入，并给出重试入口。保存通过同一持久化边界验证读取版本；外部修改时报告冲突，不覆盖新内容。覆盖式操作保留一致的可恢复备份。

**验收**：权限错误、短暂 I/O 故障、损坏内容、读取后外部修改分别覆盖；通过真实页面执行添加/编辑/合并，确认旧文件内容及读取错误均不被静默丢弃；故障解除后可正常重试。不能用“文件存在”代替成功读取证明。

### R1 / P2：重载不会保存未保存设置，却提示已重载成功

**复现**：在输入页关闭“启用 ModernIME”，不保存，点击系统页“重新加载 ModernIME”。模拟重载执行成功，界面提示成功，但磁盘仍为启用，草稿仍为关闭，保存按钮仍可点击。

**根因与证据**：`diagnostics_page.cpp:238` 的提示为“保存配置后重新加载 ModernIME”；`:258` 的 `startTask()` 只读取 savedRevision 并调用 RuntimeController。`settings_shell.cpp:525` 只接了成功回调，没有保存前置操作。

**推荐修复**：由 SettingsShell 统一编排“校验 → 保存草稿 → 记录目标内容 hash → 请求重载 → 确认目标应用”。保存失败立即保留草稿并停止重载；重载期间保存了新版本时，旧结果不能宣称新版本已应用。按钮名称说明它实际会重启 Fcitx5。

**较小替代方案**：有未保存修改时禁止重载，明确显示“请先保存”。该方案改动少，但用户需两步操作；推荐统一保存并重载，避免当前语义歧义。两种方案均须保留现有保存冲突与代次保护。

**验收**：未保存合法设置、非法快捷键、保存失败、外部保存冲突、重载期间再次保存、新旧结果乱序分别验证。不能只断言重载命令被调用。

### R3 / P2：重载成功只证明状态可用，不能证明新进程或新插件已接管

**复现**：`fcitx5` 替换程序只记录调用后退出 0，`fcitx5-remote` 始终返回已有的可用状态，`RuntimeController::reload()` 仍返回 success。复现没有启动真实 Fcitx5。

**根因与证据**：`runtime_controller.cpp:363` 起启动替换后，循环验证 `-s`、`-o` 和 `modernimeReady()`；没有比较替换前后的 DBus 服务所有者、进程身份或插件身份，也没有校验目标配置 hash。`modernimeReady()` 在无输入上下文时允许“已注册即可就绪”，而页面仍统一提示“已重新加载并激活”。

这证明**成功判据存在缺口**，不等于已观察到宿主重启失败。宿主本轮只做只读探测。

**推荐修复**：重启前记录 DBus owner/进程身份；替换后等待新 owner 及进程接管，再确认插件可用与目标配置读取。运行诊断可附进程起始标识，但不能仅凭 `runtime.state` 判活。开发部署验收还须核对 `/proc/<pid>/maps` 中插件 inode。无输入上下文时报告“已重启并就绪”，有上下文且激活已确认时再报告“已激活”。

**验收**：替换命令退出 0 但无新服务、旧进程仍响应、新进程插件加载失败、无输入上下文、启动延迟以及已保存配置 hash 不匹配。普通配置应用仍优先走已有热加载，不应强制所有修改都重启 Fcitx5。

### R2 / P2：保存后的应用反馈只查一次，后来应用成功也不更新

**复现**：保存后首次探测缺少 runtime hash，显示“已保存，应用状态待确认”；随后写入与已保存内容相同的 applied hash，运行 3 秒，提示不更新；切回概览后仍不更新。

**根因与证据**：`settings_shell.cpp:780` 只发一次后台概览请求；`:903` 的完成回调无论应用消息是等待还是成功，都会在 `:912` 清空 `savedStatusHash`。引擎约 2 秒才轮询配置，首次探测早于应用是正常时序。

**推荐修复**：保留“待确认版本”，在有界期限内异步重试，收到相同 hash 的有效确认后才清除。超时如实显示待确认，保留刷新恢复入口。新保存替换目标，旧回调不覆盖新状态；关闭页面取消该页面的观察任务，不影响真实输入法。

**验收**：首次未知、旧 hash、2 秒后确认、期间再次保存、进程退出、缺少/陈旧 runtime.state、窗口销毁。必须断言最终显示结果，而非仅测试 `describeSettingsApplication()` 的字符串映射。

### R4 / P2：检查更新把本地缓存结果说成最新；刷新软件源入口没有实际操作

**复现**：模拟 apt-cache 只返回与当前相同的缓存版本。Controller 返回 `cacheMayBeStale=1`，页面显示“已是最新版本”；页面不存在 `updates-refresh-cache` 控件。

**根因与证据**：

- `update_controller.cpp:350`：APT 用 `apt-cache policy/show`，DNF 用 `--cacheonly`，均不能证明远端刚同步过。
- `package_policy.cpp` 的 `evaluateUpdateDecision()` 已区分缓存可能过期，并给出刷新建议；页面 `updates_page.cpp:516` 起自行压缩消息，忽略该信息。
- `updates_page.cpp:418` 的 `startCheck()` 永远选择 CheckOnly；RefreshCache 分支没有页面操作进入。
- `page_registry.cpp:105` 仍可搜索“刷新软件源缓存”，页面 `focusTarget()` 却将其转向“检查更新”。搜索结果不能执行名称承诺的刷新。

**推荐修复**：保留检查与刷新缓存的区别，结果显示“本地缓存中未发现更新”，说明刷新时间或尚未同步。恢复独立的“刷新软件源缓存”操作，接通既有 Controller，成功后重新检查；认证取消、离线、无软件源、缓存过期分别呈现。继续复用既有包事务所有者与 operationId，不让窗口关闭杀掉后台包管理器。

**较小替代方案**：保留终端更新引导，删除失效搜索入口及未使用页面分支，准确显示缓存状态并给出刷新命令。推荐恢复现有刷新能力，因为搜索与底层契约已声明该操作；本轮未替用户决定最终交互，也未执行真实提权刷新。

**验收**：旧缓存同版本、远端有新版本但未同步、缓存刷新成功/失败/取消、无源、APT/DNF 两渠道、关闭窗口后事务继续；真实 GTK 断言可见状态与按钮调用，不能只跑 Controller 测试。

## 5. 其他代码确认的缺口与待点验项

以下未计入上面 5 项独立复现结论：

1. **外部设置冲突缺少界面恢复入口**：`SettingsStore::save()` 已正确拒绝外部修改，错误要求“重新加载后再保存”；模型有 `reloadFromDisk()`，Shell 却没有调用。系统页的“重载”只重启进程，也不刷新模型基线。用户需关闭重开才能恢复。建议接入明确的“重新读取磁盘设置”，涉及草稿丢弃时让用户选择；`reloadFromDisk()` 也应先检查 load status，I/O 失败时不能返回成功并把草稿换成默认值。
2. **重载缺少整体时间预算**：单命令有 1.5 秒超时，但循环最多 20 次，每次含选择、启用及 3 项探测；故障路径可能累计超过两分钟。建议使用单调总期限，在剩余预算内查询，并显示当前阶段；页面关闭只停止观察，不误杀真实服务。
3. **网页跳转失败仍统一报成功**：`updates_page.cpp:392` 起，GTK 打开失败后用后台 `xdg-open`，忽略返回结果，仍提示已打开。建议确认启动结果，失败时显示可复制链接；真实桌面验证默认浏览器缺失、URI handler 失败等路径。
4. **学习备份验证存在并发误失败风险**：`data_controller.cpp:407` 起在创建备份后，比较活库此后的 count 与备份 count；期间引擎新增学习会导致安全中止。该路径不会据此清空未备份数据，但会让“备份并清空”偶发失败。应验证备份自身完整性与对应快照，不能用不同时刻的活库数量替代一致性证明；本轮未做该交错复现。
5. **桌面覆盖范围**：Wayland、不同 GTK/Qt 应用、桌面热键冲突、复制后跨应用粘贴、实际浏览器跳转、真实包授权升级、用户日常实例的完整重启与重新打字，本轮没有逐项实机验收，不能记为通过。
