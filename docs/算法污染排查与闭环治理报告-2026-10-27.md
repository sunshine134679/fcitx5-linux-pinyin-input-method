## 一、问题根因与修复方案定位 (AP01 / P1)

### 1. 缺陷表现与物理根因
- **现象**：用户在正常上下文（如输入 `le` 提交“了” 20 次）建立成熟通用词频（`learning_boost >= 1.8`）后，在模糊音输入 `ne` 下，系统错误地将非精确匹配候选“了”（`full_pinyin = "le"`，`match_priority = 0`）提升至精确匹配同级（优先级 2）。由于“了”拥有极高的一元语言模型基准分（`base_prior`）与高学习加成，彻底碾压了当前输入的正音单字候选“呢”（`match_priority = 2`），导致最终提交产生“好的了”等反直觉严重体验故障。同类问题对称出现在 `nong -> 龙`（碾压“弄”）、`si -> 是`（碾压“四”/“司”）等所有单音节模糊音对中。
- **定位**：位于 [`core/src/candidate_ranker.cpp`](file:///home/wsl/ModernIME/core/src/candidate_ranker.cpp#L184-L198) 中的 `CandidateRanker::effectivePriority`。原逻辑仅判断 `candidate.learning_boost >= 1.8` 且音节数相等（`candidateSyllables == inputSyllables`），未对单音节模糊音设置“用户曾在当前输入下明确选择该异读音候选”的证据约束，造成通用熟悉度跨输入泄漏。

### 2. 最小边界治理方案
在 [`core/src/candidate_ranker.cpp`](file:///home/wsl/ModernIME/core/src/candidate_ranker.cpp) 的晋升准入唯一入口处收紧限制：
```cpp
    const auto effectivePriority = [&candidates, inputSyllables,
                                    inputIsFullPinyin](std::size_t index) {
        const auto &candidate = candidates[index];
        if (candidate.match_priority != 0 || !std::isfinite(candidate.learning_boost) ||
            candidate.learning_boost < 1.8 || inputSyllables == 0 ||
            !inputIsFullPinyin || candidate.full_pinyin.empty()) {
            return candidate.match_priority;
        }
        const auto candidateSyllables =
            static_cast<std::size_t>(
                std::count(candidate.full_pinyin.begin(), candidate.full_pinyin.end(), '\'')) +
            1;
        if (candidateSyllables != inputSyllables) {
            return candidate.match_priority;
        }
        // Single-syllable fuzzy candidates (match_priority == 0) must not be elevated to
        // exact match priority (2) purely by generic unigram learning boost from their normal
        // pronunciation (e.g. typing "le -> 了" must not hijack "ne -> 呢", "long -> 龙" must
        // not hijack "nong -> 弄", "shi -> 是" must not hijack "si -> 四").
        // Promotion across exact match group requires explicit correction evidence under the
        // current raw input (recent_choice_bonus > 0.0).
        if (inputSyllables <= 1 && candidate.recent_choice_bonus <= 0.0) {
            return candidate.match_priority;
        }
        return 2;
    };
```
- **单音节隔离**：单音节（`inputSyllables <= 1`）模糊音候选在没有当前输入明确纠正事实（`recent_choice_bonus <= 0.0`）时，严格保持 `match_priority = 0`，绝对禁止跃迁至优先级 2，精确正音单字候选（优先级 2）得到绝对物理保护。
- **纠正事实授权**：若用户确实在当前同一 raw 输入下反复纠正选择异读音候选，会话内的 `recentChoices` 记录激活（`recent_choice_bonus > 0.0`），满足条件后正常获得组间提升，保留明确纠错支持。
- **多音节能力无损**：多音节输入（`inputSyllables >= 2`）不受此限制，已验证的 `zongwen -> 中文`、`lali -> 哪里` 等模糊音学习晋升完全保留。
- **保护范围恪守**：不关闭 LibIME 模糊解码，不降低全局学习强度，不设置“了/龙/是”黑名单，不重置或降低存储词频。
