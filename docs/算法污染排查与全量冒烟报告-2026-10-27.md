### 这类“污染”具体发生在哪里

默认 [模糊音配置](/home/wsl/ModernIME/algorithm/pinyin/src/pinyin_shared_resources.cpp:22) 启用了 L_N、S_SH 等。`ne` 召回 `le/了` 本身属于合法容错；干净库中精确组能正确压住它。

正常上下文中的选择由 [统一学习政策](/home/wsl/ModernIME/core/src/learning_policy.cpp:47) 记录。快照和 [候选特征](/home/wsl/ModernIME/algorithm/pinyin/src/candidate_features.cpp:108) 按候选自身文本、规范拼音读取通用词频。上述合成库保存的是“了/le”“龙/long”“是/shi”，没有“了/ne”“龙/nong”“是/si”的错误键。近期窗口也按实际输入分组，清理后确实归零。

缺陷集中在 [CandidateRanker::effectivePriority](/home/wsl/ModernIME/core/src/candidate_ranker.cpp:184)：

1. 原始匹配等级为0；
2. 通用 `learning_boost >= 1.8`；
3. 输入为合法完整拼音；
4. 候选和输入音节数相同；

满足这些条件，就在第196行把有效等级提升为2，与精确匹配同组竞争。这里没有“用户曾在当前输入下明确选择该异读音候选”的证据要求。正常 `le` 的熟悉度因此被错误用于 `ne` 的准入；“了”本来的语言模型分数又足以获胜。

本例当前上下文加分为0，Composer和Mixer没有额外把它插到第一位；留出复核进一步排除了近期意图残留及父词证据直接复制。当前证据支持的是**排序证据越界**，不是数据库坏键、UI下标错位或已经证实的所有学习模块污染。

## 二、解决方案与交给执行AI的边界

### AP01 的推荐处理顺序

**先收紧晋升资格，保留正确学习事实。** 通用词频继续影响合法组内偏好；合法单音节精确候选不应仅因另一读音的通用词频成熟而被跨组夺首。这是本次最小修复边界，应在Ranker的唯一准入入口处理，避免在UI或最终列表末尾补插字表。

若产品要保留用户明确的模糊音习惯，应区分两种事实：

- “我经常使用这个词”：候选自身文本、规范拼音的通用学习。
- “我输入这个raw时，反复明确选择这个规范候选”：输入与候选身份之间的纠正偏好。

跨精确组晋升只能由后一类合格证据授权。证据需对应当前输入、文本、规范拼音、角色和消费范围；无上下文正确读音训练、其他raw的学习、父词学习都不能代替它。

现有RecentChoices可提供会话内的明确选择事实，但持久模糊习惯需要明确的持久表达。优先评估已有事件字段和接口；若确实需要新增有界索引，执行方案必须说明数据格式兼容、清空世代、禁学、失效与迁移。不能只加一个会话flag便宣称重启后的个人习惯已得到保护，也不能把旧通用频率追认为以前发生过的纠正。

本次库内记录都是正确读音，应保留。调低全局学习强度、给“了/龙/是”加黑名单、清空用户词库都没有修复准入语义。直接关闭全部模糊召回或全部F1，也可能损伤已验证的 `zongwen→中文`、`lali→哪里` 学习可达性，不作为最终推荐方案。

### 修复后的必要验收

| 类型 | 必须证明的最终行为 |
|---|---|
| 正确读音学习的隔离 | 上下文正常训练 `le/了`、`long/龙`、`shi/是` 后，未发生对应纠正的 `ne/nong/si` 保持精确首选 |
| 反证与方向 | 保留 `ni/li`、`neng/leng`、`zu/zhu`，增加方向反转及其他默认模糊组；不硬编码本次三个字 |
| 明确纠正习惯 | 用户真正在同一raw下重复纠正时，按产品契约晋升；保留既有多音节模糊音和专业词学习断言 |
| 最终消费者 | 检查最终全局位置、物理首页、数字/鼠标/空格、真实提交与剩余输入，不仅比较boost或中间分数 |
| 生命周期 | 清近期、换上下文、Provider重开、独立进程、用户清空、禁学/敏感和负反馈边界保持 |
| 存储与容量 | 正确词频及规范拼音保留；200,000条能力、原生性能门限和原测试断言不变 |

本报告只提出待实施方案，没有修改或验证任何新排序政策。

## 三、AP02 / P2：反向反污染回归缺口

这是测试覆盖问题，与AP01同一生产根因相关，不额外算一个生产算法缺陷。

[现有模糊音排序测试](/home/wsl/ModernIME/tests/core/pinyin_provider_test.cpp:287) 明确关闭learning/context learning，能证明冷启动精确组受到保护，不能覆盖词频成熟后的跨输入泄漏。[已学单字不能劫持简拼](/home/wsl/ModernIME/tests/core/candidate_ranking_regression_test.cpp:378) 覆盖了 `nh` 这类非完整拼音，但本次 `ne/nong/si` 都是合法完整音节。

[日常仿真中的cang/cao检查](/home/wsl/ModernIME/tests/core/pinyin_daily_simulation_test.cpp:641) 只检查 `items[1]` 不等于特定模糊字，也不足以证明 `items[0]` 首选不会被污染。这里不据注释推定作者必然写错索引，建议保留原断言并补真正的首选/匹配身份断言。

本次实测已证明：79项注册合同与168项GTest可以同时通过，而当前源码仍能真实提交“好的了”。解决方式是将本报告的正常训练→留出输入反向场景纳入原生测试和必测合同；先让现实现失败，再验证方案。不修改预期字、降低训练规模、绕过学习或只验证排序中间值来获得绿色结果。
