## 二、R8-01 / P2：目录元数据操作吞错，可能将有效程序目录恢复成不可访问状态

### 根因及位置

新增元数据引用文件先经 `touch -r` 创建，然后在 [第 401 行](/home/wsl/ModernIME/scripts/modernime-migrate-channel:401) 使用 `chmod --reference ... 2>/dev/null || true`。权限冻结失败被忽略，函数仍返回成功，并把这个引用文件写入元数据清单。

后续 [第 669 行](/home/wsl/ModernIME/scripts/modernime-migrate-channel:669) 直接从引用文件取权限应用到目标目录。引用文件若没有获得原目录权限，使用的就是新建普通文件的默认权限。原本具有执行/遍历权限的程序目录因此可能丢失执行位。

同一新增恢复段的 [第 670 行](/home/wsl/ModernIME/scripts/modernime-migrate-channel:670) 也忽略 `touch -r` 恢复失败，未设置 `rollback_failed` 或 `target_restore_failed`。因此元数据恢复不完整时仍会到 [第 723 行](/home/wsl/ModernIME/scripts/modernime-migrate-channel:723) 删除事务材料。这里是同一项元数据错误处理缺陷的准备、恢复两个分支，不拆成多个阻断项。

### 确定性复现

全部使用自有临时目录、普通文件和假包步骤，没有真实包管理或日常数据操作。先创建程序目录 `target/share/modernime/pinyin`，权限 0751，mtime 固定为 `1600000000123456789` ns，内部为自有模型测试文件。

1. **权限冻结失败：** 临时 PATH 的 chmod 包装器只对该目录对应的 `target_mtime_refs/ref_*` 权限冻结调用返回 74，其余 chmod 全部执行真实 `/usr/bin/chmod`。假包有调用标记，改写模型后返回失败。
2. **时间恢复失败：** 临时 touch 包装器只让从该引用文件恢复到 `pinyin` 目录的那一次 touch 返回 74，其他 touch 全部正常执行。

仓库入口与当前真实生成包入口均复现，主审在另一个新目录再次执行，结果相同：

| 场景 | 已观察到的结果 |
|---|---|
| 权限冻结失败 | 故障命中后仍调用包步骤；回滚后目录从 0751 变为 **0664**（十进制 436，取决于本机创建文件的 umask）；读取模型实际返回 `PermissionError / errno=13`；事务目录被删除 |
| 时间恢复失败 | 故障命中；模型内容与 0751 权限恢复，但目录 mtime 仍为备份期间的时间；没有报告该恢复错误，事务目录被删除 |
| 无故障、无用户备份 | 0751、原纳秒 mtime、模型内容均正确恢复，无用户恢复误报，事务目录正常清理 |
| 有真实自有配置备份 | 本次 backup-manifest 确实生成，配置恢复原内容，无误报 |
| 本次自有配置备份损坏 | 保留被改写的现场配置，明确报告恢复异常，事务材料保留 |

新矩阵 **6/10 PASS，driver exit 1**；四条失败对应同一问题在两种入口上的两个分支。错误代码没有被误报为产品 exit 0：产品仍因包步骤失败返回 1。stderr 的 `Original installation restored` 指源安装，源确实恢复，不以这句文本单独建立目标恢复成功的指控。问题依据是目标目录实际权限错误、模型访问失败，以及恢复材料被清理。

首次探针尚未捕获目录执行位丢失后的读取异常而中断；原脚本与 traceback 均保存。后续把注入范围收窄为单个目录的权限引用，并将读取的 EACCES 保存为观测值，没有放宽失败断言或修改产品。后续两次完整运行均为上述结果。
