## 3. I1 / P1：组合测试回退加载了原 checkout 的手工故障库

这是已观察到的测试集成问题，不是新的输入法业务缺陷。

观察的集成 SHA：`a42fc8a920f01ad35a4806e5469a818f06311e8a`，路径为 `.worktrees/parallel-integration-20261017`。

实际接线 `tests/CMakeLists.txt:747–768`：

```cmake

```

其默认输出为：

```text

```

但 `tests/adapter/adapter_recovery_test.cpp:307–323` 只自动查找 `config_fault_hooks.so`，随后允许绝对路径回退：

```text

```

当前组合门禁原始日志实际打印：

```text
Using hooks library: /home/wsl/ModernIME/build/architecture-debug/tests/config_fault_hooks.so
```

本轮还只读观察了组合 worker 的 `/proc/<pid>/maps`，确认其确实映射了该原 checkout 库，而不是组合构建出的 `libconfig_fault_hooks.so`。

风险是：已有工作区可能绿色，干净机器或克隆中不存在这个绝对路径库则失败；即使本次两个库行为相同，组合测试也没有绑定到当前构建产物。不能据此宣称 clean-clone 门禁成立。
