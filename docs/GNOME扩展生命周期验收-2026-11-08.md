## 用户可见变化

1. 仅当前 GNOME 图形/DBus 会话会自动部署。安装了 `gnome-shell` 不能再触发其他桌面或 headless 环境的扩展复制。
2. 完整目录的内容、类型、权限及新增文件/空目录均参与所有权验证；已有用户副本、用户改动、链接和无记录旧副本保留。暂存严格编译通过才发布；记录发布失败恢复原副本，进程中断保留并报告恢复材料。
3. GNOME Shell 返回的真实 Path 必须匹配受管目录才申请启用或恢复设置。文件部署、启用申请与当前 Shell 活动状态分开显示；未发现的新副本提示重新登录后初始化，用户后续禁用受到保护。
4. 源码/便携卸载先清理未修改的受管副本。设置恢复失败停止卸载并保留可重试入口；恢复重试检查步骤前后状态，不撤销失败后的用户新选择。用户已手动删除副本时只释放记录，并明确保留无法确认归属的 Shell 设置。
5. 渠道迁移在包事务中保留扩展，目标包验证成功后交接未修改副本的 prefix 所有权。源码迁移失败回滚不会先丢失扩展；已安装工具也执行相同交接。交接失败保留助手及精确重试命令，不能伪造包回滚或重复包迁移。
6. 初始化失败会保留原退出码；源码、便携及迁移消费者明确报告“程序已提交、会话未完成”。native 包不扫描用户家目录；普通用户在卸载包前运行 `modernime-session-init --remove-gnome-extension`。

## 实机范围、兼容与回退

- 用户选择 Ubuntu 24.04 + GNOME。本机只读核对为 GNOME Shell 46.0，现有 Kimpanel `Path`/`State: ACTIVE` 输出与解析契约一致；不是新版本扩展部署/加载验收。
- 日常 pid4332 的两个插件 inode/hash 与上一批一致；原主检出 README、settings_widgets.cpp 的用户改动 hash 不变。
- 本次仍使用用户目录的 LMDB 头文件、GTest 与 Benchmark；运行时 LMDB 解析到用户目录同名共享库，已保存映射，不能称为干净发行版依赖验收。缺少 appindicator 开发库，本次未编译托盘支持。
- 真实 GNOME 新扩展发现/加载/卸载、Wayland、跨 DPI、长期运行未在本批验证；原生 rpmkeys/rpmsign/dnf 未执行，gpgv、摘要校验、模拟 rpmsign 及 fallback 分支执行。不能把测试替身结果称为这些实机验证。
- 旧版副本没有可靠所有权记录，不追溯认领。回退到尚无新保护的旧版前须备份扩展并避免运行旧版初始化脚本；保留 JSON 不代表旧程序会遵守它。
- 原子发布范围是正常 I/O 失败回退及进程中断时保守保留，不保证断电事务，也不防御同 UID 恶意实时替换目录。手工删除副本后保留的启用数组成员可能是陈旧项，由用户确认归属后处理。
