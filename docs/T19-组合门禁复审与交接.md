## 2. D1：设置侧三项失败先调查共同包锁依赖

### 已有静态与动态证据

`UpdateController::isPackageManagerLocked()` 会读取宿主真实 `/var/lib/dpkg/*lock*`、APT、RPM/DNF 锁，以及测试环境变量。它没有因请求 PATH 指向假 pkexec/dnf 就自动变成隔离的锁事实。

`package_policy.cpp::evaluateUpdateDecision()` 在版本、来源、cacheMayBeStale 等字段都正常时，仍会因 `packageManagerLocked` 覆盖“本地缓存已最新”文案。这与第219行此前各字段断言已通过的路径相符。Shell GTK 和 R06 的 `refreshPackageCache()` 也会在启动前因相同锁事实返回 false。

本轮使用私有目录和全部假命令，在子进程显式设置 `MODERNIME_MOCK_PACKAGE_MANAGER_LOCKED=1`，运行原 Debug update_controller binary：**1.153s 内准确复现第219行同一断言，SIGABRT**。没有持有、释放或修改任何宿主真实包管理锁。

这证明当前测试对外部锁事实有依赖，并给出可复现的相同失败路径；**没有历史锁路径/PID/原始错误，仍不能断言那次三项失败一定由同一宿主锁造成。** “独立执行通过、全量失败”本身也不证明跨测试污染。不同 CTest 程序不共享内存；应调查继承环境、文件、后台进程、真实系统锁和时间交错。

### 推荐修复边界与验收

- 首先在失败断言前记录：包锁判定、检测路径/持锁 PID（如可取得）、相关合成环境、RuntimeResult.message、operationId/phase、CommandResult 状态/退出码/双流截断。未知真实命令不得执行，仅使用假包管理器。
- 普通“未占锁”业务测试应消费可控制的合成锁事实；将锁探测依赖与政策/操作测试边界隔离，采用最小、作用域明确的测试接缝。真实锁探测保留单独测试。
- **默认生产行为继续尊重宿主真实包锁**。禁止靠新增“强制忽略真实锁”环境开关使测试绿灯，禁止解锁/终止宿主包管理器，禁止把失败当成功或仅改预期文案。
- 验收包含未占锁正常操作、已占锁零 spawn、认证/启动失败释放、旧 ID 不结束新任务、Uncertain 持续占槽。相同的合成输入不应因宿主正在包更新而随机变义。
- 每个失败点若实际原因不同，按真实证据分开最小修复，不先重构整个 process_runner。

## 3. D2：runtime_controller 固定临时目录碰撞已独立复现

位置：`tests/settings/runtime_controller_test.cpp:27` 起固定使用 `${TMPDIR}/modernime-runtime-controller-test`，启动时 `remove_all`，随后在同一目录反复改写 runtime.state。`configuration_contract_test.sh::test_A07_runtime_state_compatibility()` 也会调用这个 binary。

本轮在 machine.lock 内，只并发两个该测试程序，全部 fake remote/fcitx，使用私有 TMPDIR：

| 对照 | 结果 |
|---|---|
| 两个实例共享同一 TMPDIR，第1轮 | 一个 Pass；另一个 exit1，`probe reads correct hash` |
| 同条件第2轮 | 相同断言失败 |
| 同条件第3轮 | 相同断言失败 |
| 每个实例独立 TMPDIR，两个对照轮次 | **4/4 Pass**，各约2.25s |

这是固定目录的可重现隔离缺陷，且错误文字与 fresh-clone 一致。它仍不能独自证明原运行中究竟是哪两个调用重叠；需结合运行时 PID、目录、调用时间确认。

推荐目标：每次进程执行使用 mkdtemp 等唯一目录，保留完整普通/兼容性断言；清理只涉及本次创建的目录。不要通过删掉 A07、移除单独 runtime 测试或将全套 CTest 串行化来掩盖固定目录缺陷。只加 CTest 资源锁也不能保护直接调用/其他 CTest 实例。

完成标准：两个实例**共享父 TMPDIR**仍各自产生不同子目录，连续受控对照全部通过；独立 CTest 与 A07 并发执行也不串扰。原错误实现的并发反例应失败，修改后通过。无需修改 runtime.state 用户格式或生产解析政策。

## 4. D3：两种性能失败都保留，先分解测量，暂不指定算法改造

精确区分场景：

| 场景 | 独立通过轮 | 失败轮 |
|---|---|---|
| 并发 SQLite | 最大20.81570ms | 本轮 Release 全量此项24.88042ms，通过 |
| LMDB 并发写/剪枝 | P99 2.20193ms、最大5.11563ms | Release 全量 P99 4.77335ms、最大46.53230ms，Fail |

不能把“独立20.82ms”写成 LMDB 修剪独立结果；它属于 SQLite。一次通过不能证明稳定，也不能覆盖完整 Release CTest 的超限。

### 已排除的调度误判

源码及实际 `release-registered.json` 均显示 benchmark **RUN_SERIAL=true**。fresh-clone.log 也记录其在其余76项完成后最后启动。所以，“install.sh 使用并行 CTest，benchmark 就必然与同一轮其他 CTest 同跑”不符合现有证据。RUN_SERIAL 不保证没有上一测试遗留的后台进程、其他 CTest 实例或宿主负载，这些仍需测量。

### 推荐调查与修复标准

- 固定当前指标口径，按同一 binary、同一数据规模记录入队、锁等待、版本观察、快照发布/回收、磁盘事务/扩容/剪枝、候选召回的耗时分解；保留原总墙钟指标，不用分段指标替换它。
- 记录峰值样本时的线程/进程 CPU、缺页、I/O、资源计数、后台工作是否已退出及上轮留下的测试私有进程。对照 fresh 独立运行与前序序列后的运行，不先断言 WSL 毛刺或剪枝事务根因。
- 若确认是算法或锁持有问题，再对对应职责做最小修改；**不要直接执行报告中“优化剪枝批量或拆分事务”的建议**。改变事务边界可能破坏原子性，降低生产剪枝保留目标曾导致误删用户数据，均不可为门禁擅改。
- 容量200k、LearningStore保留至上限、独立PersonalEngine既有剪枝目标、排序/学习/隐私/清空世代与数据格式契约全部保持。存储算法变更先读算法三份契约文档及演化不变量，再按 AGENTS 追加证据。
- 修复后完整矩阵及既有规定三轮、8项负向拒绝自检、Release完整CTest、fresh-clone均应符合原门限。无失败证据不得删；不能靠轮询碰绿、延长预热、降低负载、缩小词库或放宽30ms/5ms上限通过。
