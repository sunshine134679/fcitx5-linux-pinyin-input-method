## 2. V1 / P1：首次读取连续失败耗尽五次重试后，同 stamp 恢复永久停止

**位置：** `adapter/fcitx5/src/inputmethod.cpp:400–406,783–823`，重点为 `settingsStamp_(initResult.stamp)` 与第 789 行的 `settingsRetryCount_ < 5`。

初始化 I/O 失败时，SettingsStore 仍能 stat 出现存文件的 stamp；构造函数把这个失败读取的 stamp 放入 settingsStamp_。后续只能靠 settingsLoadFailed_ 和计数器重试。

五次轮询重试均失败后：

```text
currentStamp == settingsStamp_
settingsLoadFailed_ == true
settingsRetryCount_ == 5
```

条件两侧都为 false。之后即使 I/O 故障消失，只要配置文件本身没有再修改，就不再尝试读取。受控的后续恢复被变成了必须外部改文件或重启。

### 独立真实引擎复现

使用当前真实 ModernIMEInputMethod / Fcitx EventLoop，私有配置始终是 input.enabled=false。构造读取与五次重试均注入 EACCES；观察到第六次读取后立即解除故障，不改文件、stamp 或系统时钟。事件循环持续至约 30 秒，再发送真实 n 键：

```text
before_active=1 generation=0
fault_removed_without_file_change=1 count=6
observed_load_opens=6
after_active=1 generation=0 accepted=1 preedit=n
runtime: applied_content_hash=, settings_generation=0
disk_enabled=0 disk_font=14 disk_hash=08fedaef108b59ee
```

解除故障后没有第七次读取。磁盘禁用配置未生效。这不是要求首次故障时必须有历史有效配置，而是要求故障恢复后能够收敛到实际配置，属于上轮 S1 已要求的同 stamp 恢复契约。

### 最小修复与完成标准

- 明确成功读取事实与待重试状态；不能因为一次失败已拿到 stamp，就把该文件当成已经处理完毕。
- 利用现有轮询维持有界频率的恢复尝试，或采用明确的有上限退避；不要在输入线程无限循环，也不要把总次数从 5 提高到另一个常数后继续永久停止。
- 连续故障期间不虚报成功 Hash/generation；故障解除后同 stamp 自动收敛；永久失败不忙循环、不累计无限任务。
- 将四项已通过交错及本次“重试耗尽后解除故障”固化为正式可执行回归，至少保证新增失败分支不是只留在 build/ 探针中。现有 Missing 默认行为不变。
- 保留委托构造和同源读取 API，无需新 Manager、第二套 Hash 或新的全局配置状态。
