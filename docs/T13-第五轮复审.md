## 2. U2-A / P1 验收缺口：期限不是单调期限，超时未回收后代

**定位：** `tests/verify_fresh_clone.sh:86–117`。

### 2.1 `date +%s` 是墙钟

报告称“5 秒全局单调硬期限”，代码实际使用 `date +%s` 的整数墙钟差。时钟回拨会延长等待；这也不是一个覆盖启动前后的统一单调期限。

**独立复现：** 只给本探针私有 PATH 提供固定返回值的假 date，不修改宿主时钟；假 collector 写出 R 后停滞。当前检查段超过 **7002ms** 仍未退出，由探针外层看门狗回收。这是对墙钟依赖的隔离注入，不是宣称真实系统时钟本轮发生了回拨。

### 2.2 仅 kill collector PID，没有杀测试后代

超时分支只有 `kill -9 "$t4_pid"` 和 `wait "$t4_pid"`。假 collector 先 fork 一个睡眠子进程，再写 R 并停滞：检查段约 **4933ms** 返回 1，但 **descendant_alive_after_gate=true**。回收 collector 不等于回收该隔离任务拥有的后代。

这是测试门禁清理缺口，不应通过修改生产包事务为“超时就杀”来修。生产事务的 Continuing/Unknown 语义保持原样。

**最小目标：** 使用现有 Python 等已有能力，以单调时钟建立一次总期限；把本安装合成任务放入明确归属的独立进程组/受控进程树，超时和失败回收本测试拥有的假资源。避免以 PID 搜索误杀其他用户进程，不增加系统依赖。

**完成标准：**

- 正常任务成功；握手前和握手后停滞均在总期限及明确容差内非零返回。
- 墙钟回拨/固定墙钟注入不改变该期限；不修改宿主时钟。
- 假 collector 有后代时，门禁结束后无存活的本测试后代，直接子进程已回收；相关目录/FD 清理受控。
- 清理不能触及生产包事务，不使用全局 pkill 或模糊名称匹配。

## 3. U2-B / P1 验收缺口：重复字段被最后一个值覆盖后放行

**定位：** `tests/verify_fresh_clone.sh:147–163`。

`json.load()` 默认接受重复 key，以最后一个值覆盖前一个。原 U2 已明确要求拒绝重复关键字段；切换到 JSON 库并不自动满足该契约。

**独立复现：** 私有假产物写出 R，输出预期双流标记，退出 0，并产生：

```json
{"operationId":987650,"operationId":98765,"token":"install-token-98765","state":"Exited","exitStatus":1,"exitStatus":0}
```

当前安装检查段 **返回 0**。错误 ID 和失败码被覆盖后，检查器只看到了最后一个合法值。

**最小目标：** 用现有 JSON 接口在构建对象前检测并拒绝重复 key，例如受限的 `object_pairs_hook`。保留精确类型、ID/token、终态与退出码检查。按照上一轮要求补目录/文件权限、尾部/诊断文件与状态大小的预算断言；当前代码只检查了 state 文件大小，未完成其余资源验证。

**完成标准：** 重复 ID、重复退出码、重复 token（包括两值相同的重复 key）均非零；错类型、错身份、损坏/缺失状态、错标记、超限文件均非零；真实安装产物成功任务仍通过。不要复制出一套与安装检查不同的验证器来证明安装检查正确。
