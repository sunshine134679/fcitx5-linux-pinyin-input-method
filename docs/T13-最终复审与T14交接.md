## 3. T14 的原定目标与边界

原计划：`docs/superpowers/plans/2026-10-16-架构整改实施与验收方案.md` 的 T14「配置应用版本与路径（P2-01）」。

当前可直接定位的入口：

| 职责 | 当前文件/入口 |
|---|---|
| 配置格式、内容 hash、保存冲突、路径值 | `core/include/modernime/core/settings.h`、`core/src/settings.cpp`；SettingsStore、SettingsPaths::fromEnvironment |
| 运行时配置观察与应用 | `adapter/fcitx5/src/inputmethod.cpp`；pollFileChanges 目前仅比较 last_write_time |
| UI 独立配置观察/绘制缓存 | `ui/fcitx5/src/ui_addon.cpp`；mtime 观察与布局/字体度量缓存 |
| loaded/edited/saved 状态 | `tools/settings/settings_model.cpp`；SettingsWindowModel |
| 运行时环境与客户端应用信息 | `tools/settings/include/modernime/settings/runtime_environment.h`、`tools/settings/settings_shell.cpp` |
| 安装/启动/管理路径转换 | `install.sh`、`scripts/modernime-session-init`、`scripts/modernime-data-guard` |

T14 解决两个明确问题：仅用 mtime 容易漏掉同时间戳替换；安装/管理覆盖与进程实际 XDG 路径必须有明确启动边界。不能借机合并所有配置状态、改学习存储格式或扩大 UI/DataController 职责。

### 目标结构

- `SettingsFileStamp`：device/inode/size/mtime/ctime 等物理变化证据，作为重读失效条件，不把 stat 等同于语义内容。
- `SettingsApplicationVersion`：contentHash + 会话 generation，标识真实已应用配置。只用于运行内存/兼容诊断，不写入用户 settings 格式。
- core 提供与平台 UI 无关的配置/版本读取能力；adapter 负责应用业务设置并向页面提供应用版本；UI 管绘制和命中边界。兼容性独立读取携带可比较内容版本与布局代次，不得覆盖新布局。
- loaded、edited、saved、applied 分别代表不同事实，保留职责边界；不要为了“统一状态”抹掉保存冲突与未保存编辑。
- 运行程序按 XDG_CONFIG_HOME/XDG_DATA_HOME→HOME 解析。MODERNIME_* 仍属于安装/管理覆盖，在启动边界明确转换成 XDG/env；不要偷偷增加 C++ 隐藏优先级。
- runtime.state 是可再生诊断，不证明进程存活。扩展兼容旧字段和未知字段；不能兼容时先复用已有 hash/generation，不改用户数据格式。

### 不变行为

候选来源、排序、混排、分页语义、学习资格、隐私模式、容量、清空世代、包操作槽位、生产事务超时契约和数据库位置/格式均保持。字号调整可以使旧布局失效，但不得借机改变语义候选顺序或把旧点击坐标解释成新候选选择。

## 4. T14 实施与验收路径

1. **先确定契约并补失败测试。** 对齐原七份必读文档与 T14，记录受影响配置项、应用所有者、文件失效条件、路径优先级和预期差异。缺失/非法/不可读文件分别按明确契约处理，不把读取失败伪造为成功应用。
2. **引入最小 stamp/应用版本。** 复用已有 SettingsStore/contentHash，避免新 Manager/配置总线。物理变化触发重读，应用版本说明真正应用内容；相同内容替换避免无收益的重复重建。
3. **迁移 adapter/UI 观察。** 保持组合输入与选择映射；旧字号布局/命中边界拒绝；敏感上下文热载仍不越过禁学/剪贴板权限。
4. **统一启动路径边界。** 只在安装/管理到 runtime 边界映射环境；空格路径经 argv/env 原样传递。用隔离 HOME/XDG/管理覆盖和 SQLite/LMDB 活动库验证，禁止迁移、删除或误打开宿主旧库。
