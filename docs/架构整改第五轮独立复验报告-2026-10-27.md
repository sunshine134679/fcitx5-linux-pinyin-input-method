## 三、仍须修正的代码逻辑

### R5-01 / R4-02 · P1：名称清单不是目标对象前态

位置：[建立路径表:308](/home/wsl/ModernIME/scripts/modernime-migrate-channel:308)、[只写路径:329](/home/wsl/ModernIME/scripts/modernime-migrate-channel:329)、[跳过既存项:367](/home/wsl/ModernIME/scripts/modernime-migrate-channel:367)、[只恢复源安装:419](/home/wsl/ModernIME/scripts/modernime-migrate-channel:419)。

新清单有效修复了“包命令没写任何目标，却清掉原有插件”。但清单没有保存内容、权限、对象类型或链接文本。包操作部分写入后失败时，跳过同名路径只能留下改写后的对象，不能恢复目标前态。

真实仓库入口、真实生成包入口分别运行以下本地夹具，包回滚命令均为 true：

| 既存对象及本次改动 | 回滚结果 |
|---|---|
| 原插件 `target-original` / 0751，被包操作改写内容和权限后失败 | 仍为 `target-overwritten` / 0600 |
| 原 `share/modernime` 中字典被覆盖，另新建本次文件后失败 | 原字典未恢复，新文件残留；无关 keep.dat 保留 |
| 原内部插件链接被替换为普通文件后失败 | 普通文件残留，链接类型和链接文本未恢复 |

这些例子源安装与自有用户数据均正确恢复，失败集中在目标对象。包完全不改写时保留既存对象、此次新建文件失败后撤销的正常对照均通过。

主结论使用不删除目标的 true 回滚命令；另两例“传入回滚命令主动删除目标”仅为补充观察，不据此要求 migrator 保证任意外部命令的行为。六个主失败断言不是六个独立缺陷，也未证明它们是本轮新引入；它们说明 R4-02 的完整前态保护仍遗漏。

**解决要求：** 对受控目标建立足够的对象前态及本次变更记录，失败时恢复被改写对象并撤销本次新增项；不能只跳过同名路径或整个既存目录。若无法安全恢复，应在变更前拒绝，或明确保留可用恢复材料和状态，不能宣称完整恢复原状。保持已修复的物理路径和包归属保护。

证据：[安装组报告](/home/wsl/ModernIME/build/architecture-fifth-acceptance-20261027/installer/安装组第五轮独立验收.md)、[主审复跑](/home/wsl/ModernIME/build/architecture-fifth-acceptance-20261027/主审安装/复跑.log)。新矩阵 12/20 通过、退出 1，其中 6 个主失败、2 个上述补充观察；仓库/生成入口卸载转发 8 项全部通过。

### R5-02 / R4-03 · P2：负反馈不改变三字段，仍会绕过删除冲突识别

位置：[BaselineFact:251](/home/wsl/ModernIME/core/include/modernime/core/personal_engine.h:251)、[删除比较:1743](/home/wsl/ModernIME/core/src/personal_engine.cpp:1743)。

BaselineFact 只记录 hit_count、last_selected_ms 和 suppressed。真实 RecordNegativeFeedback 可以仅增加 negative_feedback，不改变这三项；因此它是新提交的持久事实，却被旧维护当作未变旧版本。

确定交错：旧引擎计算空 replace 后、取得写事务前，另一真实引擎完成负反馈提交并确认 feedback=1；旧维护随后成功删除该条：

```text
external_committed=1 before_delete_feedback=1 replace=1 after_delete_feedback=-1 total=0
```

主审重新执行当前源码编译的探针，结果一致。原“重新选择后不误删”已经通过，本项不重复报告其失败，也不主张有负反馈的词在正常 prune 中永远不能删除。问题是旧读取基线没有识别后续提交。影响是学习偏好/词条事实丢失，本轮按 P2 报告，不与快照内存问题混为一谈。

**解决要求：** 比较完整持久事实或可证明的读取版本，明确冲突和删除权限；不要仅逐次追加报告中出现的某个字段，也不要无条件 union 复活合法删除。

### R5-03 / R4-04 · P2：事务后读取版本会确认尚未吸收的外部事实

位置：[写事务后版本:578](/home/wsl/ModernIME/core/src/learning_store.cpp:578)、[readState 事务后版本:678](/home/wsl/ModernIME/core/src/learning_store.cpp:678)、[Writer 消费:612](/home/wsl/ModernIME/core/src/learning_writer.cpp:612)。

当前写事务内检测 data_version 的方向正确，但 COMMIT 后又把最新 data_version 保存为已同步基线。readState 也在读取事务结束后保存版本。若外部连接恰在事务结束与这次版本读取之间提交，新版本被记录，相关事实却没有被本次读/写快照吸收。

本地探针仅在真实 COMMIT 成功返回后安排一次真实外部 LearningStore 提交，分别命中上述两个窗口，不伪造 SQLite 返回值。第一笔 flush 后未看到外部词；再执行一次本地选择并成功 flush，仍看不到外部词和屏蔽：

```text
sqlite_external_after_write_commit external_committed=1 second_flush=1 external_seen=0 suppressed=0
sqlite_external_after_read_commit  external_committed=1 second_flush=1 external_seen=0 suppressed=0
```

两例手动 reload 对照均恢复，磁盘未丢失数据；影响是本进程召回/屏蔽视图持续遗漏外部事实。第二笔 flush 仍遗漏，排除了仅要求追赶自身提交之后的瞬时线性化争议。LMDB 对应后提交对照在下一批成功检测并吸收，不将这个 SQLite 结论泛化到 LMDB。

**解决要求：** 只接受与已读取/已合并事实对应的版本。事务提交之后的新外部版本必须留给后续检测，不能单独读取并确认成“已同步”。保持单写者快速路径，不要求恢复每批全表扫描。

R5-02、R5-03 的[存储组报告](/home/wsl/ModernIME/build/architecture-fifth-acceptance-20261027/storage/存储组第五轮独立验收.md)含完整源码、事务交错安排和命令；[主审复跑](/home/wsl/ModernIME/build/architecture-fifth-acceptance-20261027/主审存储.log)同样退出 1。3 个失败断言属于这两个根因。
