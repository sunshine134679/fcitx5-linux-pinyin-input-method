# ModernIME 架构与设计整改实施方案

> **给接手 AI：** 按本文任务逐项执行，不把整份方案合成一次全仓重构。具备相应技能时使用 `superpowers:executing-plans`；只有用户要求并行时才分派独立实施任务。所有复选框均表示待完成工作。本次用户只要求整理方案，编写者没有实施代码、测试、构建、安装或发布修改。

**目标：** 修复审查报告中的 A01–A16，并在保留既有体验与数据契约的前提下收敛 D01–D05 的重复实现和无消费者分支。

**架构方向：** 保留候选阶段、统一学习政策、不可变快照、共享 LMDB 环境与独立包事务机制。补齐跨层适配和提交边界；优先复用现有职责，不增加通用 Manager、动态策略框架或后台服务。

**技术栈：** C++20、Fcitx5、LibIME、GTK3、SQLite、LMDB、Bash、Python、CMake/CTest、GTest/Benchmark、GitHub Actions。

**依据：** [架构与设计审查报告-2026-10-26.md](/home/wsl/ModernIME/docs/架构与设计审查报告-2026-10-26.md)。报告保存发现和原始证据；本文保存推荐解决方案、任务依赖及验收要求。本文提出的新接口、测试名和目标结构均为**待实施设计**，不表示仓库已经具备。

## 一、方案选择与实施边界

采用**分批修复契约，再做行为等价精简**的方案。只加局部判断无法解决剪贴板和安装的多写者问题；整体重写又会同时触及候选、学习、配置、安装和发布，扩大回归面。本文选择中间路径，允许每项独立回退和验收。

审查基线是 `0e2eef72df69dd760dc3b0ffc0bd642f11db5ff5` 加当时未提交工作树，版本 `0.1.23`。接手时必须重新辨认当前基线，不能强制回退到该 SHA，也不能把报告中的 PID、inode、构建目录及模型身份当作当前事实。

### 全局约束

- 先读 `AGENTS.md`、适用子目录规范、`docs/项目基础与AI修改护栏.md`、`docs/AI改动前后检查清单.md`、`docs/中文命名与协作约定.md`。涉及算法/选择/学习/持久化时，按要求完整阅读算法演化记录、架构、变更指南及相关候选契约。
- 保留候选语义身份、会话/展示代次、消费范围、统一学习资格、清空世代、不可变快照、LMDB 环境与事务寿命、包事务所有权及用户数据保护。
- 默认 **200,000 条能力不降低**；原生及插桩性能门限沿用权威文档，不因方案扩大超时、缩减输入或放宽断言。
- 默认不新增第三方依赖、不改变词库/模型/排序参数、不修改已有磁盘格式。确需改变格式时，任务必须单独记录兼容读取、回退及旧写者边界，不能静默清空或转换用户数据。
- 当前有未提交 UI、设置页及测试改动。先辨认归属，禁止 `git reset --hard`、`git clean`、`git add .` 或用历史文件覆盖当前正文。不替其他任务提交；新维护文档和获准提交的说明使用中文。
- 新文件只在确有独立职责时创建。优先修改现有实现和现有测试入口，不以文件变小作为改善证据。
- 每项缺陷先补可失败的行为用例并记录旧版结果，再作最小修改。对象寿命 UB 若不能稳定产生旧版红灯，应保留静态证据并明确局限，不能伪造崩溃或测试结果；ASAN 未报错不等于该引用有效。
- 本文不授予接手者发布、推送、移动标签、清空真实用户数据或部署到日常输入法的额外权限；具体实施以用户转交时的指令为准。普通实现选择由接手者判断，不为本方案再增加审批循环。

### 特别复核的五类输入

| 条件 | 用户应得到的行为 | 负责任务 |
|---|---|---|
| 清空/删除时恰好复制，或保存失败后重试 | 旧基线不复活已删除记录；新复制不被无声吞掉 | AR02 |
| 页面打开后文件被改写、删除或暂时不可读 | 保留草稿和外部数据，不能把失败视为零条后覆写 | AR04、AR05 |
| 提示改变页宽、相同上下文重复到达 | 看见的候选与键鼠请求一致，旧请求仍受保护 | AR03 |

| 测试名存在但套件未跑、报告为空/过期或非法 skip | 验收失败且保留实际退出码，不因注册完整就放行 | AR10 |

### AR02：剪贴板读改写归入同一文件事务

**修改：** `core/include/modernime/core/clipboard_history.h`、`core/src/clipboard_history.cpp`、`persistent_clipboard_history.*`、`tools/settings/clipboard_history_model.cpp`。

**接口方向：** 在现有 `ClipboardHistory` 文件职责内增加共享更新入口，例如 `updateFile(path, mutation, committedHistory, error)`；mutation 只修改锁内刚读取的历史。`PersistentClipboardHistory` 和设置 model 都必须消费它。它是文件事务，不是新的后台服务；序列化格式保持兼容。

- [ ] 建立真实双进程栅栏回归：复制与清空交错、复制与指定文本删除交错、两复制写者交错；断言磁盘最终内容及双方返回值。删除以选中的文本身份确认，不能用旧页行号删除新文件里的另一项。

- [ ] 锁忙不能无限阻塞宿主事件线程：输入侧尝试失败后保留有界增量，按现有轮询/flush 策略重试；UI 等待重试放 Worker。取得锁后的慢 I/O 不得再持额外的宿主/GTK/学习锁。测试退出与故障重试均有界。

**完成标准：** 原报告清空复活与固定 `.tmp` 反例均被拒绝/正确串行，已删除旧历史不复活；临时正文从创建起私有。`ClipboardHistory::save()` 若仍保留为低层序列化接口，应明确普通产品写者不得用旧快照绕过事务入口。
