# 输入辅助客户端接入计划

依据 [输入辅助功能接口](../../输入辅助功能接口.md)，在主目录 main 增量接入 GTK3，沿用 frontend-design 及现有七主题、焦点和保存流程，不改引擎算法，不沿用历史安装授权。

- [x] 输入页增加“输入辅助”，接入临时英文、拆字查字、计算器三个开关与快捷方式说明；拆字、计算器用原生试用弹窗解释真实结果。
- [x] 拆字索引在 Worker 加载，失败可重试并按需查看详情；计算器直接调用有界纯接口，错误不能复制为结果。
- [x] 候选页增加置顶规则管理，私有草稿支持搜索、更换与取消；新增时在 Worker 查询真实候选，仅采集完整消费的中文／用户词典身份，不提交、不学习、不手填身份。
- [x] 全部接入设置模型、搜索、校验定位和保存／放弃；增量构建及直接相关 GTK 检查通过后提交到主目录，保留其他任务成果。

结构：`input_assist.cpp` 管试用与三个设置，`candidate_pin_query.cpp` 提供只读候选查询，`candidate_pin_dialog.cpp` 管置顶草稿与异步选择；已有页面只承担入口和保存接线。所有新组件使用已有主题样式，不新增强调色或装饰动画。

验证：首次定向检查中，输入编辑、Shell、保存反馈及搜索注册四项通过；输入辅助检查发现多音节身份拼音含分隔符，按现有 SettingsStore 与 Composer 共用的 canonical 约定接线后，单独复测通过。新检查覆盖开关保存／放弃、有效／错误计算、异步拆字、规则搜索／取消／删除／新增及往返保存、输入修改后旧结果失效、窗口销毁和完整消费过滤；未创建测试学习库或用户词典。七套主题的置顶管理截图及真实查询选择、拆字弹窗已检查，证据见 `build/输入辅助客户端-20261110/`。未运行全量测试，未安装。
