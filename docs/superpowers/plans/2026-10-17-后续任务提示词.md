# 后续任务独立提示词 Implementation Plan

> **For agentic workers:** 使用 `superpowers:executing-plans` 按当前任务逐项执行。用户要求一个对话只处理一个任务；只执行本次复制的一个代码块，复审通过后才启动下一任务。

**Goal:** 提供 T14 收尾与 T15–T19 的六段独立交接提示词，无需复制历史聊天。

**Architecture:** 沿用原整改计划和已验收契约。各任务独立实施、测试、提交和交付；验收状态与证据写入仓库文档，不依赖聊天中的口头完成声明。

**Tech Stack:** C++20、CMake、Fcitx5/GTK、SQLite/LMDB、Bash/Python 及现有项目测试工具。

**Spec:** `docs/superpowers/plans/2026-10-16-架构整改实施与验收方案.md`；T14 当前复审以 `docs/T14-复审与交接.md` 为准。

## 使用与全局约束

- 一次只复制一个代码块。当前 T14 尚未通过，先使用 T14；T15–T19 按顺序在新对话中使用。
- 后续任务基线必须是上一阶段**复审通过**的实际提交；“实现完成、等待复审”不算已通过。不得把未来提交固定成当前 `7f2f05d`。
- 只生成提示词不表示已经实施任何后续任务。这份文档不替代原计划或现有复审结论。
- 不推送、不发布、不跨任务；保留用户文件、历史未跟踪文档与失败证据。
- 原门禁编号：G0 身份/环境/注册；G1 定向；G2 行为；G3 全量正确性与 Release 性能；G4 Sanitizer/并发；G5 安装/升级/卸载/渠道；G6 GTK/桌面；G7 最终证据检查。**TSAN 不是 G5。**
- 原有性能门限及负向拒绝自检保留。benchmark 不传 GTest 参数，不与构建、插桩或另一套性能测试并行。

## Review Focus

1. 版本错配、失败读被当成功：T14 必须验证真实配置消费者。
2. 关闭窗口后异步回写或旧结果覆盖：T15 必须验证失活与版本授权。
3. 使用旧 build、零匹配或未注册测试冒充通过：T16/T19 必须验证负向准入。
4. 安装回滚覆盖并发用户写入：T17 必须验证失败阶段的数据保留。
5. 页面路由与既有实例行为不一致、文档夸大覆盖：T18/T19 必须绑定实际入口和证据。
