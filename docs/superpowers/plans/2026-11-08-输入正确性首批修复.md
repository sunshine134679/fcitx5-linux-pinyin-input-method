# 输入正确性首批修复实施计划

> 执行者按 `superpowers:executing-plans` 逐项实施；每项独立复现、修复、验证和提交，完成后进行独立代码审查。复用现有职责，不扩大为整体重构。

**目标：** 修复长拼音原文学习污染、金额转换边界错误及上下文时间衰减接线遗漏，形成可重复的真实输入回归。

**架构：** 保留 Controller → Provider → 统一学习政策 → Writer/Store 链路；在已有拼音分类、宏转换及 Features 所有者内修正原因。保留候选语义身份、消费范围、清空世代和不可变快照，不增加第二份可变学习状态。

**技术栈：** C++20、LibIME、Fcitx5、SQLite/LMDB、CMake、CTest/GTest/Google Benchmark。

**需求与证据：** [全面升级审计与路线图](../../全面升级审计与路线图-2026-11-08.md)，U01/U02/U03。用户要求先审计、再分阶段实现，主平台 Ubuntu 24.04 + GNOME。本计划不覆盖全部总目标，后续项目按路线图继续。

## 审查重点

1. 48字节边界两侧都是合法拼音时，原文提交相同且都不增加学习；真正英文/标识符仍按原政策学习。
2. Ready与Reloading恢复处理同一CommitEvent时，分类、清空世代及容量行为一致。
3. 金额超范围不产生改变数值的候选；空格、方向键后空格、选词接口、回车的实际提交及消费正确；数字键继续录入数值。
4. 小数第三位、前导零、无有效数字、零角非零分、跨四位分组不静默截断或吞输入。
5. 时间为0、未来时间、禁用上下文、旧快照仍在读时，不因传递时钟改变已有未定义时间/无上下文政策。

## 任务2：金额与数字转换的无损边界

**文件与接口：**

- 修改 `algorithm/pinyin/src/pinyin_candidate_provider.cpp` 中现有 `toChineseFinancial(std::string_view)`、`toChineseStandardNumber(std::string_view)`、`generateMacroCandidates(...)`。
- 测试 `tests/core/pinyin_provider_test.cpp`、`tests/adapter/pinyin_engine_integration_test.cpp`，宏候选保持现有Engine来源、Chinese提交角色；本批只修数值正确性。宏学习语义问题U19单独处理，不能误用触发OpenClipboard的Command来源。
- 不对其他日期、时间、符号宏和拼音召回做附带重构。

**本批明确策略：**

- 去除前导零后的整数有效长度不超过16位（现有最大单位“兆”覆盖到9999999999999999）。金融大写允许0、1或2位小数；超过2位不生成金融候选，不静默舍入/截断。
- 标准中文数字保留所有小数位，只在整数范围可表示时生成；例如 `v1.001` 可提供“一点零零一”和“1.001”，不得提供“壹元”。
- 超出整数范围时只保留数字原文宏候选；如 `v10000000000000000` 空格可提交 `10000000000000000`，回车仍遵循既有原始预编辑契约。至少有一个数字才进入数字宏，孤立小数点不转换为零。
- 语法未接受的负数/多个小数点不扩展功能，保持原有输入与原文兜底。

- [x] 新增旧实现失败用例：16/17位整数、很多前导零但有效值很小、`v1.001`、`v0.001`、`v.`；断言所有转换候选和原文兜底，不能只查首选。
- [x] 保留 `v12345`、`v88.5`、`v1000000000000` 的原断言；加入0/0.00/0.01、跨四位零组、最高支持值，证明没有破坏正常金额。
- [x] 使用真实Controller验证空格/方向键后空格/选词接口的提交文本、完整消费及既有提交角色；Enter验证原文契约，取消不落盘。
- [x] 旧实现运行并保留失败；在宏入口与转换器边界拒绝不可表示值，只调整必要分支，保持结果顺序的既有正常场景。
- [x] 运行 `modernime_pinyin_provider`、`modernime_pinyin_engine`、`modernime_engine_state` 和相关学习角色回归；确认没有单词专用硬编码。
- [x] README宏表增加范围与小数说明；只编辑本任务涉及正文，保留已有视觉段落补丁。独立审查后中文提交。

建议提交说明：`修复：限制金额转换范围并保留精确原文`。
