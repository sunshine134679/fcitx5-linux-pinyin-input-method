# GNOME 扩展生命周期实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 在当前隔离 worktree 内逐项执行；保留失败证据和独立复审。

**目标：** 用户已有/修改的 GNOME 扩展受到保护，ModernIME 自管副本可更新、可移除，启用状态不再假报成功。

**架构：** 专用 Python 标准库模块负责完整副本基线与启用状态所有权，session-init 和 uninstall 只负责调用。保留现有 UUID、资产和 Fcitx5 会话流程。

**技术栈：** Bash、Python 3.10 标准库、现有 GNOME CLI、CMake/CTest。

**设计：** [GNOME 扩展生命周期设计](../specs/2026-11-08-GNOME扩展生命周期设计.md)。

**实施状态：** 两项任务的实现、独立复审整改及完整隔离验证均完成；26 项专项、81 项 CTest（75 通过、6 合法 headless 跳过）、203 项 GTest 和安装卸载闭环通过。实际 GNOME 新副本加载、Wayland 及跨 DPI 另待综合验收，详见 [验收记录](../../GNOME扩展生命周期验收-2026-11-08.md)。

## 全局约束

- 主验收平台 Ubuntu 24.04 + GNOME；测试隔离 HOME/XDG/DBus，不操作日常扩展或重启日常 Fcitx5。
- 保留所有既有测试断言；无算法变更，不修改核心容量和性能门限。
- Python 最低 3.10，不引入新系统库。中文文档/提交，历史证据不覆盖。
- 不认领无记录的旧副本；不以 native 包 root 钩子扫描用户家目录。

## 复审重点

- 跨 prefix 或配置/数据路径迁移不能删除另一份安装的副本：任务 1 验证不同 prefix 与 Shell 路径；配置/数据路径的独立迁移用例未执行，当前实现校验完整记录身份，不能称为所有路径迁移场景均已覆盖。
- GNOME 工具返回成功但扩展未加载不能误报活动：任务 1 增加 INITIALIZED/查询失败用例。
- 恢复两个设置键中途失败不能让重试永久失效：任务 1 增加部分恢复后重试用例。
- 升级和用户修改（包括新增空目录、模式和符号链接）不能混合两版文件：任务 1 增加树修改和 schema 失败用例。
- 发布新树后记录写失败应回滚而非丢失旧副本：任务 1 在隔离子进程替换 OS 原子记录发布边界并抛出 PermissionError，其余目录及回退操作使用真实文件系统；此前只读记录夹具会在发布前触发保守保留，未到达目标故障边界。进程中断另有强制退出用例验证恢复材料保留。
