# 设置状态反馈设计（U08）

## 依据与范围

基线 `2e45a97b97ba59249901e9111842f75603dbefbe`，工作树干净。`build/设置状态反馈-20261108/初始截图/` 的生产 GTK 截图与当前三个页面源文件 hash 一致：学习空库只显示禁用的清空按钮；非空搜索无匹配时没有提示；720×520 候选预览缩小却没有说明。前一目标轮完成 U07，属于实质进展；本项继续原总目标，不重做全仓审计。

保留八模块、现有风格与导航。只修正客户端反馈，不改变候选排序、分页/绘制算法、学习计数或备份清空存储契约。页面不创建新的数据库事实源。

## 交互设计

1. 非空搜索无匹配时在原结果浮层显示“未找到匹配的设置”及换关键词建议；提示不可点击、不抢搜索焦点。空白查询收起；恢复匹配时正常导航；Escape 原契约保持。实际回归发现 GTK 默认模态弹层会抢焦点，改为非模态搜索建议，支持连续键入、Tab/下方向键进入结果，焦点离开搜索区域时收起。
2. 学习数据区显示加载、记录数、空库、读取失败和清空中状态。读取失败给出具体原因与就地“重试”。初次未知时禁用清空；已知有数据后的刷新保留既有清空能力，真正备份/清空仍执行原确认与保护。既有 generation 和 isClearing_ 决定结果是否可应用，旧异步结果不能覆盖新状态。
3. 学习数据统计和最近一次清空结果分开呈现：后台刷新不能抹去备份/清空失败原因或成功后的备份位置；开始下一次清空才替换上次操作结果。不新增持久状态或后台线程。
4. 预览保留原真实 renderer 与缩放规则，在旁边明确“实际大小”或当前百分比，并说明仅缩小预览、设置字号不变。随分配尺寸、字号和容量更新；不在 draw 中修改布局，不因显示状态更改配置草稿。

维护者选择沿用现有三个页面与测试目标，避免增加状态管理层。就地重试为真实读取失败提供一步恢复，不增加新的设置项或数据库接口。

## 验收与回退

先在旧实现上观察真实 GTK 失败，再修复。保留原 shell 导航/分页断言、data_async 的读后挂起/清空重入/慢 I/O 心跳/销毁回归，增加最终可见状态与重试验证。预览验证窗口收缩、放大及字号/容量变化，校验显示比例与实际绘制宽度一致，配置草稿不因窗口缩放变化。

执行 Release 编译、设置控制器/模型/页面注册与候选布局相关检查，并在隔离 X11/DBus 下执行全部客户端 GTK/导航测试、检查新截图。此项不改变依赖、构建/安装脚本、格式或引擎热路径；按护栏的影响范围验收，不把 U07 的完整安装结果冒充本项实际重新安装或性能提升。整体产品综合验收仍需后续 full 与真实桌面场景。独立中文提交可回退，无用户数据迁移，不部署日常环境。
