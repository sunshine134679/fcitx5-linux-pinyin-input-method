# ModernIME Fcitx5 重建设计规格

## 目标

从零构建一款基于官方 Fcitx5 Addon / Input Method Engine 机制的 Linux 中文拼音输入法。保留旧项目中已经验证过的核心算法能力，但不继承旧项目的工程结构、安装方式或运行时覆盖层。

第一阶段的成功标准是：在 Wayland 主环境下稳定完成拼音输入、候选显示、数字选词、删除、Esc、Enter 以及中英文切换，并在 X11 下保持同一套核心逻辑可用。候选栏以用户提供的设计图作为唯一视觉标准。

## 约束

- 不修改 Fcitx5 本体。
- 不删除或覆盖其他输入法、Fcitx5 官方文件和系统目录。
- 开发阶段不执行 `sudo make install` 或 `sudo ninja install`。
- 所有安装文件必须由 `install.sh` 产生并由 `uninstall.sh` 反向移除。
- 所有写入用户目录或系统目录的路径都必须在安装清单中可追踪。
- 每个独立功能或算法更新都必须单独进行一次 `git commit`。
- 每个阶段都必须先编译、测试、验证，再进入下一个阶段。
- 旧项目残留只按已确认的精确路径清理；`/usr/local` 和 Fcitx5 本体目录不做宽泛删除。

## 总体架构

工程拆成四个运行时边界：

1. `core`：与 Fcitx5 无关的拼音匹配、候选排序、词典、学习和隐私逻辑。旧项目的核心算法迁移到这里时只做接口适配和必要的错误修正。
2. `adapter/fcitx5`：官方 Fcitx5 输入法引擎适配层，负责按键事件、输入上下文、候选列表、提交字符串和每个输入上下文的生命周期。
3. `ui/fcitx5`：独立的 ModernIME UI addon，负责 ModernIME 候选栏的窗口生命周期、定位和绘制；不使用外部悬浮程序模拟输入法窗口。
4. `config`：配置 schema、默认值、用户配置路径和安装元数据；不得把开发路径硬编码进运行时。

推荐的工程边界如下：

```text
core/
  include/modernime/core/
  src/
adapter/fcitx5/
  include/modernime/fcitx5/
  src/
ui/fcitx5/
  include/modernime/ui/
  src/
config/
tests/
  core/
  adapter/
  ui/
assets/reference/
packaging/
scripts/install.sh
scripts/uninstall.sh
```

输入法引擎只依赖 core 和 Fcitx5 公共 API；UI addon 只依赖 Fcitx5 UI 公共 API 和 ModernIME 的显示模型。core 不包含 Fcitx5 头文件，保证算法可以脱离桌面会话进行单元测试。

## 输入与候选数据流

1. Fcitx5 将按键事件交给 ModernIME engine。
2. engine 在每个 InputContext 的状态对象中维护原始拼音、光标、候选页和 generation。
3. adapter 将输入状态传给 core；core 返回候选文本、完整拼音和稳定的候选 ID。
4. engine 通过 `InputPanel` 设置 preedit 和 candidate list，并调用 Fcitx5 的 UI 更新接口。
5. ModernIME UI addon 读取当前 InputPanel 的显示模型，只在当前输入法为 ModernIME 时绘制自定义候选栏。
6. 数字键、空格、方向键和翻页键通过 candidate list 的选择接口回到 engine；engine 提交选中的文本并清理当前状态。
7. generation 变化时旧候选选择请求必须失效，防止高速输入期间提交过期候选。

第一阶段只实现完整拼音的稳定路径。候选页上限先固定为 9，候选不足时不渲染不存在的候选。模糊音、拼写纠错、长句预测和联网能力不进入第一阶段。

## 稳定性策略

- 按键处理和当前候选刷新保持同步、短路径、无磁盘 I/O。
- 学习写入、词典索引和非必要统计全部放到后台队列；UI 不等待 SQLite。
- 每个输入上下文独立保存状态，不使用全局可变输入缓冲。
- reset、focus out、切换输入法、Esc 和提交路径都必须清理 preedit、candidate list 和 generation。
- 任何 LibIME 或词典异常都回退到空候选或原始拼音提交，不让异常穿透 Fcitx5 主循环。
- UI addon 初始化失败时，engine 仍可通过 Fcitx5 默认 UI 工作；UI 失败不能阻断输入。

## 候选栏视觉规格

附件设计图是唯一视觉基准，原始图片尺寸为 2172 × 724。第一版需要锁定以下关系，并通过运行截图逐项比对：

- 画布背景为纯白，预编辑文本位于候选栏左上方并保持左对齐。
- 候选栏为横向单行、白色半透明面板，带浅灰边框、柔和阴影和大圆角。
- 候选栏整体位于预编辑文本下方，内部候选沿同一基线排列。
- 第一个候选使用蓝色圆角胶囊选中区域，编号和汉字均为白色。
- 未选中候选使用深色文字，编号紧邻汉字，不额外增加图标或辅助文字。
- 候选顺序为 `1.还 2.海 3.害 4.嗨 5.咳 6.亥 7.孩 8.骇 9.氦` 这一类九项横向布局；实际内容由引擎提供。
- 面板宽度、面板高度、候选间距、选中胶囊尺寸、文字基线、字体大小、字重、圆角、边框、阴影和透明度都以设计图截图为测量基准，不使用“差不多”的主题默认值。
- 视觉验收循环固定为：设计图 → 同分辨率运行截图 → 叠加/差异检查 → 调整 → 再截图。
- 截图验收必须记录 Wayland/X11、缩放比例、字体、分辨率和 compositor；字体抗锯齿和 compositor 阴影可能造成无法跨机器完全一致的像素差异，差异必须显式记录。

UI 的第一实现目标是固定尺寸和固定字体下还原设计图；响应式宽度、深色模式和高级主题配置排在稳定候选栏之后。

## 清理、安装和卸载

清理阶段只处理已经确认的旧 ModernIME 路径，包括旧 addon/inputmethod 配置、旧 `.so`、旧词典/学习库/主题、旧启动器、旧 systemd unit、旧 D-Bus 覆盖文件和旧用户启动脚本。`~/.config/fcitx5`、系统 Fcitx5 路径和其他输入法文件保持不变。带有旧主题引用的备份配置不整目录删除，除非后续逐文件确认。

新安装默认使用用户前缀 `${XDG_DATA_HOME:-$HOME/.local}` 和 `${XDG_CONFIG_HOME:-$HOME/.config}`，不写 `/usr` 或 `/usr/local`。`install.sh` 记录实际安装清单，`uninstall.sh` 只读取该清单并删除 ModernIME 自己创建的文件；空目录只有在确认无其他内容时才移除。

## 分阶段交付

### 阶段 0：工程和验证基础

完成 Git 初始提交、CMake 构建、core 测试框架、Fcitx5 依赖探测、安装清单机制和开发文档。此阶段不安装到系统。

### 阶段 1：最小可用输入法

完成官方 Fcitx5 engine、每输入上下文状态、基础拼音缓冲、候选列表、数字选词、空格、删除、Esc、Enter 和中英文切换。使用固定的测试候选模型先验证事件闭环，再接入真实 LibIME。

### 阶段 2：候选栏 UI

完成独立 UI addon 的候选栏绘制和定位，先在 Wayland 验收，再验证 X11。每次 UI 调整单独提交，并保存截图测试记录和差异说明。

### 阶段 3：核心算法接入

迁移旧项目中已保留的拼音匹配、候选排序、词典和快照算法，保持 adapter 接口不变；每一类算法更新独立提交并补充回归测试。

### 阶段 4：学习和增强功能

在基础输入稳定后再启用用户学习、隐私过滤、模糊音、拼写纠错和长句输入。每项功能均必须有开关、测试和可回滚提交。

## 验收标准

- 编译过程无未处理警告，单元测试和集成测试通过。
- 在连续高速输入、快速删除、连续切换输入法和候选刷新竞态下不崩溃、不提交旧候选。
- 设计图中的基础候选栏元素全部存在且位置、尺寸、颜色、间距和圆角经过截图比对。
- `install.sh` 和 `uninstall.sh` 能在用户前缀内完成可追踪安装和完整卸载。
- Git 历史能够按提交粒度清晰回答每次新增功能或算法更新改动了什么。
