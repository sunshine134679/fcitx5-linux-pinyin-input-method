# ModernIME 自适应候选流水线设计规格

## 目标

在不改变现有候选框尺寸、位置、字体、圆角和间距的前提下，让 ModernIME 具备可日常使用的候选推荐能力：候选排序会记住用户习惯，能够加载专业词和用户词，并支持稳定的候选分页、当前页数字选择以及错误学习词删除。

## 调研依据

- LibIME 采用 Trie 词典、语言模型、Viterbi/Beam Search 和 N-best 候选生成。ModernIME 继续把 LibIME 作为拼音切分和句子解码的核心，不重复实现解码器。
- Microsoft Pinyin 将系统词库、领域词库、用户短语、个人调频和新词学习分开管理，并支持前缀输入时实时更新候选。
- Rime 将用户词典和动态调频分开，并允许用户删除错误学习词；其默认配置使用 `PageUp/PageDown`、`-`、`=`、`,`、`.` 作为翻页键。

## 范围

### 包含

1. 用户选择学习：记录用户最终确认的词语、拼音、选择次数和最近选择时间。
2. 本地专业词库：加载可编辑的文本词库并并入 LibIME 的独立词典层。
3. 自适应排序：在 LibIME 原始语言模型分数之上叠加词库优先级、频率、时间衰减和负反馈。
4. 候选分页：保留全部候选，每页显示 9 项；支持上下方向键、PageUp/PageDown、`=`/`+` 翻页。
5. 当前页选择：数字键选择当前页的候选；鼠标点击继续选择真实候选。
6. 错误学习删除：对当前选中的用户学习词支持 `Ctrl+Delete` 和 `Shift+Delete`。
7. 上下文排序基础设施：从 Fcitx5 surrounding text 读取光标前后的有限文本，在可用时提供给排序流水线；前后文不可用时不降低候选可用性。

### 不包含

- 不接入云端候选、联网搜索或远程模型。
- 不引入神经网络模型，不替换 LibIME 的拼音解码器。
- 不改变现有候选框的固定尺寸和 UI 视觉参数。
- 不记录逐键输入日志，只记录用户明确选择或删除的候选。

## 数据模型

### 候选来源

候选项增加来源类型：

- `Engine`：LibIME 原生解码候选。
- `UserDictionary`：用户手动词库中的候选。
- `Learned`：由用户选择产生的自动学习候选。

候选仍保留其显示文本、完整拼音和来源索引。来源索引只在对应来源层内解释，避免把用户词条误当成 LibIME 候选索引。

### 用户词库格式

默认路径：`${XDG_DATA_HOME:-$HOME/.local/share}/modernime/user-dictionary.txt`。

每行格式：

```text
拼音<TAB>词语<TAB>权重
```

示例：

```text
rengongzhineng	人工智能	100
kubernetes	Kubernetes	100
weixinxiaochengxu	微信小程序	80
```

规则：

- 空行和 `#` 开头的行忽略。
- 拼音统一转小写并去除分隔撇号后比较。
- 词语不能为空，权重必须是有限非负数。
- 同一“规范化拼音 + 词语”只保留最后一条有效记录。
- 单行解析错误不会导致输入法退出，只跳过该行。

### 学习存储

学习数据使用本地 SQLite 文件，默认路径为 `${XDG_DATA_HOME:-$HOME/.local/share}/modernime/learning.sqlite3`。

每条记录至少包含：

- 规范化拼音；
- 词语；
- 选择次数；
- 最近选择时间；
- 负反馈次数；
- 是否为手动词条。

学习写入不阻塞按键处理。输入法启动时加载只读快照；选择后进入写入队列，写入完成后刷新下一次候选计算使用的快照。数据库创建失败时退化为进程内学习，不影响基本输入。

## 候选生成与排序

每次拼音输入变化时执行：

1. 让 LibIME 根据当前拼音构建切分图并生成 N-best 原生候选。
2. 从用户词库和学习词库查找完整匹配与前缀匹配候选。
3. 按“文本 + 规范化完整拼音”去重；同一词条保留来源优先级最高且信息最完整的一份。
4. 计算候选分数。
5. 稳定排序并生成完整候选序列；分页只发生在展示和按键层，不参与推荐排序。

排序分数的逻辑顺序为：

```text
最终分数 =
    LibIME 原始候选顺序基础分
  + 完整拼音匹配奖励
  + 用户词库权重奖励
  + log(1 + 选择次数) 频率奖励
  + 最近使用时间衰减奖励
  + 可用时的前后文奖励
  - 负反馈惩罚
```

约束：

- 原生 LibIME 顺序仍是主要基线，用户学习不能无上限压过语言模型。
- 手动词库权重可以稳定提升候选，但不能绕过拼音匹配。
- 自动学习采用有上限的频率奖励和时间衰减，避免单个词永久霸榜。
- 前缀匹配的候选低于完整匹配；短输入时限制用户词库候选数量，避免输入单个字母时污染列表。
- 负反馈只影响用户学习层；系统词库不会被物理删除。

## 学习生命周期

- 用户通过数字、鼠标或空格确认候选后，记录该候选的拼音和词语。
- 用户提交原始拼音、Esc 清空或输入标点时，不生成学习记录。
- 选择同一词条时递增次数并更新时间。
- 用户执行删除时，自动学习词条增加负反馈并从当前候选中隐藏；手动词条从用户词库移除；系统词条只取消用户调频。
- 负反馈和学习记录均保存在本机。

## 分页和按键语义

候选列表内部保留全部候选，Fcitx5 `CommonCandidateList` 的页面大小保持为 9。

| 按键 | 行为 |
| --- | --- |
| `Up`、`PageUp` | 上一候选页；没有上一页时不处理 |
| `Down`、`PageDown`、`=`、`+` | 下一候选页；没有下一页时不处理 |
| 数字键 `1`–`9` | 选择当前页对应位置的候选 |
| 鼠标点击 | 通过候选对象携带的全局索引选择候选 |
| `Ctrl+Delete`、`Shift+Delete` | 删除当前高亮的用户学习词或撤销其调频 |

翻页时高亮位置优先落在目标页第一项；当前页内用左右方向键或 Tab 移动候选。到达边界不循环，未发生移动时不吞按键。

## 上下文

Fcitx5 输入上下文在声明支持 surrounding text 且数据有效时，提供光标前后有限窗口。ModernIME 只传递短窗口给排序器，并限制最大字符数；不能读取 surrounding text 时使用空上下文。上下文只作为排序增量，不改变候选拼音合法性。

## 错误处理与隐私

- 缺失用户词库：按空词库处理并继续启动。
- 用户词库存在非法行：跳过非法行，保留其他有效词条。
- 学习数据库损坏或不可写：记录诊断信息，退化到内存学习和系统词库。
- 所有用户词条、选择次数和 surrounding text 只在本机进程内使用，不上传网络。
- 学习数据库写入采用事务和临时文件/SQLite 原子提交，避免半条记录破坏整个词库。

## 验收标准

1. 选择一个非首选候选后，再次输入同样拼音，该候选在不违反拼音匹配的前提下稳定提前。
2. 重启输入法后，上述学习结果仍然存在。
3. 加入 `rengongzhineng<TAB>人工智能<TAB>100` 后，输入 `rengongzhineng` 能看到“人工智能”。
4. 用户词库中的词条支持输入前缀时出现，单字母输入不会展示整个词库。
5. 输入超过 9 个候选时，`Down`、`PageDown`、`=`、`+` 能到下一页，`Up`、`PageUp` 能返回上一页。
6. 翻页后按数字键选择的是当前页候选，鼠标点击选择结果正确。
7. 删除自动学习词后，该词不再出现在对应拼音的候选前列；系统词库词不被物理删除。
8. 14 项现有测试及新增测试全部通过，候选框现有尺寸相关测试不变。

## 提交边界

每个独立功能必须完成“失败测试 → 最小实现 → 全量测试 → 独立 commit”：

1. 用户学习存储和排序接入；
2. 专业词库加载和 LibIME 多词典接入；
3. 候选分页、当前页数字选择和快捷键；
4. 错误学习删除；
5. surrounding text 上下文排序。

任何一个功能不得把另一个未完成功能的代码混入同一个提交。
