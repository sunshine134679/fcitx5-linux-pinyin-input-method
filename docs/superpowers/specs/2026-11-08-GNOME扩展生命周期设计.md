# GNOME 扩展生命周期设计

状态：已实现并通过隔离验收，真实桌面加载仍待验收；基线 `debe03fa0733d66ffda8de7c421139decef885ae`。对应全面升级审计 U05，主验收平台 Ubuntu 24.04 + GNOME。结果见 [本批验收](../../GNOME扩展生命周期验收-2026-11-08.md)。

## 问题与范围

`modernime-session-init` 当前以 GNOME 程序是否安装推断桌面，直接覆盖用户的 `kimpanel@kde.org`，忽略 schema / 启用失败。源码卸载只删除 prefix 内的资产，用户副本和启用设置遗留。此前 U06 真实隔离安装卸载后留下 20 个扩展文件，不能把该结果称为完整对称卸载。

修复当前用户的部署、更新、移除及状态反馈；保留 UUID、扩展内容和 Fcitx5 启动行为。输入算法、候选框绘制不变。本设计是维护者在用户全面升级授权下作出的工程选择，不是用户指定的实现。

## 方案取舍

1. 逐文件接入旧 managed-file：无法识别用户新增的文件/空目录，局部更新可能混合两版扩展，弃用。
2. 用户目录改成指向 prefix 的符号链接：改变第三方扩展管理器删除/更新语义，且依赖其根链接处理，弃用。
3. **保留目录复制，记录完整目录基线**：能够保护已有安装和新增文件，更新整份扩展；采用。Python 3.10 标准库实现专用生命周期模块，复用已有 Python 运行依赖，不添加通用管理框架。

## 所有权与部署

- 专用模块 `scripts/gnome_extension.py`，CLI `deploy|remove --prefix PATH --config-home PATH --data-home PATH`；部署额外 `--bundle PATH`。
- 目标固定为 data-home 下 `gnome-shell/extensions/kimpanel@kde.org`。记录固定为 config-home 下 `modernime/session-managed-files/gnome-extension.json`，包含版本、规范 prefix/目标、目录/文件类型、权限及内容 SHA256；不记录其他用户数据。多 prefix 不接管彼此的记录。
- 无记录的已有副本，即使内容与内置扩展相同，也视为用户所有；旧版复制不追溯认领。已有内容、新增文件、空目录、权限或符号链接变化均保留整个副本，不更新、不启用、不移除。损坏记录同样不接管。
- 不跟随目标和管理记录的符号链接；若父路径解析发生变化，则记录的规范位置不匹配，保留并报告。配置目录中的专用锁串行化该用户的扩展操作，不代替上述所有权验证。
- 新部署在同文件系统的临时目录复制并编译 schema，成功后才发布。编译失败保持旧版和记录。升级先保留旧目录，发布及记录更新失败时回滚；突然退出可能留下临时/备份目录或未认领新副本，后续须保守保留并报告，不能据当前内容补造所有权。正常成功清理自己的临时目录。
- 原子替换只承诺正常 I/O 失败的回退和进程崩溃时保守保留，不宣称跨两个目录/记录的断电事务，也不防御同 UID 恶意进程实时替换目录。

## 桌面与启用

- 仅 `XDG_CURRENT_DESKTOP` 的冒号分隔 token 含 GNOME（不区分大小写）、有 DISPLAY/Wayland 和会话 DBus 时自动部署/启用；安装了 `gnome-shell` 不构成会话证据。其他环境明确跳过，不制造用户副本。自动部署仍发生在显式 session-init；登录自启继续只启动 Fcitx5。
- 只对本次管理的完整副本申请启用。使用 `gnome-extensions`，不再无条件追加 GSettings 后备；每次外部调用超时 5 秒。
- 启用前和恢复设置前必须通过 `gnome-extensions info` 的 `Path` 验证 Shell 识别的规范目录等于受管目标。自定义 data-home 配日常 DBus 不能据 UUID 操作另一份扩展。未发现/查询失败/路径不符时部署报告待发现且不申请启用；移除若持有启用所有权则返回非零保留材料，待正确会话重试。
- 首次申请前读取 enabled-extensions / disabled-extensions 的 UUID 成员状态；已经启用或显式禁用时尊重现状，不认领启用修改。其他扩展的设置始终保留。
- 请求启用前持久记录该 UUID 的前后成员状态及请求意图；只申请一次，重跑初始化不撤销用户后续禁用。失败显示退出码与可操作提示。主动重试使用 GNOME 自身的启用命令，不隐藏重试循环。
- `gnome-extensions info` 在 `LC_ALL=C` 下检查状态；只有 ACTIVE/旧版 ENABLED 才报告当前活动，其他状态和查询失败分别报告待加载/异常/未知，不把命令退出 0 当作扩展正在运行。GNOME 46 enable 自带 GSettings 后备，可能只改变设置，依据：[官方实现](https://raw.githubusercontent.com/GNOME/gnome-shell/46.0/subprojects/extensions-tool/src/command-enable.c)。
- 部署成功但启用失败：session-init 完成独立的 Fcitx5 流程后返回非零并明确部分完成。源码/便携安装已提交程序事务时保留安装结果，明确桌面集成不完整；不伪造程序回滚。普通保留用户副本/非 GNOME 跳过属于正常结果。
- 源码安装保留现有初始化调用；便携安装本轮新增同样的用户级初始化调用（跳过 Fcitx5 重启，由原重启流程处理）；native 系统安装仍只提示用户自行初始化。渠道迁移捕获初始化的真实输出和退出码，报告包迁移已完成但会话初始化失败，不改写已完成包事务，也不再吞输出。安装/迁移遇此情况返回非零，提示重跑 session-init，不重复执行安装或包迁移。

## 移除与包渠道

- `remove` 不要求 GNOME 会话，先验证完整副本仍受管理。用户改动时连同记录保留，启用设置也不动。
- 已删除副本直接释放其残留记录，保留无法确认文件归属的 Shell 设置并明确提示，避免“部署要求先移除、移除又要求 Shell 发现不存在的目录”的死循环。若副本仍在且本工具曾申请启用，仅当当前 UUID 成员状态仍等于申请结果时，恢复其原始成员关系；每次只替换当前数组中的本 UUID，保留其他项。当前状态不同则尊重用户操作，不恢复。
- 恢复步骤将剩余键持久化；每步重试只接受此前步骤已完成、当前一步执行前/执行后的两种成员状态。用户在部分失败后新增禁用/启用选择导致状态偏离时，停止恢复设置，不能将未完成步骤当成持续修改授权。
- 查询/恢复失败时保留记录和副本并返回非零，允许同参数重试；无启用所有权的离线副本可直接移除。不在无 DBus 时伪造设置清理成功。
- 源码及便携 `uninstall.sh` 在删除程序资产前调用同一模块，失败应停止卸载并保留可重试入口。无扩展记录时不会调用真实桌面服务。
- 渠道迁移是所有权交接，不能在包事务提交前删除用户扩展：源码调用卸载时使用明确的 `--keep-gnome-extension` 参数；已安装入口和源码入口均在删除程序前暂存同一生命周期模块，包安装/验证失败时扩展及启用设置不变。包验证成功后以 `transfer --prefix OLD --new-prefix NEW` 在完整副本验证下只更新记录的 prefix，不修改文件或设置。交接写入失败报告包已提交，保留暂存助手和精确重试命令；不重新执行包迁移。已修改副本仍保留原记录，不放宽身份检查。
- `modernime-session-init --remove-gnome-extension` 只执行该用户的扩展移除，不改环境、自启或重启 Fcitx5。系统 DEB/RPM 不以 root 遍历其他主目录；文档要求需要清理此用户副本时在移除包前运行此命令。包卸载后可从源码使用同一入口，不宣称原生包自动清理所有用户状态。
- 模块纳入 CMake、源码 manifest、便携工具和 RPM 文件清单。既有用户副本不自动迁移，提示路径及保留原因，由用户决定是否备份后重新部署。

## 验收与回退

先增加能在旧实现失败的真实 session-init / uninstall 黑盒测试，隔离 HOME/XDG/DBus，只替身 GNOME 外部程序：非 GNOME、原有副本、已改副本、新增文件/链接、成功更新、编译失败、启用失败、未加载、保留其他启用项、重复初始化、对称移除、系统包用户入口、并发/路径带空格。真实目录复制和 schema 编译另做一次隔离验证。

注册必需 CTest，保留所有既有断言；运行安装相关回归及 full fresh-clone，核对注册/执行/JUnit/GTest。原生 GNOME 当前会话仅做只读接口核对，不部署测试扩展到日常用户目录；真实显示与 Wayland 激活仍需独立桌面验收，不能由替身测试担保。

实现作为完整闭环提交，再提交综合验收证据；避免临时提交仍执行无所有权启用。回退到具备本设计保护的版本保留记录与副本；基线旧版不识别记录且会覆盖目录，回退旧版前须备份用户副本并避免运行旧版 session-init，不能声称旧程序具备新保护。
