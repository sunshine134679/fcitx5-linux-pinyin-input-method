# ModernIME 候选基础质量设计

## 目标

第一阶段只解决直接影响日常输入手感的候选基础问题：固定宽度候选栏不能跳过候选，长拼音候选要按有用程度混排，常见模糊音和错键要能恢复，常用短简拼要优先给出中文结果。

## 全局约束

- 运行时默认完全离线，不新增网络请求、云候选或遥测。
- 候选栏外观、固定宽度、字体、颜色和圆角保持不变。
- 首候选仍由可信的完整句转换占据；部分候选只提供不同的选词路径，不得用低质量同音词凑满首屏。
- 选择部分候选后只提交已选择文字，剩余拼音继续保留。
- 所有行为修改严格执行 RED→GREEN，使用真实 LibIME、真实候选列表和手工推导的期望值。
- 完整测试套件必须零失败；无图形后端时 GTK 测试允许按既有规则跳过。

## 方案

### 1. 质量驱动的多粒度候选

从最佳完整句的字词边界生成可信前缀，如“请帮我打开文件”派生“请帮我”“请帮”；再从解码器部分候选中补充一个有区分度的同音备选。候选去重后按以下顺序混排：最佳完整句、较长可信短语、两字可信短语、一个同音备选、其余完整句。

不得继续使用“某边界固定取三项”作为质量标准。长输入首屏中，同一完整拼音的完整句变体最多一个出现在前五项；派生短语必须与最佳完整句前缀一致或拥有真实解码来源。

验收样例：

- `nihaoalaodi`：第一项“你好啊老弟”，前五包含“你好啊”“你好”和一个有区分度的短词候选。
- `qingbangwodakaiwenjian`：第一项“请帮我打开文件”，前五包含“请帮我”和“请帮”，不得由“青帮、清帮、青棒”占据三个位置。
- `nengbunengbangwokanxia`：正确整句“能不能帮我看下”必须进入前三。

### 2. 保守纠错与短简拼

在 `CommonTypo` 基础上启用常见模糊音集合：`Z_ZH`、`C_CH`、`S_SH`、`L_N`、`EN_ENG`、`IN_ING`。精确拼音候选优先于模糊匹配；只有模糊匹配能给出更强语言模型结果时才允许其升到首位。

三字母常用简拼若存在中文候选，不得因为长度阈值把原始 ASCII 强行放到第一位。原始输入仍必须保留在候选列表中，用户随时可以提交英文缩写。

验收样例：

- `zongguo`：前三包含“中国”。
- `wsm`：第一项为“为什么”，原始 `wsm` 仍存在。
- `xign`：继续纠正出 `xing` 对应候选。
- `who`：原始英文仍保持第一，避免把普通英文误当简拼。

### 3. 固定宽度下的完整分页

候选框继续使用现有固定宽度。每页候选数量由本页文字实际占用宽度决定，但所有候选必须恰好属于一个页面，不能以 placeholder 隐藏后被 PageDown 跳过。

分页模型必须保存每一页的全局 `[begin, end)` 边界；数字选择、上下移动、Tab、Space、PageUp 和 PageDown 都基于同一组边界。候选内容变化后重新计算边界，并把全局光标钳制到合法候选。

无 GTK 的纯逻辑测试使用确定性的文字宽度函数；Fcitx 集成测试验证跨页候选能够逐项选中。

### 4. 质量回归基线

新增离线候选质量回归测试，覆盖整句、部分选词、短简拼、英文保护、模糊音和错序纠错。测试只断言用户可感知结果，不断言私有实现常量。

本阶段不实现数字日期模式、双拼、Emoji、云候选或跨设备同步；它们在候选基础稳定后单独规划。
