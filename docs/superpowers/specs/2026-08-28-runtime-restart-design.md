# 设置客户端真实重启设计规格

## 背景与根因

设置客户端当前把 `fcitx5-remote -r` 当作 ModernIME 插件重载命令。根据本机 Fcitx5 的命令语义，这个参数只重新读取配置，不会结束已加载的插件动态库。安装新 `.so` 后，旧 Fcitx5 进程仍可能持有标记为 `(deleted)` 的旧文件，因此客户端虽然能看到 ModernIME 处于激活状态，实际执行的仍然是旧代码。

## 目标

让设置客户端的“重新加载 ModernIME”真正替换运行中的 Fcitx5 进程，使新安装的 ModernIME 插件从当前用户前缀重新加载；只有新服务恢复并确认 ModernIME 激活后，客户端才报告成功。

## 非目标

- 不修改候选栏尺寸、位置、字体、圆角和间距。
- 不修改拼音候选算法、剪贴板和用户词典数据格式。
- 不使用管理员权限启动 Fcitx5。
- 不强制清理 `/usr/local` 下的历史文件；运行时通过明确的插件目录优先级避免误加载。

## 运行时流程

1. 查询 `fcitx5-remote` 是否可用及当前服务状态。
2. 如果服务正在运行，启动 `fcitx5 -d --replace -u modernime-ui`，由 Fcitx5 自身替换旧实例；不再把 `fcitx5-remote -r` 当作插件重载。
3. 如果服务未运行，启动 `fcitx5 -d -u modernime-ui`。
4. 通过有上限的状态轮询等待服务恢复。
5. 使用 `fcitx5-remote -s modernime`、`-o` 和状态探测确认当前输入法为 ModernIME 且处于激活状态。
6. 任一阶段失败都返回包含阶段和底层错误的结果，不得把旧服务仍处于激活状态当成新插件加载成功。

启动子进程使用客户端解析出的 Fcitx5 绝对路径，并传递当前用户的显示、D-Bus、运行时目录和 `FCITX_ADDON_DIRS`。ModernIME 用户安装目录排在系统插件目录前面，保证新安装文件优先。

## 错误与界面行为

- 重载期间禁用重载和状态刷新按钮，并显示“正在替换 Fcitx5 并加载 ModernIME”。
- 替换、启动、等待服务、激活 ModernIME 任一阶段失败时恢复按钮，并显示可读的中文错误；不清除用户未保存设置。
- 成功状态必须在最终探测确认后显示；状态页随后刷新，展示服务运行、当前输入法和 ModernIME 激活状态。

## 测试策略

- 测试替身分别记录 `fcitx5-remote` 和 `fcitx5` 的调用顺序、参数及 `FCITX_ADDON_DIRS`。
- 已运行场景必须调用 `fcitx5 --replace`，不得调用远程配置重载作为插件重载，也不得留下重复启动路径。
- 未运行场景必须正常启动；启动失败、替换失败、服务恢复超时和 ModernIME 未激活都必须返回失败及错误信息。
- 完整 CTest、构建、用户前缀安装和真实桌面会话的进程/动态库路径检查作为交付验收。

## 验收标准

1. 点击客户端重载后，运行中的 Fcitx5 被替换，旧 `(deleted)` ModernIME 动态库不再被当前进程持有。
2. 新进程加载 `/home/wsl/.local/lib/fcitx5/modernime_fcitx5.so`，ModernIME 成为当前激活输入法。
3. 重载失败时客户端明确提示失败阶段并允许重试，不假报成功或永久卡住。
4. Fcitx5 未运行时客户端仍能启动并激活 ModernIME。
5. 全量构建和测试通过，安装后设置客户端可直接使用。
