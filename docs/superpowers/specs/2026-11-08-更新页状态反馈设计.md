# 更新页状态反馈设计（U07）

## 问题与基线

基线 `089e38c3ecfecdf86ecbe1b277a9eb377b45ce47`，工作树干净。真实 `UpdatesPage → GTask → UpdateController` 在隔离 X11/DBus 环境读取模拟 APT 输出：缓存候选 `0.1.22`、当前 `0.1.23` 时，页面显示“已是最新版本”、可用版本 `0.1.23`，并把未知安装渠道显示为 deb。查询退出 100 时统一建议检查网络。新采集位于 `build/更新页状态反馈-20261108/基线-*.png`；这是生产 GTK 页面渲染，非完整 GNOME/Wayland 输入体验验收。

## 设计与边界

本项是有意的状态反馈修正。沿用八模块、折叠详情、异步查询和复制终端升级命令的交互。页面消费后端状态，不新建第二套更新决策模型；不改包事务、权限、渠道迁移、版本比较或输入算法。包锁优先提醒，其他已完成状态显示后端具体说明；可用版本保留查询值，未知渠道明确未知。

检查期间清除上次候选/更新说明，禁用重复检查和复制命令；完成后恢复对应操作。异常不擅自归因于网络。后端默认说明只描述查询事实，不能凭查询失败宣称数据健康，也不能在缺少更新说明时杜撰版本特性。现有显式软件包说明保留。

选择直接修正既有页面和政策文案，避免为少量展示状态新增 Presenter/Manager。该实现选择由维护者依据总目标授权作出，不代表用户逐项指定了技术方案。

## 验收

新增实际 GTK 消费测试，只在外部 APT/DNF 命令边界放夹具。覆盖缓存相同/较旧版本、新版本、输出截断、查询失败、包锁、渠道未知、检查中及失败后重试；校验最终控件与复制内容。保持已有包事务和页面销毁断言。先记录旧实现失败，再修复并复测；无显示环境合法返回 77，desktop 执行不得把跳过算通过。

最终检查更新相关 CTest、现有 GTK 消费者和必需项注册契约；因新增测试接线执行完整隔离 fresh-clone 安装/卸载，另在本机隔离 X11 执行 GTK 测试并检查截图。没有引擎数据格式、学习、容量或按键热路径变化，不声称输入性能提升。改动可通过独立 Git 提交回退，无用户数据迁移；不部署到日常环境。
