# 剪贴板采集边界设计（U09）

状态：实现及阶段验收完成，见[采集边界验收](../../剪贴板采集边界验收-2026-11-08.md)；未部署。基线 `86bad51`，主平台 Ubuntu 24.04 + GNOME。

## 问题和证据

实际构建的 `modernime_fcitx5.so` 在隔离 Fcitx5 5.1.7 实例中运行原有 500ms 轮询，Clipboard addon 仅返回合成文本。`build/剪贴板采集边界-20261108/真实轮询旧版-4.log` 记录：Sensitive 状态、失焦时仍读取并保存；切换到 keyboard-us 时暂停，但切回后补记期间的文本。启动时已有值也直接入库。该探针退出码 0 表示观察过程完成，不是修复通过。

上游 [Clipboard::clipboard](https://github.com/fcitx/fcitx5/blob/5.1.7/src/modules/clipboard/clipboard.cpp) 返回全局最近值，不根据输入上下文过滤。不能把传入 ic 当成隐私保护。初次探针的编译、静态注册和事件循环退出错误保留在证据目录，不作为产品失败或通过。

## 行为与取舍

采用在 adapter 检查采集资格、在既有 PersistentClipboardHistory 建立观察基线的方案。仅补敏感判断仍会恢复补记；完全停用剪贴板会删除现有功能；本批不选这两种方案。

- 开关开启、全局输入启用、最近上下文有焦点、当前输入法为 ModernIME 且没有 Password/Sensitive 时才允许查询 Clipboard 和轮询历史文件。
- 启动及每次恢复后的首次成功读取只建立去重基线，不添加历史；后续变化按原逻辑记录。模式内 Shift 中英切换保持既有采集语义。
- activate/deactivate、敏感能力变化及配置关闭立即使采集区间失效，覆盖两个轮询之间的快速往返；读取异常也使区间失效。普通能力变化不无端重新建立基线。
- PersistentClipboardHistory 唯一拥有最后观察值。新增 `void setObservationBaseline(std::string_view)` 只更新该值，不更改历史、待写队列或磁盘；既有有效复制的失败重试继续保留。
- 恢复后的首个轮询前发生的正常复制也可能被跳过，这是在无复制时间/来源 API 下避免补记的保守边界。既有轮询也不能识别两次采样之间复制相同文本；本批不宣称识别所有复制来源或提供全系统敏感信息过滤。
- 仍按当前 500ms 定时器采样；不承诺500ms最大延迟。暂停期间不读剪贴板；恢复时读取值只用于内存去重，绝不进入可见历史/持久文件。应用未报告敏感能力的内容无法由本修复判断。

## 职责、兼容与验收

本项是采集行为修复，隐私边界遵循 `ALG-GATE/CONTEXT` 的禁止补记原则；不改候选排序、学习资格实现、容量、schema、剪贴板文件格式或事务合并。无新系统依赖。核心去重状态与 adapter 采集区间均由 Fcitx 主线程调用；不新增异步任务。U10 主循环 I/O 另行验证和设计，不以 nonBlocking 锁标记宣称写盘异步。

回归必须加载当前构建插件，使用真实 Fcitx 焦点/能力/输入法事件和生产轮询；合成 Clipboard 只替代外部数据源。检查查询次数、磁盘内容及 V+2 实际候选，包含启动、敏感、密码、失焦、其他输入法、配置关闭、快速往返、读取失败恢复、正常重新复制和外部清空。核心测试验证基线不落盘、不丢失败待写和不复活外部清空。旧行为必须被断言拒绝。

完成 full CTest、GTest、Release Benchmark、core-only 注册/构建与 fresh-clone 安装卸载；GUI 跳过和未测桌面范围分别记录。独立复审后中文提交；回退只撤代码，不回写旧用户历史文件。当前不部署、不推送。

## 独立审查交接

最终审查者只读本批补丁、测试及证据，核对失效事件是否覆盖快速往返、基线是否变成第二份事实、异常是否补记、外部清空/失败重试是否被改变及真实插件加载路径。禁止修改文件、触碰宿主剪贴板、创建子代理或执行重负载测试。发现按具体触发条件及用户影响报告；未验证范围不写通过。
