# 候选解码评分方向修复设计

状态：已实施并完成本阶段隔离验收，见[验收报告](../../候选解码评分验收-2026-11-08.md)。对应全面升级 U04；基线 `03bc68620df44bab5aa1ba730848db798765e098`，Ubuntu 24.04、LibIME 1.1.5。沿用用户授权的自主分阶段实施方式，方案选择由维护者负责，不增加审批关卡。

## 问题与目标

`CandidateRanker` 把 `(max-score)/range` 当作奖励并从最终代价扣除，但输入来自 LibIME 的较高分更优语义。真实 `nihao` 回放中低分项得到更大解码奖励；同先验受控反例选择“拟好”而非较高分的“你好”。这证明次级信号方向错误，不代表当前真实首选普遍错误。

同时存在三条相连边界：新补充候选的 `+0.8/+2.0` 被注释为惩罚；纠错重复身份只在索引更小时覆盖分数且未施加惩罚；无原生解码的个人召回默认分数为 0。单独翻转归一化会把未知分值变成强奖励，也会把原惩罚变成奖励。

目标是统一解码证据含义，修复同条件下的相反偏好，保持常用中文、既有学习和实际选词消费。不开新候选来源，不调权重、模型、字典、召回预算、混排名额或 UI。

证据：`build/候选评分方向-20261108/` 中基线身份、78 组固定输入与 18,467 行原生管线/最终候选记录。LibIME 官方 [1.1.5 PinyinContext](https://raw.githubusercontent.com/fcitx/libime/1.1.5/src/libime/pinyin/pinyincontext.cpp) 使用降序分值排列补充候选；本机头文件 `SentenceResult::score` 与直接回放交叉确认。回放只使用隔离空学习库，未读取日常词库。本轮核对时没有运行中的 `fcitx5` 进程；磁盘插件身份已单独记录，不能沿用上轮 pid。

## 方案取舍

1. **采用：全链路保持 LibIME 高分更优。** `decoder_score` 明确为可缺失证据；Ranker 奖励随分值单调增加，补充惩罚从分值扣除。字段含义与原生接口一致，改动集中于现有 Ranker/Pipeline。
2. 在 Pipeline 将所有分值取负转成代价，保留 Ranker 方向。也能正确，但字段名和原生调试记录需额外辨认符号，重复合并与缺失证据仍必须修复，无明显收益。
3. 去掉解码项或重训权重。会丢失已有信号或扩大质量校准范围，不适用于本次已复现的方向错误。

采用第一项是维护者的技术决定，不记为用户逐项选择。

## 算法契约与接口

- 沿用 `ALG-RANK/TYPO/ZHEN/IDENTITY/DECAY`、`CAND-QUALITY/RECALL/ADAPT/IDENTITY/COMPOSE/SELECT/PAGES`。新增明确子契约 `CAND-DECODER`：已知分值越高，解码奖励不得越低；缺失/非有限证据不参与范围统计、无奖励；补充解码施加非正调整，合并不降低已经持有的解码证据。
- `CandidateScore::decoder_score` 改为 `std::optional<float>`，默认 `std::nullopt`，已知零仍是合法分数。生产赋值仅在现有 Pipeline；类型只服务请求内评分，无持久格式或插件接口变化。NaN/Inf 视为不可用证据。
- 对本次候选集合的有限已知分数计算 `(score-min)/(max-min)`；奖励仍在 [0,1]，最终权重仍为 0.25。空集合、单个已知分或所有分值相同都没有相对解码奖励。保留原先全池归一化时点，不提前屏蔽、不按来源另归一化、不重排资格组。
- 纠错新候选用 `nativeScore-0.8F`，近音变体新候选用 `nativeScore-2.0F`。保留原有预算、跨度映射、近音插位与单音节保护。
- 同文本、规范拼音及消费范围的原生/纠错身份合并时，`source_index` 沿用较小位置先验；解码分独立保留较强的有限证据，纠错证据先扣惩罚再比较。纠错不能因索引更小就覆盖更好的原生分，也不能因原生索引更小就丢弃更好的纠错证据。不增加原生 anchor；变体重复项沿用当前不替换规则。
- 个人召回无原生分时保持缺失，由自身学习/词典证据排序；不伪造解码信号。混排、分页、选择身份、原始击键消费、屏蔽及学习资格均沿用现有真实消费者。

## 状态、兼容与回退

只改一次请求内 CandidateScore，由 Pipeline 写入、Ranker 计算；无线程、全局状态、缓存、I/O 或新的学习入口。200,000 容量、256/Top16 学习召回预算、128/16 原生及补充预算、各用途衰减、清空世代与隐私边界不变。

旧字段从 float 变为 optional 是内部 C++ 类型变更，全部消费者必须重新编译；不发布混合构建。无配置、依赖或数据迁移。回退只撤销本阶段代码，保留用户合法学习数据。

## 验收与允许差异

先增加旧版会失败的 Ranker 与真实 LibIME Pipeline 回归，再实施：方向、缺失/零/非有限、排列不变、补充惩罚、重复身份强证据保留与真实消费。原 `learning_store_test` 把“lower decoder score”写成预期，是本次明确纠正的错误契约；仅调整该夹具的高低分与说明，其他断言不动。

同一模型/词典、隔离空库、78 组固定输入回放比较全部候选身份、消费和排名，逐条分析首选及前排变化。新奖励允许同资格近分候选重排；缺失分值不得改变已知分值归一化。不得用整批更新金样、固定词语补丁、削弱学习或缩小容量通过测试。

既有学习曲线（一次保护、10 次会话晋升、50 次重开）、物理分页和实际提交由原 GTest 及 Controller 套件联测；完整 CTest/GTest/Release Benchmark 和隔离 fresh-clone 均须执行。验收报告保留失败、跳过、环境依赖及前后性能，不以内部评分正确声称整体输入准确率提升。真实 GNOME/Wayland 与长期耐久仍属后续综合验收。
