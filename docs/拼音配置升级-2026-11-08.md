# 拼音配置升级

基线：`2559cac`；主平台：Ubuntu 24.04 + GNOME。按用户最新要求采用局部增量构建和直接相关回归，完整发布门禁集中到集成阶段。

## 实施顺序

1. 六组模糊音独立开关：`z/zh`、`c/ch`、`s/sh`、`l/n`、`en/eng`、`in/ing`。默认均开启，兼容已有配置；输入与按键页提供开关、搜索定位及现有保存/恢复流程。
2. 共享 LibIME 解析配置由输入线程更新；配置代次使所有会话旧候选失效。保留当前原始击键，重新解码；先更新 Provider，再让 Controller 发布新页面，避免显示旧结果。
3. 验证每组开关的真实候选差异、重新启用、共享上下文旧请求拒绝、保存重开及 GTK 控件。沿用默认拼音回归，不改既有断言。
4. 接入 LibIME 内置小鹤、自然码双拼方案；其他双拼方案尚未提供。双拼原始击键与完整拼音学习身份分离，部分消费、数字/宏按键和热切换沿用现有 Controller。

## 契约与边界

新增 `ALG-FUZZY-CONFIG`，依赖 `ALG-PINYIN/IDENTITY/GATE` 与 `CAND-RECALL/SELECT`。关闭某组只停止该组发音混用，不删除学习数据或改变用户词条的规范拼音。拼写纠错与近音变体策略保持；核验其候选不能意外恢复被关闭的发音组。

不改变候选评分、学习政策、容量、持久格式或默认输入能力。共用重型词典和模型，不按模糊音组合复制引擎。双拼的具体消费映射先验证 LibIME 格点接口，再实施，不通过把编码当全拼写入词库来凑通功能。

## 验收记录

六组模糊音已实现。引擎与设置客户端增量构建成功；`modernime_settings`、`modernime_pinyin_provider`、`modernime_page_registry`、`modernime_settings_save_gtk` 四项直接相关 CTest 全部通过，耗时14.11秒，0失败/跳过。包含实际候选开关、重新启用、共享会话继续编辑、旧候选拒绝、保存重开和 GTK 操作。

初版暴露 LibIME 配置变更清空上下文的问题，已从既有页面的原始拼音恢复后重新解码；修复前失败与通过结果保留在 `build/拼音配置验证/`。未重复全量 GTest、Benchmark 或安装卸载，未部署到日常输入法。

## 双拼接入（基线 df25c57）

新增 `ALG-SHUANGPIN`，依赖 `ALG-PINYIN/IDENTITY/GATE/RANK` 与 `CAND-RECALL/ADAPT/SELECT`。沿用 [LibIME 1.1.5 的原生双拼解析](https://github.com/fcitx/libime/blob/1.1.5/src/libime/pinyin/pinyinencoder.cpp)，不自行维护键位表。`ShuangpinInput` 只为当前请求提取音节边界和匹配事实，完整拼音查询最多16种读音；学习仍走原快照与 Writer。排序接收解析器提供的匹配事实，保留既有评分；双拼编码不进入全拼纠错或读音误写提示。Raw 编码回车上屏不学作英文，明确英文候选仍走原学习政策。

`pinyin.scheme` 支持 `full`（默认）、`xiaohe`、`ziranma`。小鹤 `nihc`、自然码 `nihk` 输出“你好”；选择 `nihcma` / `nihkma` 中的“你好”消费4字节并保留 `ma`。输入与按键页可切换方案，保留输入并重新解码。新增内容不改变词典/模型格式或安装依赖。

引擎与客户端增量构建成功；5项直接相关检查最终均通过：设置、GTK保存、搜索注册、候选Provider、真实Controller按键回归。前3项在隔离GNOME中通过；显示执行器60秒总时限中断了后续检查，仅补跑引擎相关项。Provider通过（74.49秒）；非隔离Controller运行在既有`yuedign`断言失败，改用临时HOME/XDG目录后原断言通过（36.64秒），未修改生产逻辑或放宽断言。最初误用了不存在的集成测试构建目标名，改为现有`modernime_pinyin_engine_tests`后构建成功。原始记录均保留在`build/双拼接入验证/`。

新双拼路径包含两方案实际候选、已有学习词召回、完整拼音持久身份、部分消费、热切换、数字选词与金额宏；未新增压力矩阵或运行全量安装/卸载、GTest、Benchmark。本批不宣称性能提升，尚未安装到日常桌面。
