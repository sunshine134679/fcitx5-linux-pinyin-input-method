# 拼音配置升级

基线：`2559cac`；主平台：Ubuntu 24.04 + GNOME。按用户最新要求采用局部增量构建和直接相关回归，完整发布门禁集中到集成阶段。

## 实施顺序

1. 六组模糊音独立开关：`z/zh`、`c/ch`、`s/sh`、`l/n`、`en/eng`、`in/ing`。默认均开启，兼容已有配置；输入与按键页提供开关、搜索定位及现有保存/恢复流程。
2. 共享 LibIME 解析配置由输入线程更新；配置代次使所有会话旧候选失效。保留当前原始击键，重新解码；先更新 Provider，再让 Controller 发布新页面，避免显示旧结果。
3. 验证每组开关的真实候选差异、重新启用、共享上下文旧请求拒绝、保存重开及 GTK 控件。沿用默认拼音回归，不改既有断言。
4. 随后接入 LibIME 内置双拼方案。双拼原始击键必须与完整拼音学习身份分离，真实部分消费、数字/宏按键和热切换验证完成后才作为已实现功能交付。

## 契约与边界

新增 `ALG-FUZZY-CONFIG`，依赖 `ALG-PINYIN/IDENTITY/GATE` 与 `CAND-RECALL/SELECT`。关闭某组只停止该组发音混用，不删除学习数据或改变用户词条的规范拼音。拼写纠错与近音变体策略保持；核验其候选不能意外恢复被关闭的发音组。

不改变候选评分、学习政策、容量、持久格式或默认输入能力。共用重型词典和模型，不按模糊音组合复制引擎。双拼的具体消费映射先验证 LibIME 格点接口，再实施，不通过把编码当全拼写入词库来凑通功能。

## 验收记录

六组模糊音已实现。引擎与设置客户端增量构建成功；`modernime_settings`、`modernime_pinyin_provider`、`modernime_page_registry`、`modernime_settings_save_gtk` 四项直接相关 CTest 全部通过，耗时14.11秒，0失败/跳过。包含实际候选开关、重新启用、共享会话继续编辑、旧候选拒绝、保存重开和 GTK 操作。

初版暴露 LibIME 配置变更清空上下文的问题，已从既有页面的原始拼音恢复后重新解码；修复前失败与通过结果保留在 `build/拼音配置验证/`。未重复全量 GTest、Benchmark 或安装卸载，未部署到日常输入法。双拼留待下一批。
