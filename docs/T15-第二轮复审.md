## 2. S1 / 测试设施安全：跨线程替换 IoHook 可释放正在执行的闭包

**位置：** `tools/settings/data_controller.cpp:40–46,410–412`，`data_controller.h:77–78`。

新增 s_ioHook 是一个进程级 std::function。worker 直接调用全局对象，主线程的 setIoHookForTesting 同时赋值/销毁它，没有同步，也没有保护在途调用的闭包寿命。

正式测试会在后台任务期间安装、替换、清空钩子。以 entered/finished 标志或固定 drain/sleep 时间代替完整退出握手，不能保证旧回调已经离开；ASAN 也不能仅凭一次普通套件绿色排除这类交错。

### 确定性 ASAN 复现

探针调用真实 DataController::loadDictionary，安装一个持有 shared_ptr 状态的钩子，在 worker 进入后暂停；主线程 setIoHookForTesting(nullptr)，再放行 worker 读取自己闭包内的状态。其他握手状态均为原子变量，并活到 worker join 后。

```text
hook_lifetime_asan exit=1
AddressSanitizer: heap-use-after-free
READ: notifyIoHook -> DataController::loadDictionary -> worker callback
FREE: DataController::setIoHookForTesting -> std::function replacement
```

这不是捕获已销毁的调用方局部变量：被提前释放的是全局 std::function 自己拥有的闭包。证据见 hook_lifetime_asan.log。

**范围说明：** 本次 UAF 在安装了测试钩子的路径复现；普通未安装钩子的输入法使用路径没有复现这一问题。它影响本轮并发故障注入和验收可靠性，不把它描述成已复现普通用户运行时崩溃。

### 最小目标

- 安装/读取/卸载钩子必须有明确同步和寿命规则。可在短锁内取稳定的本地副本，再锁外调用，保证全局替换不会释放在途回调；不要持锁执行会等待栅栏的钩子。
- 若采用“卸钩前必须全部静止”的协议，必须在测试设施/调用点落实完整握手，不能只写注释后继续允许未检查的并发替换。
- 测试捕获的状态要活到所有相关 worker/回调退出。用显式完成信号/任务完成观察清理，替代固定 30/50 次 sleep/drain。
- 把上述跨线程卸钩场景加入针对性回归，ASAN/UBSAN 下无错误。只修最小测试 seam，不创建通用任务管理器，也不借此重构页面主流程。

## 3. S2 / R3 验收：旧统计与在途搜索测试仍没有捕获目标交错

### 3.1 正式旧统计测试会放过已知有缺陷的旧实现

**位置：** `testLearningPageStaleRefreshAndClearReentry` Scenario A，以及 `DataController::learningEntryCount` 开头的 notifyIoHook。

当前钩子在读取计数**之前**阻塞。代码注释写“已读到 1 后暂停”，实际情况是：数据库清空、第二次请求返回 0 后，第一次请求才开始真正读取，也只会读到 0。即使旧实现没有 generation 检查，按钮也不会被该请求重新启用。

本轮只在忽略目录构造反证：保留当前 DataController、正式测试 Scenario A 和其他依赖，把 LearningPage 换成已知存在旧结果覆盖 Bug 的 `2a0460a` 版本。Scenario A 仍然退出 0：

```text
old_learning_stale_formal_test exit=0
REVIEW old_learning_page_stale_test_passed=1
```

该反证只执行 Scenario A，避免其他场景掩盖它。上文真实读后栅栏已证明当前生产修复有效，因此这里要求的是补可靠的长期回归，不是推翻生产修复。

**完成标准：** 让旧请求真实取得 count=1 后、主线程接受结果前暂停；第二个请求读到 0 并应用，再释放旧结果。当前修复必须通过，已知旧实现必须确定性失败。应观察旧 worker 完成，不用固定睡眠假定它结束。可在现有最小测试 seam 增加清晰的读后阶段，也可沿用真实 SQLite 读后包装，不复制页面业务逻辑。

### 3.2 三次搜索信号都发生在上一批完整渲染之后

**位置：** `pumpEventsUntil` 第 91–95 行及 `testContinuousSearch` 第 635–655 行。

pumpEventsUntil 内层 while 会持续处理全部就绪 idle，之后才检查条件。因此“观察到 search-changed 且行数大于 0”时，旧列表可能早已完整渲染。控件防抖还会给上一批更多完成时间。

本轮复制当前正式测试，仅在两次所谓“中断”之前增加行数观察，链接当前生产页面，结果：

```text
round1_before_interrupt_rows=4000 expected_total=4000
round2_before_interrupt_rows=4000 expected_total=4000
Actual search-changed signals: 3
```

三次信号和最终 4000 行精确比对是真实的；这次运行没有覆盖未完成批次被替换。

**完成标准：** 在至少两次切换前明确观察 `0 < renderedRows < expectedOldRows`，下一次生产过滤处理必须在旧 idle 尚未结束时发生。逐步泵事件或受控发出真实控件信号，使测试不被控件防抖/无限 drain 吞掉交错；不增加另一套过滤/渲染逻辑。保留最终完整行集合、原索引、心跳和移走原文件后搜索的有效断言。

### 验收口径

- 当前慢 I/O 已真实接入生产读取，加载/删除保存的执行证据有效；不要将其扩写成所有导入/导出 UI 分支也已逐一运行。对声称已验的入口给出对应执行，未跑如实列出。
- 普通构建 heartbeat 门限仍为 100ms；当前源代码对 ASAN 使用 300ms 门限，应在报告中区分。不能将插桩通过自动描述成同一 100ms 断言已执行。本轮实测插桩搜索为 90ms，但其程序门限仍是 300ms。
- 本轮 ASAN 使用 detect_leaks=0，仅报告 UAF/地址/UB 检查结果，不声称独立验证零泄漏。若交付声明零泄漏，应提供实际启用 leak 检查的证据或明确其范围。
