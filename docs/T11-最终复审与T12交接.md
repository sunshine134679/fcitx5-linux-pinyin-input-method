## 2. 下一阶段只执行T12

依据：`docs/superpowers/plans/2026-10-16-架构整改实施与验收方案.md` 第3.3节及T12。T12是P1-06第一部分：**完整包操作所有权**。

目标：一次包操作从spawn之前到确认完成，只有一个状态负责人。页面busy仅展示，不能决定是否允许开始。普通等待期间、认证、超时转后台、页面关闭都必须保持正确占槽语义。

建议实施顺序：

1. 固定当前基线、检查UpdateController实际调用点和状态/结果对象；保留现有静态API作为兼容门面。
2. 先用假pkexec和确定性栅栏复现普通等待期同时刷新/升级导致重复spawn；不等待超时才测并发。
3. 实现spawn前 `tryBeginPackageOperation(kind)`，返回operationId；合法状态转移只有一个负责人。未知结果进入Uncertain并继续占槽。
4. 按ID完成和一次消费结果；最多8项未消费完成结果，满时拒绝新操作且保留旧结果。
5. 接回UpdateController与页面展示，完成更新/运行时/设置保存相关回归及原计划G3/G6，记录未完成的真实桌面项。

状态按原计划：Idle→Starting→Running→Continuing→Completed；身份或结果不确定转Uncertain。Starting/Running/Continuing/Uncertain均占槽。spawn失败或认证取消也必须按同一ID完成释放；后台继续不能重新占槽；页面开关不能释放真实操作。

| 必需测试 | 行为验收 |
|---|---|
| NormalWaitRejectsConcurrentOperation | 假pkexec在spawn后栅栏阻塞；两个刷新/升级请求仅产生1次spawn |
| AuthenticationFailureReleasesSlot | 认证失败/取消、启动失败均释放对应操作；后续请求可开始 |
| CompletionConsumedOnce | 同一operationId结果只消费一次，旧结果不会被新操作覆盖 |
| OldCompletionCannotFinishNewOperation | 旧ID完成不能释放或改变新ID操作 |
| UnconsumedResultsHaveBound | 未消费完成结果≤8；满时拒绝开始，不丢已有结果 |
| 页面开关与状态转移 | 页面关闭不结束事务；超时继续仍占槽；Uncertain不自动重试或释放 |
