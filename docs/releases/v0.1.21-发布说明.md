> **发布状态说明（2026-10-25）**：本版本 Release CI 仍在 Ubuntu 22.04 门禁失败（真实根因为简拼输入被学习单字越组劫持，见 [v0.1.22](v0.1.22.md) §2），**未产出 Release 资产**；正式发布版见 [v0.1.22](v0.1.22.md)。功能内容与 v0.1.22 一致。

日期：2026-10-25  
标签：`v0.1.21`

## 1. 版本概述

ModernIME v0.1.21 是 v0.1.20 的发布门禁修正版本，功能内容与 v0.1.20 一致：**高频易错音内联读音提示（卡qiǎ住）、简拼部分消费范围修复、读音提示跨 fcitx5 链路传递修复**。

v0.1.20 在 GitHub Actions 的 Ubuntu 22.04 作业中因旧版 LibIME 语言模型（1.0.11）下的单字冷启动排名与符号词排名差异未通过测试门禁，未能产出 Release 资产（v0.1.18/v0.1.19 亦受同一问题影响，`releases/latest` 曾停留在 v0.1.17）。本版本沿用项目既有的“遗产模型基线”机制完成精确标定后重新发布。

## 2. 发布门禁修复（相对 v0.1.20）

- **问题复现**：下载 Ubuntu 22.04 官方 `libime-data` 与 `libime-data-language-model` 1.0.11 数据包，通过 `MODERNIME_PINYIN_DICT` / `MODERNIME_PINYIN_LM` 在本地 100% 复现两个失败：
  - `modernime_pinyin_daily_simulation`：`pozhehao` 的「破折号」在现代模型（1.1.5）为索引 0，旧模型实测索引 16（仍为第 2 页）；
  - `modernime_personal_engine_gtest`：`shi/jian` 的「试/键」在现代模型前 5，旧模型实测索引 6（仍在首页）。
- **修复方式**：复用 `NativePinyinTestBaseline::hasAuditedLegacyProfile()` 的行为探测识别旧模型，仅对旧模型使用实测基线（试/键 索引 ≤6、破折号 索引 15~17），并输出实际排位；**现代模型保持原有严格门禁**（试/键 前 5、破折号索引 0）。`ge` 次选断言在旧模型下改为“必须仍是中文且英文原文不得插队”，现代模型仍与原生次选完全一致。
- **验证**：Jammy 数据与 Noble 数据各跑全量 CTest，均 79/79 通过。

## 3. 功能内容（同 v0.1.20）

### 3.1 高频易错音内联读音提示（卡qiǎ住）

- 输入 `kazhu`（把「卡住」的「卡」记成 kǎ）时，首选显示 `卡qiǎ住`，qiǎ 以小号注音内嵌在「卡」之后；规范读音依据《现代汉语词典》第七版（动词义 qiǎ）。
- 离线词表 32 词（卡住/卡在/卡顿/卡壳/关卡/发卡/卡脖子、角色 jué、睡觉 jiào、银行 háng、说服 shuō、血液 xuè、粗犷 guǎng、给予 jǐ、落下 là、落枕 lào、穿着 zhuó 等），由 `scripts/生成易错音词表.py` 逐字对 Unicode Unihan 五读音字段（含繁简形关联）校验后生成，随仓库离线发布。
- 触发规则对齐主流输入法：仅当用户输入的无声调节节与该字规范读音不一致时才提示；正确读音（`qiazhu`）、简拼（`kzhu`）、错位拼与非词表词（`卡着`）一律不提示。提示只影响展示，不改变排序、身份、消费范围与学习。

### 3.2 简拼部分消费范围修复

- 多音节简拼下，原生解码只覆盖输入前缀音节的候选不再冒充全消费：`zmhuishi` 的首选恢复为全消费整句「怎么回事」，高频学习的「怎么」以真实部分消费（`zm`，2 字节）居次席；选中后未消费的 `hui'shi` 保留在组合中继续输入。
- 读音提示字段完整穿过 Provider→引擎→fcitx5 候选列表→UI 重建全链路，修复实机候选条不显示提示的问题。

### 3.3 容错与学习链路强化（承接 2026-10-24 专项）

- 近音变体召回（`baoyan→表演`、`lui→六`）、换位+简拼混合修复（`wiesm→为什么`）、模糊音组间压制修复（`zongwen` 经学习可升首）、提交后空有效窗口不再误扣词频。
- 不变量矩阵新增 #47~#51。

## 4. 平台兼容性与升级指南

### 4.1 安装渠道支持矩阵

| 资产文件名 / 渠道 | 适配发行版与代号 | 架构 | 最低系统要求 |
|---|---|---|---|
| `modernime_0.1.21_amd64_ubuntu22.04.deb` | Ubuntu 22.04 LTS (`jammy`) / Debian 12 (`bookworm`) | `amd64` (`x86_64`) | glibc ≥ 2.35, Fcitx5 ≥ 5.0.14, LibIME ≥ 1.0.11 |
| `modernime_0.1.21_amd64_ubuntu24.04.deb` | Ubuntu 24.04 LTS (`noble`) | `amd64` (`x86_64`) | glibc ≥ 2.39, Fcitx5 ≥ 5.1.7, LibIME ≥ 1.1.5 |
| `modernime-0.1.21-1.oe24.x86_64.rpm` | openEuler 24.09 (`oe2409`) / 24.03 SP4 | `x86_64` | glibc ≥ 2.38, Fcitx5 ≥ 5.0.14, LibIME ≥ 1.0.11 |
| `modernime-0.1.21-linux-x86_64.tar.gz` | Linux 便携免编译包 | `x86_64` | glibc ≥ 2.34, libstdc++ ≥ 3.4.30, Fcitx5 |
| 源码构建 (`./install.sh`) | 任意 Linux (含 ARM64, RISC-V) | 全架构 | C++20, CMake ≥ 3.24, GCC ≥ 10, Fcitx5-devel |

### 4.2 升级方式

- **源码升级**：
  ```bash
  git pull --ff-only
  ./install.sh
  ```
- **APT 仓库升级（Ubuntu / Debian）**：
  ```bash
  sudo apt update
  sudo apt install --only-upgrade modernime
  ```
- **DNF 仓库升级（openEuler）**：
  ```bash
  sudo dnf upgrade --refresh modernime
  ```
- **设置客户端**：打开「ModernIME 设置」客户端 -> 切换至「检查与更新」页面 -> 点击「检查更新」并一键升级。
- **升级数据安全**：安装器在升级前自动备份学习数据库（SQLite WAL Checkpoint + Backup API 完整性校验、LMDB 备份），用户词典与个性化配置哈希保持不变。
