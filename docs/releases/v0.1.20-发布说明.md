# ModernIME v0.1.20 发布说明

日期：2026-10-25  
标签：`v0.1.20`  
构建源码：基于通过全量 CTest、双套件隔离冒烟与实机部署验证的正式代码基线。

---

## 1. 版本概述

ModernIME v0.1.20 是专注于**中文读音教学提示、简拼消费范围正确性与候选展示链路可靠性**的正式版本。

本版本新增「高频易错音内联读音提示」：当用户把多音字词记混读音（如把「卡住」记成 `kazhu`）时，首选候选会以 `卡qiǎ住` 的形式在字后内联标注规范读音，效果对齐主流商业输入法；同时修复了实机候选条不显示提示的跨链路字段丢失问题，以及多音节简拼下部分消费候选冒充全消费、借学习加成越过整句篡位的排序缺陷。

## 2. 核心改进与技术实现

### 2.1 高频易错音内联读音提示（卡qiǎ住）

- **调研依据**：「卡住」规范读音为 **qiǎ zhù**（《现代汉语词典》第七版：`卡` 表“夹住、堵塞”的动词义读 qiǎ，外来名词义读 kǎ）；微信输入法「正确读音秒知道」与搜狗同类功能的共同触发规则是**输入读音有误时才在出错字后标注正确读音**。
- **离线词表**：`core/include/modernime/core/reading_hints.inc` 收录 32 个高频易错音词（卡住/卡在/卡顿/卡壳/关卡/发卡/卡脖子、角色 jué、睡觉 jiào、银行 háng、说服 shuō、血液 xuè、粗犷 guǎng、给予 jǐ、落下 là、落枕 lào、穿着 zhuó 等），由 `scripts/生成易错音词表.py` 生成，逐字对 Unicode Unihan 五个读音字段（含繁简形关联）校验，任一字不符即拒绝生成；带声调展示串按拼音正词法程序化生成并 NFC 规范化。词表随仓库离线发布，构建零网络请求。
- **触发门控**：仅当（a）输入为全拼且音节数与词字数一致（排除简拼/错位拼）；（b）前 3 位候选为词典成词且命中词表；（c）非标注位逐音节与候选全拼一致；（d）**标注位的输入读音 ≠ 该字规范读音**（`kazhu` 的 `ka` ≠ `qia`）时才提示。正确读音（`qiazhu`）、简拼（`kzhu`）、错位拼与非词表词（`卡着`）一律不提示。
- **渲染**：布局与分页度量同步计入提示宽度（溢出回退时与尾注一并放弃），渲染按 前缀→注音→后缀 以小号注音字体（14pt 注音色）内联绘制，选中态显示 `1.卡qiǎ住`。提示只进展示字段，不改变候选身份、排序、消费范围与学习事件。

### 2.2 读音提示跨 fcitx5 链路传递

- **问题**：读音提示生成于 Provider 页面，但引擎转成 fcitx5 候选列表时只携带词文本与尾注，UI 侧重建候选页时字段丢失，实机候选条永远读不到提示。
- **修复**：`FcitxCandidateWord` 完整携带 `readingHint` 与标注字位，发布时传入、UI 重建时读回，并在 `modernime_fcitx5_input_panel` 增加跨链路断言防复发。

### 2.3 简拼部分消费范围修复（zmhuishi 整句篡位）

- **问题**：匹配等级为 0 的原生候选默认按全消费处理；多音节简拼下原生解码只覆盖前缀音节的候选（`zmhuishi` 下的「怎么」实际只消费 `zm`）因此冒充全消费，高频学习词条借加成越过全消费整句「怎么回事」篡位，且选中后会吞掉未消费后缀。
- **修复**：按“输入音节段是候选音节前缀（声母 / zh、ch、sh 双字母声母 / 全音节）”逐段对齐还原真实消费范围，部分消费候选归入部分消费池，既有混排结构恢复「整句第 1、个人前缀第 2」；精确拼音前缀（`-1`）与整词覆盖路径行为不变。真实库快照复核：`zmhuishi` → `1.怎么回事 2.怎么`（消费 2/8），选中「怎么」后 `hui'shi` 保留在组合中。

### 2.4 容错与学习链路强化（承接 v0.1.19 后的专项整改）

- **近音变体召回**：`baoyan→表演`、`taojian→条件`、`lui→六` 可达且不篡合法首选；明确不引入 ang→an 方向（容错容忍对会侵入精确匹配组）。
- **换位+简拼混合**：`wiesm→为什么` 居首，`jaili→家里` 恢复，英文前缀保护（`garag→garage`）不受影响。
- **模糊音组间压制修复**：`zongwen/lali` 等规范读音候选经 20 次选择（学习增益 ≥1.8 且音节数一致）可升至首位。
- **空有效窗口负反馈修复**：提交后宿主首次上报空窗口不再判定“删光”，真实删除行为保持原语义。
- **分页一致性**：新增“分页度量 = 布局度量”一致性断言，杜绝展示字段导致的页内断裂。

## 3. 平台兼容性与升级指南

### 3.1 安装渠道支持矩阵

| 资产文件名 / 渠道 | 适配发行版与代号 | 架构 | 最低系统要求 |

| `modernime_0.1.20_amd64_ubuntu24.04.deb` | Ubuntu 24.04 LTS (`noble`) | `amd64` (`x86_64`) | glibc ≥ 2.39, Fcitx5 ≥ 5.1.7, LibIME ≥ 1.1.5 |
| `modernime-0.1.20-1.oe24.x86_64.rpm` | openEuler 24.09 (`oe2409`) / 24.03 SP4 | `x86_64` | glibc ≥ 2.38, Fcitx5 ≥ 5.0.14, LibIME ≥ 1.0.11 |
| `modernime-0.1.20-linux-x86_64.tar.gz` | Linux 便携免编译包 | `x86_64` | glibc ≥ 2.34, libstdc++ ≥ 3.4.30, Fcitx5 |
| 源码构建 (`./install.sh`) | 任意 Linux (含 ARM64, RISC-V) | 全架构 | C++20, CMake ≥ 3.24, GCC ≥ 10, Fcitx5-devel |

### 3.2 升级方式

- **源码升级**：
  ```bash
  git pull --ff-only
  ./install.sh
  ```
- **APT 仓库升级（Ubuntu / Debian）**：
  ```bash
  sudo apt update
  sudo apt install --only-upgrade modernime
  ```
- **DNF 仓库升级（openEuler）**：
  ```bash
  sudo dnf upgrade --refresh modernime
  ```
- **设置客户端**：打开「ModernIME 设置」客户端 -> 切换至「检查与更新」页面 -> 点击「检查更新」并一键升级。
- **升级数据安全**：安装器在升级前自动备份学习数据库（SQLite WAL Checkpoint + Backup API 完整性校验、LMDB 备份），用户词典与个性化配置哈希保持不变。

## 4. 验证摘要

- 全量 CTest：79/79 通过。
- 隔离冒烟：容错专项 16,411 次 + 通用套件 17,376 次真实提交全绿，篡位 0、垃圾置顶 0；两套件前后宿主真实学习库 SHA-256 逐字节一致。
- 延迟：击键 P50 约 5.7 ms、P99 约 12.2 ms，与 v0.1.19 基线（5.66 / 12.07 ms）持平。
- 新增回归：`testKeystrokeVariantRecallAndReadingAnnotation`、`testLearnedPartialPrefixDoesNotUsurpAbbreviationSentence`、`modernime_candidate_reading_hint`（布局/渲染/分页一致性）、`modernime_fcitx5_input_panel`（跨链路传递）。
- 实机：`kazhu` 显示 `1.卡qiǎ住`；`z'm'hui'shi` 首选「怎么回事」；插件重启后 `/proc/<pid>/maps` 映射磁盘当前 `.so`（无 deleted）。
