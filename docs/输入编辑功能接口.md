# 输入编辑功能接口（客户端交接）

2026-11-10。后端首次交接实现成对标点、智能标点、按应用输入模式和撤销重选，未修改 GTK 页面；后续客户端接入如下。客户端仍维持八个模块。

## 客户端入口

- 「输入与按键 → 输入状态」：按应用记住中英状态，管理应用默认规则。应用标识精确匹配、区分大小写；规则列表可搜索、新增、编辑和删除，临时模式记忆不写磁盘。
- 「输入与按键 → 快捷键」：撤销上屏并重新选词开关，展示固定快捷键 `Ctrl+Shift+BackSpace`、15 秒窗口和应用支持条件；操作限制可查看开关提示。
- 「输入与按键 → 标点」：中文标点总开关、成对补全和智能半角保护。「更多标点设置」包含下划线模式与逐键自定义，搜索对应设置会展开并定位。
- 两类规则弹窗编辑私有副本，取消不改变设置草稿；「使用这些规则」更新主窗口草稿，仍需「保存设置」才写盘。新增与编辑复用 `validateSettings()` 校验，删除规则恢复默认行为；标点子项跟随总开关，关闭不清除已配置的值。
- 继续使用 `SettingsWindowModel` 的保存、外部修改冲突和放弃流程；新控件及规则回调不额外读取或写入文件。UI 接线位于 `tools/settings/pages/input_page.cpp` 与 `tools/settings/input_rule_dialog.cpp`，客户端不调用下文引擎编辑接口。

## 配置接口

公共头文件：`core/include/modernime/core/settings.h`。沿用 `ModernIMESettings` 与 `SettingsStore`，配置文件由 `SettingsPaths::fromEnvironment(...).settingsFile` 定位，通常是 `~/.config/modernime/settings.conf`。

| C++ 字段 | 配置键 | 默认与语义 |
|---|---|---|
| `bool autoPairPunctuation` | `punctuation.auto_pair` | `true`，补全中文括号、书名号和引号 |
| `bool smartPunctuation` | `punctuation.smart` | `true`，连续标识符、网址和路径标点保留半角；关闭后仍保留原有紧邻英文/数字的保护 |
| `UnderscoreStyle underscoreStyle` | `punctuation.underscore` | `Smart` / `smart`；另支持 `Ascii` / `ascii`、`Chinese` / `chinese` |
| `std::map<char,std::string> punctuationOverrides` | `punctuation.map.<十进制 ASCII>` | 空；按键对应固定文本，覆盖智能转换和该键的自动配对 |
| `bool rememberModePerApp` | `input.remember_per_app` | `false`，开启后在当前 Fcitx 进程内记忆每个应用的中英模式 |
| `std::map<std::string,InputMode> appInputModes` | `input.app.<program>` | 空；应用默认模式，值为 `chinese` 或 `english` |
| `bool undoCommitEnabled` | `input.undo_commit` | `true`，启用 `Ctrl+Shift+BackSpace` 撤销重选 |

`punctuation.enabled` 仍是标点总开关。`input.enabled`、全局 `defaultMode`、学习开关和现有快捷键保持原职责。

例子：

```ini
punctuation.auto_pair=true
punctuation.smart=true
punctuation.underscore=smart
punctuation.map.47=/
punctuation.map.95=_
input.remember_per_app=true
input.app.code=english
input.app.org.gnome.TextEditor=chinese
input.undo_commit=true
```

上例的 `punctuation.map.95=_` 会使下划线始终为 `_`；删除该条映射即可恢复 smart 模式下「独立输入为 ——，ASCII 标识符内为 _」。`ascii`、`chinese` 分别固定下划线的两种输出，逐键映射优先级最高。

映射键限 ASCII 可打印标点；文本为非空、无 ASCII 控制字符、首尾无空白的有效 UTF-8，最多 32 字节。删除操作使用 `punctuationOverrides.erase(key)`，不保存空串。应用标识精确匹配 Fcitx `InputContext::program()`，区分大小写，不支持通配符；限 1–128 个 ASCII 字母、数字或 `._-/@`，规则最多 128 条。模式使用 `InputMode::Chinese/English`。

加载、校验和保存示意（放在现有设置保存流程，不在 GTK 回调中新增同步 I/O）：

```cpp
auto loaded = core::SettingsStore::load(path);
// IoError 时显示错误；不能拿默认值覆盖未知的磁盘配置。
auto edited = loaded.settings;
edited.autoPairPunctuation = true;
edited.appInputModes["code"] = core::InputMode::English;
auto validation = core::validateSettings(edited);
auto saved = core::SettingsStore::saveWithResult(
    path, edited, core::SettingsExpectedBaseline::fromLoadResult(loaded),
    &loaded.rawLines);
// 分别处理 Saved / Conflict / Invalid / IoError，继续使用原有冲突 UI。
```

保存时保留其他设置、注释和未知键；移除的映射/应用规则不会因保留旧行而复活。引擎沿用约 2 秒的配置轮询。标点及撤销开关热载后生效；应用默认规则在下次激活该应用时生效，不打断当前组合。调整应用规则或记忆开关会清空进程内模式记忆，其他外观设置不清空它。

## 输入行为

- 成对补全覆盖 `（）`、`【】`、`《》`、`“”`、`‘’`，光标位于中间；再次按对应闭符号越过本会话补出的闭符号，空对按 Backspace 或 Delete 一次删除。支持嵌套和括号内候选上屏；正在输入的拼音中 `'` 仍是隔音符，`[` / `]` 仍优先以词定字，翻页键仍优先服务组合。
- 默认智能模式下，组合尚未选词时按 `_` 保留原始击键，不依据当前候选的语言猜测意图：`inter_` 不接受 `interface` 补全，`foo_bar` 不接受“佛”，`nihao_` 同样保留拼写。先选词上屏“你好”再按 `_` 仍得到“你好——”，独立输入仍为 `——`。显式中文下划线或非 `_` 的逐键映射仍优先。此修复复用原配置，客户端无需增加接口。
- 普通英文/数字后保持原有半角规则，并保护 `snake__`、`https://`、`file.name/`、`name@` 这类连续 ASCII 片段。不能预测后续输入；希望以下划线、斜杠开头的内容始终半角时使用逐键映射。
- 成对编辑要求应用提供有效周边文本、无选区且当前有焦点。终端不自动补对。支持 Fcitx 5.1.2 光标提交的客户端直接定位；兼容客户端按提交后发送一组 Left 按下/释放定位。不满足能力或处于敏感输入时退回普通标点，不移动光标、不删除选区。只跳过本次补出的闭符号，不接管文档中原有的符号。
- 应用模式优先级：开启记忆后的当前进程记录 → 该应用规则 → 全局默认。空 `program()` 沿用全局默认，不把所有未知应用合并记忆。应用规则持久保存，临时模式记忆不写磁盘，重启 Fcitx 后重新应用默认规则。
- 撤销重选只针对最近一次普通候选提交，15 秒内可用；空格、数字键和鼠标选择共用同一入口。恢复原始击键和候选，部分选择会恢复已消费前缀与原剩余输入。例如 `nihaoma` 选「你好」留下 `ma`，撤销恢复 `nihaoma`。只支持一级；回车原文、以词定字、生成宏、标点和剪贴板不提供此撤销。
- 新输入、外部编辑、光标移动、选区、失焦/重置、切换输入模式、设置热载或进入敏感状态会使撤销失效。执行前核对文本、光标及两侧窗口；不满足条件时放行快捷键。`Ctrl+BackSpace` 继续留给应用删词。
- 撤销后的中文/用户词负反馈沿现有 `onNegativeFeedback` 且遵守学习开关；不删除词典、不清学习库，也不声称事务级回滚之前的全部学习。恢复组合本身不产生额外正向学习。

## 引擎内部接口（客户端无需调用）

`adapter/fcitx5/include/modernime/fcitx5/engine.h` 新增可选宿主接口：

```cpp
struct TextEditContext { std::string before, after; std::size_t cursor; };
virtual std::optional<TextEditContext> textEditContext() const;
virtual bool insertPair(std::string_view opener, std::string_view closer);
virtual bool replaceSurrounding(std::string_view before,
                                std::string_view after,
                                std::string_view replacement);
bool ModernIMEController::undoLastCommit();
```

窗口两侧各最多 256 字符，`cursor` 为宿主文本中的 Unicode 码点偏移。缺省宿主返回不支持；Fcitx 实现核对当前焦点、能力、敏感状态、选区及待替换文本。`replaceSurrounding` 参数是光标左侧后缀和右侧前缀，成功后光标位于 replacement 末尾。`KeyKind::UndoCommit` 与 `KeyBindings::undoCommitEnabled` 接入现有按键链路；原始按键用于区分会被 Fcitx 规范化的 Shift 修饰键。
