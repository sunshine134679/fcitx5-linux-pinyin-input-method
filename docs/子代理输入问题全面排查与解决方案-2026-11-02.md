## 一、结论

**发现两项可独立复现的功能缺陷，当前不能以既有测试全绿认定输入体验已无问题：**

|---|---|---|---|
| Z01 | P1 | 模糊拼音部分候选被错误标记为消费全部输入 | 输入 `zidaili` 后选「之」或「指代」，未提交的 `daili` 或 `li` 被清掉 |

同时确认一组明显的**冷启动词汇覆盖与候选可发现性问题**：全拼「子代理」存在，但本次干净环境最终排第 8；在参考字体与窗口尺寸下位于第二页。若试图分段选「子」，它排第 75、参考分页第十二页。冷启动的 `zdl`、`zdaili`、`zidli` 均没有完整「子代理」。这些事实能够解释用户“打不出来”的感受，不能把深藏后页当作体验正常。

**未发现“子代理完全不能学习”或“学会后重开进程即丢失”的证据。** 正常选择正确的「子/zi」再选「代理」，合成环境中三轮后完整词成为首选；独立进程重开保持，纯简拼 `zdl` 也可首选真实提交。这与 Z01 的模糊候选消费错误、Z02 的混拼缺口是不同路径。

本次没有读取日常个人学习库，因此不把现象直接归因于“用户词库已被污染”，也没有通过清空用户数据取得结果。

## 三、「子代理」究竟在哪一环出问题

下表名次均为从 1 开始；原始日志使用从 0 开始的索引。

| 输入 | 系统原生「子代理」 | 加扩展词典后原生 | 统一 Pipeline | 最终 Provider |
|---|---:|---:|---:|---:|
| `zidaili` | 12 | 12 | 5 | 8 |
| `zi'dai'li` | 12 | 12 | 5 | 8 |
| `zdl` | 无 | 无 | 无 | 无 |
| `zdaili` | 无 | 无 | 无 | 无 |
| `zidli` | 无 | 无 | 无 | 无 |

系统与扩展词典没有「子代理」的显式整词条目，全拼整词由「子＋代理」组合生成。当前干净首选为「自代理」；混排从最佳整句派生「自代」「自」等前缀，使 Pipeline 的第 5 名「子代理」进一步后移至最终第 8 名。不是目标被全拼切分成了错误音节。

分页证据使用生产分页函数、Pango 测量、`Noto Sans CJK SC`、610px 参考宽度及当前参考样式；在此配置下「子代理」为第二页第二项，「子」为第十二页第四项。不同字体、DPI、宽度可能改变物理页，不能把这些页码写成所有用户的固定位置。

冷启动 `zdl` 的原生列表共有 3499 项，目标整词在完整列表内就不存在；「子」位于扩展原生第 943 名，「子代」第 464 名，均在头部 128 项评分预算之外，因此连合理的分段退路也丢失。相反，全拼 `zidaili` 中「子」仍保留，只是最终第 75 名。增加 NBest 至 64/128 的消融没有让冷 `zdl` 产生「子代理」，所以不能把单纯扩大解码宽度当作已验证方案。

### 冷启动改善方案

1. 审阅并补充现代 AI 领域词汇覆盖，优先考虑「子代理」「主代理」及相关留出术语，交由既有召回、证据和排序链路处理，不按文字硬插首位。
2. 在固定总候选预算内为不同消费跨度、高质量替代首字保留有界覆盖，随后统一去重、排序、混排；避免全局原生头 128 项把所有分段退路裁掉。需同时评估最佳整句前缀席位，不能仅给最佳句的首字可见机会。
3. 词库覆盖与候选预算分别验收：隔离用户词典加入中性 `zi'dai'li 子代理 0` 后，全拼成为第 1，`zdaili` 第 3、`zidli` 第 18，但 `zdl` 仍在第 57。**补词可恢复召回，不能保证所有写法都进入首页。**
4. 不建议把评分池直接提高到数千、固定「子」置顶或大幅提高所有学习权重。它们会把召回、排序和性能问题混在一起，也没有解决下面两个正确性缺陷。

对应实现：[原生候选预算](/home/wsl/ModernIME/algorithm/pinyin/src/candidate_pipeline.cpp:28)、[首句前缀混排](/home/wsl/ModernIME/algorithm/pinyin/src/candidate_mixer.cpp:56)、[部分候选尾部追加](/home/wsl/ModernIME/algorithm/pinyin/src/candidate_mixer.cpp:159)。

## 四、Z01 / P1：模糊部分候选吞掉后缀

### 可复现行为

每例使用独立 Provider/Controller，关闭学习以隔离提交行为；选择请求携带当前会话、展示代次和 expected identity，排除了陈旧候选或界面选错位置。

| 原始输入 | 选择项 | 原生格点消费边界 | Provider 标注消费 | Host 实际提交 | 实际剩余 / 正确剩余 |
|---|---|---:|---:|---|---|
| `zidaili` | 子 / `zi` | 2 | 2 | 子 | `daili` / `daili`，正确对照 |
| `zidaili` | 之 / `zhi` | 2 | **7** | 之 | **空** / `daili` |
| `zidaili` | 指代 / `zhi'dai` | 5 | **7** | 指代 | **空** / `li` |

显式隔音符输入 `zi'dai'li` 也存在同类错误：「之」被标为消费全部 9 字节并清空；正确「子」消费 3 字节后保留 `dai'li`。直接选择完整「子代理」消费全长则正常。

### 根因

[CandidatePipeline 原生转换](/home/wsl/ModernIME/algorithm/pinyin/src/candidate_pipeline.cpp:46) 传递文字、完整拼音、分数和来源索引，却没有保留原生格点已经知道的真实消费边界。

[Provider 构造候选](/home/wsl/ModernIME/algorithm/pinyin/src/pinyin_candidate_provider.cpp:1697) 先默认消费 rawInput 全长；后续对低匹配等级候选通过音节字符串前缀关系尝试恢复部分消费。[字符串判定](/home/wsl/ModernIME/algorithm/pinyin/src/pinyin_candidate_provider.cpp:1735) 对 `zhi` 与 `zi` 返回不匹配，不能表达已启用的 Z_ZH 模糊关系。恢复失败后保留全长，再被误分到完整候选。

错误字段继而影响 [CommitEvent 的 partial 判定](/home/wsl/ModernIME/algorithm/pinyin/src/pinyin_candidate_provider.cpp:1084) 及 [选择后输入清理](/home/wsl/ModernIME/algorithm/pinyin/src/pinyin_candidate_provider.cpp:1155)。这是上游事实丢失后下游错误推断造成的输入丢失。

### 解决方案与验收

- 在原生召回时把真实原始输入跨度固化为值，经候选转换、评分、排序、身份和去重传递；不得保存超出寿命的格点指针，或在候选重排后用来源索引错误反查。
- 对纠错、近音变体等来源，若原生解码使用了不同长度或切分的输入，需要把其消费边界显式映射回原始击键。不能无条件把变体偏移直接当作 rawInput 偏移。
- 派生及个人候选继续按自身实际前缀对齐；不能确认跨度时，不得默认为全部消费。保持候选身份、提交文字、partial 标志、学习事件与剩余输入一致。
- 增加 Provider 和真实 Controller 回归：上述三项及显式隔音符、简拼、混拼、纠错来源；断言实际提交、剩余文本、消费跨度和学习事件。保留既有 `zmhuishi` 部分消费契约及所有旧断言。
- 不以关闭 Z_ZH 模糊、隐藏所有模糊部分词或将测试预期改成清空来规避缺陷。

本轮确认的是消费错误；学习开启后错误事件可能影响后续学习，但没有检查用户真实库，不声称已产生持久化污染。主审用新的合成目录独立复现，见 [主审控制器原始输出](/home/wsl/ModernIME/build/子代理输入排查-20261102/主审复现/控制器消费完整.log)。

### 先确认学习本身有效

全新合成库中，通过 Controller 实际选择「子」再选剩余「代理」，没有预置整词或直接调用学习 API 注入：

| 组合内分段训练轮数 | 完整词最终名次 | 参考物理页 / 编号 | 持久整词频次 |
|---:|---:|---|---:|
| 0 | 8 | 2 / 2 | 无 |
| 1 | 7 | 2 / 1 | 1 |
| 2 | 6 | 1 / 6 | 2 |
| 3 | 1 | 1 / 1 | 3 |
| 独立进程重开、提交前 | 1 | 1 / 1 | 3 |

每轮后重置会话并清空周边文本，查询时近期奖励为 0。独立进程中再按数字 1，实际提交完整「子代理」。持久键 `zidaili`、展示拼音 `zi'dai'li` 是既有规范化行为，不是错误键。

跨两个独立组合 `zi→子`、`daili→代理` 也通过；按既有三轮形成门槛，前两轮没有整词记录，第三轮形成频次 3、首选并跨进程保留。留出「子任务」「主代理」「多代理」同样完成两通道三轮及独立进程提交。共 24 轮形成、48 次实际片段提交、8 次独立进程整词提交。

### 真正缺口

在已经学会的库上开启新进程：

| 输入 | 目标是否出现 | 结果 |
|---|---|---|
| `zdl` | 是 | 第 1 / 首页，真实提交正确、完整消费 3 字节 |
| `zi'dai'li` | 是 | 第 1，消费 9 字节 |
| `zdaili` | **否** | 完整最终列表缺失，个人索引也返回空 |
| `zidli` | **否** | 完整最终列表缺失，个人索引也返回空 |

主审只读补证得到：整词规范键 `zidaili`、频次 5；`zdl` 的 recall 和 initialsMatch 成功；两个混拼的 recall、matchPriority、initialsMatch 均失败。这不是学习不落盘、词频不足或目标藏在后页。仅证实这两种典型写法的缺口，不外推为所有混拼均失效。

### 根因与方案

- [个人索引构建](/home/wsl/ModernIME/core/src/learning_snapshot.cpp:303) 与 [查询](/home/wsl/ModernIME/core/src/learning_snapshot.cpp:1335) 主要覆盖完整规范键、纯声母及规范拼音字面前缀；`zdaili` / `zidli` 不属于这三种关系。
- [initialsMatch](/home/wsl/ModernIME/core/src/pinyin_match.cpp:435) 每音节消费声母或 zh/ch/sh，不接受逐音节全拼与声母混合，因而混拼也没有匹配资格。
- [个人候选补充](/home/wsl/ModernIME/algorithm/pinyin/src/candidate_pipeline.cpp:166) 依赖上述召回，缺失目标不会自动进入统一排序；单纯加权无效。

建议使用有界的逐音节匹配：以现有索引或受控的新索引获取候选，对每个音节允许完整拼写或合法声母，并对有歧义切分进行有界求解。**召回入口与匹配等级必须一起修复。** 保留精确全拼、可信简拼及中英仲裁边界；只保留一份规范学习事实，不为每种 raw 写法复制持久记录，不全扫 200,000 词，不预生成指数级混拼组合。

验收至少包含：全拼真实学会→全拼/纯简拼/两种混拼/隔音符均召回并实际提交；独立进程；错误近似串不能误匹配；清空与屏蔽后各写法一致失效；禁学、敏感输入、消费身份和剩余文本；200,000 容量和原生性能门限保持。也须覆盖既有 AP01 单音节隔离，避免多音节修复重新扩大单字晋升范围。

原始及主审补证：[分段学习与混拼详细报告](/home/wsl/ModernIME/build/子代理输入排查-20261102/learning/分段学习与简混拼召回复核报告.md)、[主审个人索引输出](/home/wsl/ModernIME/build/子代理输入排查-20261102/主审复现/个人召回索引完整.log)。
