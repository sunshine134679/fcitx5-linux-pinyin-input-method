## 2. W1 / P1：新增 UI 验收使原无头配置契约失败

**位置：** `tests/ui/ui_addon_test.cpp:63–65`，以及 `tests/configuration_contract_test.sh` 对 UI 测试的两次无条件调用。配置契约在 `tests/CMakeLists.txt:18–20` 注册为普通测试。

`gtk_init_check()` 的返回值被忽略。无 DISPLAY/WAYLAND_DISPLAY 时，生产 UI 正确处于不可用状态，但测试仍要求点击成功，以业务断言失败退出。总控脚本因此也失败，并非明确的 GTK 环境跳过。

同一提交、相同测试与私有数据目录下的独立对照：

| 环境 | 完整配置契约 | 六项定向 CTest |
|---|---|---|
| 显式 `DISPLAY=:0 GDK_BACKEND=x11` | exit 0，7/7 | **6/6 Passed，14.93 秒** |
| 无显示 / 默认无显示环境 | exit 1 | **5 Passed，1 Failed，exit 8** |

失败点：`UI addon test failed: handleButtonPress should return true`。前面的 settings/layout/adapter/runtime 测试均已通过，失败由新增 GUI 必需调用引入。这会影响无显示的完整 CTest 和安装生命周期验证，不能通过统一向 CI 填一个不存在的 DISPLAY 修复。

**完成标准：**

- UI 测试在 GTK 不可用时明确返回约定 skip 码，例如 77；有显示环境继续严格执行原断言。
- 将真实 GTK 场景作为独立测试注册，配置显示资源锁、超时和 skip 语义；非 UI 配置/存储/路径契约在无显示环境仍实际执行。
- 总控脚本必须识别场景结果：无显示不能宣称真实 UI 已通过或完整 7/7；不能因 shell `set -e` 把合法 skip 当失败；也不能无条件 `|| true`。
- 必需产物真的缺失仍应失败。显示不可用与产物未构建是不同事实。
- 协调者将新增 GTK 用例纳入对应 profile 的必需测试及合法跳过规则；桌面 profile 不接受该项跳过。

无需修改生产 UI 的无显示行为，也无需修改 install.sh 以绕过测试。

## 3. W2 / 既有验收缺口：路径矩阵仍绕过环境自动选址

**位置：** `tests/configuration_contract_test.sh:374–410`，`tests/core/db_fixture_helper.cpp` 的显式 path 参数。

当前过程是测试先计算 `expected_data_dir`，把其中的 SQLite/LMDB **绝对路径**传给 helper；随后给 guard 同时显式传入 `--data-dir expected` 和 `--config-dir expected`。helper 的两次 subprocess 甚至没有传递该场景组装的 `env`。因此这段能证明真实数据库与显式保护目录有效，不能证明运行时从 HOME/XDG/MODERNIME 环境实际选择了预期目录。

独立反证仅修改忽略目录中的测试脚本副本：在 `home_default`、`xdg_override` 两种场景计算预期根前，把其运行环境的 XDG_CONFIG_HOME/XDG_DATA_HOME 改成其他私有目录，保持预期根不变。

```text
[MUTANT] supplied runtime env differs from expected directories: home_default .../deliberately_wrong_data_root
[MUTANT] supplied runtime env differs from expected directories: xdg_override .../deliberately_wrong_data_root
exit=0
All T14 Configuration Contracts PASSED (7/7)
```

这证明矩阵没有观察环境与实际选址的关系；不是证明当前生产路径实现错误。上轮 V2 已明确要求“观察生产选址/实际记录，比较 guard 保护根”，本项仍属该要求。

**最小收尾：**

- 保留真实 LearningStore 夹具，增加由环境解析路径的测试入口；复用生产启动环境构造与 `SettingsPaths::fromEnvironment`，不要在测试里再写一份路径优先级算法。
- 每种场景以 `env=env` 启动真正消费该环境的进程，输出/观察其实际解析路径，然后在这个路径写入提交。预期根只用于外部断言，不能作为实际路径参数喂回被测入口。
- 对 managed 冲突场景，实际经过生产的 MODERNIME 到有效 XDG 映射，再进入 core 路径解析；只调用 core 时直接传原始冲突 XDG，不能冒充已经测试启动映射。
- guard 自动选址校验/备份至少有一次不带路径覆盖参数，并核对其保护根与实际写库根一致。
- 关闭重开后检查实际标记词条；备份也检查同一标记事实，而不只是文件存在。全部目录保持私有，实际宿主库不进入测试。
- 错误环境/错误生产解析的负向对照应确定性失败。修正验收报告，把显式目录数据库验证与自动选址分别说明。

不要求修改 T17 已接管的脚本、用户数据格式或路径生产默认值。
