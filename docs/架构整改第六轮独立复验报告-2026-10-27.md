## 二、R6-01：整目录回滚覆盖或删除独立用户新数据

**等级：P1。触发条件：显式目标前缀与用户数据目录重合，迁移期间发生独立用户写入，随后包步骤失败。不是默认 `/usr` 目标必现。**

代码位置：

- [默认用户数据目录](/home/wsl/ModernIME/scripts/modernime-migrate-channel:204) 默认形成 `$HOME/.local/share/modernime`。
- [目标备份范围](/home/wsl/ModernIME/scripts/modernime-migrate-channel:329) 包含整个目标 `share/modernime`，[备份复制](/home/wsl/ModernIME/scripts/modernime-migrate-channel:347) 复制整目录。
- [清除新增路径](/home/wsl/ModernIME/scripts/modernime-migrate-channel:405) 只判断路径是否出现在迁移前清单；`:407` 删除所有未出现的路径，没有确认是否由本次包事务创建。
- [旧目标整体回放](/home/wsl/ModernIME/scripts/modernime-migrate-channel:450) 将既存文件内容也一并退回旧值。

本轮使用临时 HOME，将支持的 `--target-prefix` 显式设为该 HOME 下的 `.local`，保留默认用户数据目录。源安装在另一个临时前缀。数据目录迁移前有不属于程序安装清单的自有文件 `owned-user-data=old-user-fact`。

假包步骤内启动独立 Python 写入进程，将该文件保存为 `new-user-fact`，新建 `user-dictionary.txt` 测试文件，并写出带真实 PID 和写入内容的回执。随后假包返回失败；包回滚命令为 `true`，没有自行删除这两个文件。全程没有执行真实包管理命令或操作日常用户数据。

仓库入口和真实生成包入口的结果一致，主审另行独立重跑也一致：

```text
独立进程写入回执：owned=new-user-fact，且新词典文件已写入
product_exit=1
source_value=source-original
owned_value=old-user-fact
new_dictionary_exists=false
remaining_transactions=[]
```

实际损失是已完成的新用户写入被回拨，新文件被删除。源安装恢复成功不代表用户新数据受到保护。这里验证文件保存事实，不依赖词典解析器、GUI 或真实输入法服务。

三类对照排除了泛化结论：

1. 第五轮保存的完整安装源码快照，在相同路径重合场景中保留新数据和新文件。
2. 当前源码只将目标放到用户数据目录之外，仓库及生成入口均保留新数据和新文件。
3. 当前源码中源与目标相同、但没有独立新写入的普通失败场景，既存安装和测试文件正确恢复。

预备份时没有已知词典或学习数据库，新词典测试文件在迁移中才出现，避免把已有 data-guard 的回放与本次新增目录清理混淆。本次直接回归来自扩大了目标恢复范围。

**整改要求：** 以程序 payload 清单和本次事务实际变更归属确定恢复、删除范围；用户数据和配置不能因处在同一目录树就被纳入通用程序回滚。迁移前不存在，不等于本次包步骤创建。既要保留第五轮已修复的旧插件内容、权限、目录和链接恢复能力，也要保留独立用户新写入。不能通过禁止原本支持的隔离前缀测试或回滚整个用户数据目录来使反例通过。

## 三、R6-02：目标恢复 I/O 失败后仍销毁恢复材料

**等级：P2。触发条件：包步骤失败后，目标前态恢复复制发生 I/O 错误。**

[目标恢复复制](/home/wsl/ModernIME/scripts/modernime-migrate-channel:450) 丢弃 stderr，并用 `|| true` 吞掉失败；[事务目录清理](/home/wsl/ModernIME/scripts/modernime-migrate-channel:475) 随后无条件删除 `$temp_work`，其中包含目标原文件备份。

隔离夹具先创建内容为 `target-original` 的目标插件；假包把它改成 `target-overwritten` 后失败。临时 PATH 中的 `cp` 包装器只让来源为 `*/target_backup/.` 的目标恢复复制返回 74，其余复制全部交给真实 `/usr/bin/cp`。源备份、源恢复与故障命中均有原始日志。

仓库、生成入口及主审重跑均观察到：

```text
product_exit=1
injection_hit=true
source_value=source-original
target_value=target-overwritten
remaining_transactions=[]
```

这里没有产品错误返回 0：产品非零来自前面的包步骤失败。stderr 中 `Original installation restored` 指源安装，源确实已恢复，不能凭这句话认定目标恢复成功或单独认定文案虚假。独立成立的问题是目标仍被改写，恢复错误未报告，且可恢复原内容的事务备份已被删除。

新探针对该场景还附带检查了上述文案；该附加判断不用于本报告定性。即使忽略文案，目标内容和 `remaining_transactions=[]` 已直接证明恢复材料未保留。原探针与原始结果保持不变。

**整改要求：** 汇总目标恢复步骤的真实结果。发生复制、清理或回滚失败时，明确报告未完成的恢复对象，保留备份与事务记录，并输出可定位的恢复路径。只有相应恢复完成后才能删除对应材料。不要求系统保证 I/O 永不失败，要求失败后仍可诊断和恢复。
