基线 `ab0a1d5`；用户要求缩短交付周期，本批只做直接相关验证，完整门禁集中在集成发布。上一批候选显示身份已交付；总升级继续。

## 证据与方案

隔离 HOME/DBus 的 GNOME 46.2 原生 Wayland 会话中，固定 `-u modernime-ui` 选择自绘 GTK 窗口，出现无 parent 的 popup 无法映射；去掉强制参数后，实际 Fcitx5 UI 管理器可以选择 Kimpanel。初始探针遗漏系统 DBus 插件的 keyboard 依赖，已修正，最终对照为 forced退出1/auto退出0。

采用 Fcitx5 自身的 UI 发现与可用性回退，不新增路由服务：ModernIME UI 设置优先级100，在X11继续使用自绘窗口；原生Wayland或Wayland桌面中的XWayland进程不宣称自身窗口可定位，返回不可用，交由Shell Kimpanel或宿主支持的UI。各安装、自启和设置重启入口统一去掉 `-u modernime-ui`。不修改排序、学习、用户数据及扩展所有权。

Wayland应用可请求客户端候选UI，Fcitx5按既有协议优先交给应用；其余上下文使用可用的桌面面板。Shell候选外观由GNOME扩展控制；自绘候选的字号/主题配置不会自动变成Shell设置。扩展不可用时不能保证GNOME原生候选弹窗，仅遵循Fcitx5现有回退。后续设置页须准确显示这个区别，不能宣称全部Wayland应用已验收。

## 实施与验收

1. 更新启动/重启回归，证明不再强制UI；保留失败、环境传递与用户数据保护断言。
2. 设置UI优先级和实际后端可用性判断，移除所有默认入口的强制参数，修正文档。
3. 增量构建UI及设置运行控制器；运行直接相关的UI、runtime、session/init/install脚本回归。
4. 在独立GNOME原生Wayland使用仓库扩展验证Shell候选数据及选择回传；X11验证仍选ModernIME。测试副本使用专用UUID防止Shell在线更新替换被测扩展，生产文件不变。
5. 记录结果并提交本地回退点；不重启日常输入法、不运行完整生命周期复跑。

## 本批结果

- 增量构建 `modernime_ui`、`modernime_ui_addon_tests`、`modernime_runtime_controller_tests` 和 `modernime-settings` 成功。

- 真实GNOME 46.2无屏Wayland、系统Fcitx5 5.1.7、仓库扩展的隔离副本：自动选择 `kimpanel`，面板实际可见，显示“你好/世界”，调用Shell候选控件的选择回调后，Fcitx上下文恰好提交一次“你好”。X11实际路由仍为 `modernime-ui`。手动强制旧 `-u modernime-ui` 在Wayland仍不可用，不作为推荐启动方式。
- 实际原生GTK3输入：GdkWaylandDisplay、输入框真实聚焦、Fcitx状态2/modernime；由测试合成器的虚拟键盘输入 `nihao` 和空格，最终 `Gtk.Entry` 文本为“你好”。这验证真实GTK IM模块、DBus前端、生产引擎与上屏；没有假造中文提交或直接修改输入框内容。Shell通道点击回传与GTK键盘提交是两个独立场景，不混为同一UI路径。
