## 2. 仍然阻断验收的问题

### S1 / P0：旧请求只被拒绝一次，页面没有持久失效（已复现）

位置：`algorithm/pinyin/src/pinyin_candidate_provider.cpp:979–1002,1038–1042,1178–1184,1288–1294`。

`checkResourceChanges()` 会消费新世代/状态，更新 observed 字段，但选择、取字、删除入口发现 changed 后只返回失败，不使 `page_` 的generation失效，也不保留dirty标志。下次检查会认为资源未改变，而旧页仍在。

确定复现：保存clear前的page/request → 暂停worker并clear → 共享资源观察Reloading → 旧请求第一次拒绝 → 恢复worker并flush至Ready → 不调用page或append，重复原请求两次 → 第二次接受旧请求。上述probe有完整输出。相同设计也影响字典重载后多次旧动作。

为什么现有测试漏掉：新增 A05 用假Provider替换generation，只验证假Provider的旧generation检查，没有经过真实Provider的资源观察消费过程；既有字典测试在选择前又调用page/append，已提前刷新页面。

目标：将“资源已观察”和“当前页已重建/授权”区分。观察变化立即撤销旧页授权，直到显式重建才发布新generation；或者在拒绝旧动作时安全重建并永久作废原generation。不能把原请求改成选择新页同索引。所有动作共享这条不变量。

验收：真实Provider/Controller上，clear和字典reload后，不先page/append，连续重复旧select/取字/删除都拒绝；插入Ready事件分发前后仍拒绝；旧候选零上屏、零消费、零学习；新页新请求正常。测试必须覆盖多个调用，不能只断言第一次失败。

### S2 / P0：Ready回调先解引用this再检查alive，插件退出时可能访问已销毁dispatcher（静态确认）

位置：`adapter/fcitx5/src/inputmethod.cpp:507–515,795–813`；成员顺序：`adapter/fcitx5/include/modernime/fcitx5/fcitx_engine.h:378–387`。

后台回调保存 `[this, alive]`，先执行 `dispatcher_.schedule(...)`，alive只在被调度的内层lambda检查。析构只将alive设false并detach，没有撤销并等待在途Worker回调。成员按声明逆序析构，dispatcher早于resources；Writer完成重载或资源销毁期间仍可能调用保存的外层回调。此时尚未检查alive就已访问销毁中的或已销毁的dispatcher。

仅将alive改成atomic或在外层先判断一次不能解决“检查后析构”的竞态。需明确通知端点所有权、取消与在途回调收束顺序，使插件析构开始后不能再调用其成员。已经排入事件循环的闭包也必须安全作废。

同一回调只取mostRecentInputContext并检查输入法名/非空preedit，没有捕获并验证通知世代、会话标识和当前focus；这与报告宣称的失焦、敏感切换、二次clear完整验收不符，需在真实通知路径验证并按结果修正。

验收：对真实Ready→dispatcher→Controller/Host发布路径设置栅栏，分别在“后台已复制回调、尚未schedule”和“已schedule、尚未dispatch”时销毁插件/会话；ASAN无悬空访问，后台可正常结束。覆盖失焦、敏感切换、二次clear、换会话及重复Ready。不要只测试Controller.reset或setSensitive。

### S3 / P1：Reloading时标点自动提交原拼音，违反已确定的过渡契约（代码和现有测试确认）

位置：`adapter/fcitx5/src/engine.cpp:612–622,934–939`；`tests/adapter/candidate_selection_test.cpp:527–531`。

None被识别为“没有真实候选”后，标点路径调用commitRawPreedit，自动上屏组合。当前新测试还明确要求它提交 `test` 再提交逗号，因此测试通过恰好证明了这项未经授权的行为变化。

原计划T11明确：“只有用户显式Enter才保留既有原文提交能力”，并要求过渡期保留组合、不悄悄自动上屏。避免提交占位文案不应扩大为标点自动提交原拼音。

目标：None/未获授权视图下，标点不得隐式提交preedit或占位项；保留组合/光标，按原契约处理消费，显式Enter原文能力保留。不改正常Ready候选的标点行为。

验收：标点开关开/关、全角/半角、引号/括号，None页面均零隐式原文上屏；组合保持。使用真实Provider+Controller检查Host提交与学习队列。修正与契约相反的新测试，不改原有正常行为断言。
