## 二、第五轮缺陷物理根因修复详情

### 1. R5-01 / R4-02 · P1：目标对象完整物理前态备份与失败恢复
- **缺陷现象**：安装通道迁移脚本 `scripts/modernime-migrate-channel` 建立的 `target-preexisting.txt` 仅记录了文件路径字符串，未保存文件内容、权限掩码（0751 等）、对象类型（符号链接与其指向的目标文本）或目录内文件。当包管理命令部分写入后失败时，跳过同名路径仅能遗留下被改写后的脏对象，无法恢复目标前态，且事务新建文件在已存在的 `share/modernime` 目录下残留。
- **根因分析**：清单保护停留在“路径名跳过”，缺乏对受控目标（`bin/`, `lib/`, `share/fcitx5/`, `share/modernime`, `share/doc/modernime` 等）的物理前态快照及目录内差量变更感知。
- **治理实施**：
  1. 在 `scripts/modernime-migrate-channel` 准备阶段，建立独立的物理备份目录 `$temp_work/target_backup`；
  2. 扫描受控目标候选列表：凡目标前缀下既存的文件、软链接或目录，使用 `cp -a` 完整保留其数据、0751 权限位、mtime 与符号链接文本；
  3. 若目标目录（如 `share/modernime`）已存在，递归记录其下所有既有文件到清单；若其符号链接指向目标前缀内的实体，一并备份实体前态；
  4. 在 `cleanup_target_prefix_files` 中，对既存目录（`share/modernime`）进行深度优先扫描（`find ... -depth`），精准撤销本次事务新增的文件与子目录，保留既有条目（如 `keep.dat`）；
  5. 在 `restore_original_channel` 失败回滚中，在执行完包卸载与新增文件清理后，立即执行：
     ```bash
     if [[ -d "$target_backup_dir" ]]; then
         cp -a --remove-destination -- "$target_backup_dir/." "$target_prefix/" 2>/dev/null || true
     fi
     ```
     以 `--remove-destination` 无损还原覆盖/删除的所有既存目标对象（包括恢复文件内容、0751 权限、软链接文本，以及被外部包回滚命令意外删除的既存文件）。
- **验证结论**：
  - 运行 `python3 build/architecture-fifth-acceptance-20261027/installer/第五轮目标基线与卸载探针.py`：仓库入口与生成包入口下的 6 类模式（`unchanged_file`, `overwrite_file`, `overwrite_directory`, `replace_symlink`, `rollback_removes_preexisting`, `transaction_created`）及 8 类卸载参数转发**全部 20/20 PASS（exit 0）**；
  - 第四轮补验 `第四轮定向补验.py` 12/12 PASS；生命周期测试 `install_lifecycle_prep_test.sh` 81/81 PASS。

### 2. R5-02 / R4-03 · P2：比较完整持久事实判定删除冲突（覆盖 negative_feedback 等所有持久字段）
- **缺陷现象**：在 `PersonalEngine::FlushToLmdb` 中做 `replace_all` 替换与剪枝时，先前的 `BaselineFact` 仅比较了 `hit_count`, `last_selected_ms`, `suppressed` 三项。当旧引擎计算空替换、取得写事务前，若另一并发实例调用 `RecordNegativeFeedback` 提交了负反馈（仅更新 `negative_feedback`，不改变前述三字段），旧引擎误将新提交的事实当作旧事实直接删除，导致磁盘持久反馈丢失。
- **根因分析**：删除冲突判定依赖不完全字段集合，未能以完整持久事实的等价性来确认删除权限。
- **治理实施**：
  1. 在 `core/include/modernime/core/personal_engine.h` 中，将 `WordMeta` 结构体（常驻内存及 LMDB 底层零拷贝序列化的 29 字节完整结构）作为基线事实标准，定义严格的等价与不等价比较运算符：
     ```cpp
     inline bool operator==(const WordMeta &a, const WordMeta &b) noexcept {
         return a.last_used_timestamp == b.last_used_timestamp &&
                a.hit_count == b.hit_count &&
                a.base_weight == b.base_weight &&
                a.text_bytes_len == b.text_bytes_len &&
                a.context_before_len == b.context_before_len &&
                a.context_after_len == b.context_after_len &&
                a.negative_feedback == b.negative_feedback &&
                a.suppressed == b.suppressed &&
                a.last_selected_ms == b.last_selected_ms;
     }
     inline bool operator!=(const WordMeta &a, const WordMeta &b) noexcept {
         return !(a == b);
     }
     using BaselineFact = WordMeta;
     ```
  2. 将 `baseline_entries_` 升级为 `std::unordered_map<std::string, WordMeta>`，在 `FlushToLmdb`、`Clear`、`LoadDbFromLmdb` 中保存完整的 `WordMeta` 事实；
  3. 在 `FlushToLmdb` 的 `replace_all` 扫描中：
     ```cpp
     if (replace_all && in_baseline && it == variants.end()) {
         const bool disk_updated = (view.meta != it_base->second);
         if (disk_updated) {
             // 磁盘上存在未曾见过的外部持久新事实（如并发 negative_feedback、频次更新、时间戳更新等），严格保留
             StoredVariant new_var;
             ...
             variants.push_back(std::move(new_var));
         } else {
             // 磁盘事实与读取基线完全一致，未发生任何外部写并发，正常执行删除
         }
     }
     ```
  4. 既防止了对并发提交事实的误删，又避免了无条件 union 导致合法删除无法生效。
- **验证结论**：编译并运行第五轮边界探针中的 `concurrent_negative_fact`，输出：
  `concurrent_negative_fact seed=1 external_committed=1 before_delete_feedback=1 replace=1 after_delete_feedback=1 total=1 ok=1`，断言完全通过。

### 3. R5-03 / R4-04 · P2：SQLite 事务内捕获版本，消除事务后吞并外部提交窗口
- **缺陷现象**：在 `core/src/learning_store.cpp` 中，写事务 `recordBatch` 与读事务 `readState` 均在 `COMMIT;` 之后调用 `lastDataVersion_ = dataVersion();`。SQLite 的 `PRAGMA data_version;` 机制在当前连接提交自身事务时不会递增，只有外部连接提交才会递增。若外部连接恰在 `COMMIT;` 之后、版本采样之前提交，该后置版本采样会直接将外部提交的新版本赋予 `lastDataVersion_`，而该批数据根本未被当前内存快照吸收；随后写事务检测 `curVer == lastDataVersion_` 误判为无外部变更，导致本地视图长期漏看外部新词与屏蔽事实。
- **根因分析**：版本记录与事实吸收边界不一致，在事务提交后单独采样外部版本，破坏了单调性与因果链。
- **治理实施**：
  1. **`readState()` 读事务**：在 `BEGIN;` 之后、读取快照前捕获读版本 `const auto readVer = dataVersion();`。事务提交后将 `lastDataVersion_ = readVer;`，确保记录的版本与实际读入内存的数据事实严格对齐；
  2. **`recordBatch()` 写事务**：在 `BEGIN IMMEDIATE;` 内部捕获 `const auto curVer = dataVersion();` 并判定 `extChanged = (lastDataVersion_ != 0 && curVer != lastDataVersion_);`。完全移除 `COMMIT;` 之后的无保护 `dataVersion()` 调用。
     - 若 `!extChanged`（无并发外部提交），事务提交后维持 `lastDataVersion_ = curVer;`；
     - 若 `extChanged == true`，写事务自身不推进 `lastDataVersion_`，交由 `LearningWriter` 在检测到 `externalChanged` 后调用 `readState()`，在读入事实后原子更新 `lastDataVersion_`；
     - 任何在事务开始或提交之后发生的外部提交，都不会被写事务吞并，将在下一批写入或显式读取中被 100% 可靠捕获。
- **验证结论**：第五轮直接边界探针重新执行：
  - `sqlite_external_after_write_commit ... external_seen=1 suppressed=1 ok=1`
  - `sqlite_external_after_read_commit ... external_seen=1 suppressed=1 ok=1`
  - `lmdb_external_after_write_commit ... external_seen=1 suppressed=1 ok=1`
  存储组直接边界探针 `assertion_failures=0`（全部通过，exit 0）。

## 五、主审意见与交接规范校准

针对第五轮复验报告第五节指出的口径问题，本轮统一规范如下：

1. **构建选项口径**：当前本地构建目录 `build/` 遵从 CMake 缺省配置，但在运行门禁脚本（`verify_package_repo_gate.sh`、`verify_fresh_clone.sh`、`configuration_contract_test.sh`）时均显式指定并验证了 `MODERNIME_REQUIRE_FULL_TESTS=ON`；不把本地单个缓存的配置状态等同于全仓语义。
2. **工作树状态**：本轮明确所有修复均基于工作树当前未提交源码进行，改动文件清晰约束在：
   - `scripts/modernime-migrate-channel`
   - `core/include/modernime/core/personal_engine.h`
   - `core/src/personal_engine.cpp`
   - `core/src/learning_store.cpp`
3. **并发同步机制**：`MaterializedCache` 的初始化由 `std::once_flag` 与 `std::call_once` 提供标准线程安全的懒加载物化，写路径采用原子替换 `std::shared_ptr` 的读写分离设计；准确表述为“读路径无锁物化共享与原子替换”。
4. **HeartbeatMonitor 析构边界**：显式析构函数针对正常作用域退出、RAII 生命周期和 C++ 异常展开提供清理保障；断言与致命信号退出机制依操作系统原生行为处理。
5. **门限一致性**：坚持 200,000 容量规格与 5ms P99 / 30ms Max 严格门限，实测 P99 221.59us 与 Max 720.76us，全量数据可信透明。
