## 3. 模块与候选链路的负责人

依赖由 CMake 目标、公共头文件和实际调用共同决定，不能只查目录名。`core` 不依赖算法实现、Fcitx5、GTK 或界面；算法依赖核心模型/契约，adapter 与 UI 各自接入宿主；settings 使用业务门面及明确的持久化/运行时接口。

| 阶段或状态 | 当前负责人和入口 | 后续扩展应遵守 |
|---|---|---|
| 宿主事件、敏感能力、上下文事实 | `adapter/fcitx5/src/inputmethod.cpp` | 只采集获准的当前上下文，不增加宿主外的输入采集 |
| 组合会话、按键、提交与失效 | `ModernIMEController`，`adapter/fcitx5/src/engine.cpp` | 管会话和协议，不另建排序、存储或学习政策 |
| LibIME 会话与一次候选请求 | `algorithm/pinyin/src/pinyin_candidate_provider.cpp` | 作为协调者，保持清晰阶段，不让新功能都堆进 Provider |
| 召回、匹配和来源特征 | `candidate_pipeline.cpp`、`candidate_features.cpp`、`core/src/pinyin_match.cpp` 等现有策略 | 新来源提供证据，不自行获取固定高位或学习资格 |
| 组内排序及部分词自身证据 | `CandidateRanker`、`candidate_prefixes.cpp` | 父整句证据不能冒充前缀自身学习，比较器保持严格弱序 |
| 多粒度席位与最终组合 | `candidate_mixer.cpp`、`candidate_composition.cpp::composeCandidates` | 排序、混排分别在各自阶段改变顺序；最终输出后不得追加隐蔽插位政策 |
| 分页、布局及绘制 | `ui/fcitx5/src/candidate_pagination.cpp`、`candidate_bar_layout.cpp` 等 | 只把既定有序序列分成物理页，不重新决定词语优先级 |
| 学习是否记录 | `core/src/learning_policy.cpp::decideCommitLearning` | 各调用方复用同一政策，不在按键、导入或重载分支复制近似规则 |
| 乐观学习、写队列、清空协调 | `core/src/learning_writer.cpp` | 输入侧发布小范围新快照，后台负责持久化与重建 |
| 事务、数据格式、容量与后端 | `LearningStore`、`PersonalEngine`、`LmdbEnvironment` | 门面语义一致，后端职责与已明确的剪枝差异保留 |
| 配置读写事实 | `SettingsStore`，`core/src/settings.cpp` | 同次读取的内容、hash、stamp 同源，界面编辑值不是已应用事实 |
| 设置页面操作 | `tools/settings/pages/`、`DataController` | 页面管理交互和失效，不在 GTK 回调内直接承担慢 I/O |
| 包事务槽位、进程执行、包政策 | `package_operation_state.cpp`、`process_runner.cpp`、`package_policy.cpp` | 状态所有权、执行机制、纯政策分开；页面 busy 不是事务锁 |
| 设置页解析与导航 | `page_registry.cpp::parseSettingsPage`、`SettingsWindow::show` | CLI、DBus 与窗口复用同一解析和路由 |

## 4. 候选身份、顺序和选择必须对齐

1. 候选语义身份包含文本、规范拼音/英文完整键、提交角色和原始输入消费范围。来源证据可合并，不同消费范围或读音不能仅按显示文本去重。
2. `CandidateSource` 与 `CommitCandidateRole` 不可互换。释义、命令、原文及可学习词条使用其现有政策，不能靠改来源枚举绕过学习限制。
3. `sourceIndex` 是来源位置，不是最终显示下标。`CandidateSelectionRequest` 的会话、展示代次、全局位置和 expected identity 必须匹配；数字键、鼠标和分页共用这套选择含义。
4. 展示代次、布局代次与清空世代各有用途。字体或宽度热载使旧几何失效，不得拿旧坐标/旧下标选中新列表里的其他词。
5. `CandidateSource::None` 为无提交语义的占位来源，不能选词、取字、删除、反馈或学习；回车/标点原文契约通过现有提交路径处理，不能把占位提示上屏或落盘。
6. 字号、主题、注释、省略和页面宽度只改变几何/展示，不改变候选身份、排序或消费。前缀只消耗对应原始击键，不能误吞剩余拼音。
7. 学习验收追踪“确认选择→最终全局位置→物理页面→真实提交与剩余输入→持久召回”，不能仅证明词频/分数增长。

## 5. 学习、隐私与清空世代

- 敏感/禁学判断必须发生在修改学习事件、造词跟踪、近期意图等状态之前。新来源和反馈不能绕过同一边界；不把用户真实密码或聊天上下文写进测试、日志、截图或诊断。
- 保留差量学习、核心默认词保护及已定义例外。Raw、English、Chinese、Command 等角色按纯政策决策，不以“一律跳过 Raw”之类捷径改变正常/Reloading 的行为。
- Provider 的近期意图是有界会话状态，不跨 Provider/敏感边界共享，不冒充重启后持久偏好；不同衰减参数不盲目统一。
- `resetRevision` 是用户清空世代，`snapshotVersion_` 是进程内乐观发布版本，schema 版本表示数据格式；三者不合并，也不拿显示代次充当持久化去重 ID。
- 后台读取、发布前再次核对清空事实。二次 clear 后拒收旧结果，合法的新世代事实不能随失败重试被静默丢掉；外部 clear 不依赖 UI 先刷新才能生效。
- `Reloading` 不代表空库已就绪，失败不得伪造 Ready。PendingCommit 按正常政策恢复决策；`flush()` 和销毁在永久读失败时有界返回/退出，不能永远等 Ready。
- 不可用或 Reloading 时的待持久化队列受当前 100 条上限约束，按现有政策保留较新事实。必须说明这是有界降级：不保证无限离线输入全部留存，不影响已持久记录。
- Ready 通知由宿主事件循环安全刷新活动会话；注销、失焦、敏感、再 clear 和销毁使旧通知失效。不能从 Worker 直接操作 Fcitx5/GTK。

## 6. 不可变快照与输入热路径

- 已交给读者的 `LearningSnapshot` 及其缓存不可被后续写入改变；COW/分片更新不是允许任意整库复制的借口。当前 512 分片属于实现，不要求永远固定；替换必须保住不变性、首次调用和容量回归。
- 输入路径不承担全库加载、序列化、写盘或大量快照析构。异步启学后第一笔提交和下一键不 join 尚未完成的全库构造。
- 空快照共享、retired snapshots 后台释放及发布竞争处理不能因“去掉缓存/简化生命周期”退回输入线程的大对象分配或回收。
- 缓存只保存可复用结果，不成为第二套可变学习事实。首次物化、未命中、清空、并发发布和旧快照读者均需验证。
- 保持默认 200,000 条能力。`LearningStore` 的容量门面与独立 `PersonalEngine` 的默认剪枝目标不相同，不得为了基准统一成 80% 或降低容量。
- 性能测量包含所声明操作的完整生命周期，尤其快照释放；不以漏计析构、计时外剪枝/扩容、跳过持久化制造低延迟。

## 7. LMDB 资源、锁和紧凑格式

主要入口：`core/src/lmdb_environment.*`、`core/src/personal_engine.cpp`、`tests/core/lmdb_lifecycle_test.cpp`。

1. 同进程同规范路径复用受登记管理的环境。普通事务持共享生命周期门，关闭、升级和扩容持独占门；共享门不是写互斥锁，不能代替事务与既有写同步。
2. 缓存 revision 只读事务属于 `LmdbEnvironment`，不得搬回 `PersonalEngine` 等更长寿命的调用者。在 close、RO→RW 重建、map resize 前释放缓存事务，之后按新环境重建。
3. `readResetRevision()` 当前按 `lifecycle_gate → revision_mutex_` 保护 renew/read/reset；修改时列出所有锁及析构隐式取锁边，不能只审查显式 lock。
4. `OpenLmdb()` 替换环境时，将旧 shared_ptr 移到局部，并在新环境门和引擎锁作用域之外释放。不得在持有 `lmdb_mutex_` 时用赋值/析构触发旧环境 close。
5. 不能持共享门直接升级为独占门；MAP_FULL 重试要退出原事务/门后走受控扩容。最后持有者关闭，单个引擎不得主动关闭其他引擎仍持有的共享环境。
6. LMDB mmap 值视图只在相应事务/环境有效期内使用，不跨 abort/reset/close 留悬空引用；Packed `WordMeta` 字段避免绑定要求对齐的引用，不能为了少一次复制恢复未对齐访问。

已发生并修复的反例必须记住：缓存事务跨环境造成 SIGSEGV/STALE_TXN；shared_ptr 赋值隐式析构造成 TSAN 锁序反转。逻辑测试全过但检测器退出非零仍是失败，不能略过。

## 8. 子进程、包事务与在线更新

- Query 与 PackageTransaction 是两种契约。查询有单调总期限、双流有界输出及继承 FD 回归；包事务等待超时只转 Continuing，不能因 GUI 退出或计时到期杀掉真实包管理器。
- `operationId` 绑定槽位、完成结果及采集器；旧 ID 不结束新操作。同步返回不污染后台未消费结果队列，未消费结果上限当前为 8，满额背压，不静默丢旧结果。
- `NotStarted` 必须有目标确未启动的证据。可能启动却未握手、采集器异常或状态不明时保持 Unknown/Uncertain，不假报完成、释放槽位或自动重复执行。
- stdout/stderr 的驻留缓冲、返回尾部、诊断文件及状态文件分别受预算约束；包事务尾部通常为每流 64KiB，诊断每流 1MiB，状态文件 4KiB。累计排空字节不是驻留量，不能新增 1GiB 累计硬截止或截断后不再排空。
- 状态解析保留严格 token/类型/重复字段/数值范围和 collector 身份验证；身份及状态不明时不清理现场。权限、超时和退出码分别记录，不压成一个 bool。
- 多线程进程 fork 后至 exec/_exit 只走受约束的安全路径；文本/参数等预先构造，不重新加入 child atfork 回调中的队列 clear、C++ 析构或条件变量重建。模拟“客户端退出”的测试使用 fresh exec。
- 回收器只回收其拥有的子进程，空队列等待、非空轮询有退避，不忙循环；进程退出时不 join 正在运行的包事务，不访问已销毁全局对象。
- 测试合成包锁只通过显式测试 Environment 注入；生产默认仍检查真实包锁，不能新增继承环境变量绕过保护或对宿主锁做测试。
- APT/DNF、script/便携按原渠道升级，不静默跨渠道覆盖。旧客户端直升必须用真实旧客户端与旧源/信任验证；只修新版 GUI、模拟旧文件或比较版本大小均不足以证明直升。

## 9. 配置、GTK 和页面导航

- `SettingsFileStamp`、content hash 与 application generation 分别描述物理文件、内容和进程应用状态；mtime 相同不等于文件未变，初始化和热载都消费同次读取事实。
- 保留 loaded/edited/saved/applied 区分及保存冲突检测；临时 I/O 故障后同 stamp 仍有界退避恢复，不能在若干次失败后永久不再读取。
- `runtime.state` 是可再生诊断，不是进程存活或授权的唯一事实；未知字段前向兼容，不能据损坏诊断值判定进程不存在。
- 字典、学习页的慢读取、保存、导入、导出和清理放 Worker；过滤已加载词典在内存完成。列表按当前每批最多 200 行或 4ms 让出事件循环，不阻塞主循环排完整列表。
- 每项异步操作有明确代次及 owner 生命周期；旧回调不覆盖新结果，窗口销毁后不能碰 GTK。清空/写入的逻辑防重不能只依赖按钮置灰。
- 测试钩子也要线程安全：锁内复制闭包，锁外调用；卸钩不能释放仍在途闭包。用真实读后/发布前栅栏及完成握手，不用固定 sleep 假定交错发生。
- `entryCount()` 失败返回 nullopt，不能伪装为零；SQLite COUNT(*) 不构造完整 Snapshot，但不是 O(1) 保证。
- 页别名、非法页和子项定位统一经现有解析/窗口入口；非法请求不得创建首窗口或改变已有窗口，次级实例通过 DBus 投递同一命令契约。

## 10. 用户数据与安装生命周期

- 导入外部不可信词频与可信本地恢复使用不同 `PersonalFileIntent`。外部频次钳制、核心词保护与本地恢复保留原值分别验证，不能用通用 import 一刀切损坏备份。
- SQLite WAL、LMDB 使用一致性备份接口；数据库损坏或备份失败阻断破坏性操作。备份自己的完整性/快照内容不能用不同时间的活库行数比较代替。
- 回滚只还原本次部署涉及的程序文件，绝不恢复旧用户数据库/配置覆盖升级期间的新写入。卸载基于 manifest 和所有权，保护用户改过的托管文件及系统包所有文件。
- 已加载 `.so` 使用 unlink 后替换等既有保护，不原地覆写 mmap inode；目录碰撞预检失败时不要触碰前缀。
- 源码、便携、DEB、RPM 的所有权和迁移边界保留。HOME/XDG、显式 prefix、含空格路径、无显示环境和离线数据自包含必须维持。

## 11. 构建、验证和发布也是基础

- CMake 声明依赖并保持 core-only 可构建；core 基准不能强制链接可选拼音/Fcitx5。头文件直接包含所用标准类型，不能只在新编译器的传递 include 下成功。
- 必需测试以当前 `tests/verify_required_tests.py` 与 CTest 注册表为准，不冻结“47/78/136 项即通过”。同时核对注册、执行、GTest 必需套件、失败和 skip；JUnit 路径使用绝对路径。
- 原生性能门限与 Sanitizer 开销分开：已有唯一容量回归 `FullCapacityInsertionEvictsLocallyAndKeepsOldSnapshot` 原生严格 <30ms，ASAN/TSAN 严格 <150ms。它不授权其他测试普遍放宽，也不改变 Release 的 1ms/5ms/30ms 门禁。
- 库/模型差异先原生 LibIME 回放，再定范围明确的兼容夹具。`NativePinyinTestBaseline::hasAuditedLegacyProfile()` 是已审计行为画像，不是安全指纹或版本号；未知画像不能自动获得放宽断言。保留真实选词、完整消费、最终位置和重启召回，不批量更新金样。
- Sanitizer 未报告错误是该次配置的结果；ASAN 不能证明无数据竞争，第三方库级 LSan 抑制不能证明业务零泄漏。测试逻辑过了但进程/检测器退出非零，不得写通过。
- 版本、README、网站动态/失败后备、资产名、不可变标签、签名源和 Release 绑定同一已验证来源。不能强推移动已发布标签或使用临时密钥替生产签名；文件更新与运行会话激活分别验收。
