## 根因与确定性反证

父进程的回收线程持有互斥锁，在 `g_pendingReaps.erase()` 内释放字符串。若其他线程此时 fork，子进程可能继承“字符串内存已释放、队列元素仍在析构中”的瞬间。原 `pthread_atfork` 子回调调用 `g_pendingReaps.clear()`，再次删除同一指针。其条件变量原地初始化也不能使继承的 C++ 对象成为完整的新运行时。

回归夹具 `tests/settings/process_runner_fork_fixture.cpp` 使用实际 `process_runner.cpp`，仅在独立测试程序中插桩分配释放：在父线程完成真实 `free()` 后、队列析构返回前暂停，然后 fork。子进程若再次删除被监视指针，夹具以 86 明确失败，避免测试依赖 glibc tcache 是否自行中止。子分支只调用 `execv` 和失败时的 `_exit`。

- 修复前：`child_exit=86`，夹具退出 6；输出 `fork child tried to free an already freed reaper path`。
- 修复后：`child_exit=0`，夹具退出 0；输出 `FORK_EXEC_OK_PARENT_REAPED`。同时断言父进程正常回收其 collector 并删除所属操作目录。
- 原审查方的原生分配器反证保留于主检出的 `build/T19-R1与R2第二轮复审证据/`；其 SIGABRT 历史不被此次新证据覆盖。

此夹具为窄范围并发交错测试，包含真实实现以定位释放栅栏，没有为生产类添加测试 API，也没有替换生产回收器。它通过既有 `modernime_process_runner` 套件编译和执行，无新增 CMake 接线要求。

## 生产改动

- 删除 `pthread_atfork` 回调及继承队列“清理后重新接管”的分支。回收队列、条件变量和线程由创建它们的进程管理；fork 子路径在 exec 前不重建这些对象。
- Query 和 collector 内启动目标命令失败时，错误文本由 fork 前构造，子进程用 `write` 输出后 `_exit(127)`，移除子进程中的 `dprintf`/`strerror`。
- `process_runner_test.cpp` 的 A06 客户端模拟、`update_controller_test.cpp` 的 7c 正常客户端退出模拟均改为 fork 后立即 exec 当前测试二进制。完整业务逻辑与正常 C++ 析构在新运行时内执行，保留后台命令完成、双流输出和客户端退出的原断言。

未改变生产包事务的超时、占槽、Uncertain、输出预算或独立采集器继续执行契约。未修改学习、候选、用户数据格式及共享 CMake/CI/checker 接线。
