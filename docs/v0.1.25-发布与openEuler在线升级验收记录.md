### 已观察到的限制和非致命告警

- 旧 0.1.17 客户端在启用严格仓库验签后仍会误报缓存不可用，其复制命令可用；升级后的 0.1.25 客户端实际检查成功。不能把“DNF 能升级”替代为“旧 GUI 检查也正常”。
- RPM 根用户脚本中的既有 best-effort `fcitx5-remote -r` 在没有用户会话 DBus 时出现辅助进程 `Aborted (core dumped)`。DNF 事务及 RPM 校验均退出 0，实际 Fcitx5 守护进程没有因此退出；随后以桌面用户身份重启并验证新插件生效。当前更新仍要求用户会话重启；后续可将根脚本中的会话通知改为仅在可确认的用户会话内执行，并保留包事务退出码，勿把此记录写成“安装零告警”。
- 首轮实机按键驱动因 UKUI 自动锁屏抓取键盘而未获得输入焦点，尚未执行任何词句。通过锁屏正常登录按钮恢复桌面后，同样的输入断言 11/11 通过。没有修改输入算法来规避焦点问题。
- 图标验收工具第一次受 `xprop` 默认输出长度截断，未读取完整 256 图标；显式提高工具读取长度后五个尺寸全部按原像素断言通过。收尾核对另处理了重启等待和新窗口默认在概览页的驱动前置条件；这些辅助脚本失败不计入产品测试通过数量。
- 此次实机范围为该 openEuler X11 / UKUI 桌面和独立 GTK 输入窗口，不扩展宣称所有 Qt / Wayland / 浏览器场景已实际验证。原生完整性能门禁在本机构建上执行，未把该数值宣称为 openEuler 机器上的基准。

## 签名缓存连接处的额外修复（发布前发现）

DNF 4.16 的 `--cacheonly` 会强制使用系统缓存。启用 repo_gpgcheck=1 后，普通用户查询会试图读取 root 私有的仓库公钥目录并提示导入，最终报缓存不可用；普通用户另建缓存也不能改变该行为。已依据实机 Python DNF 实现和真实旧客户端复现，不能把 root 刷新成功等同客户端成功。

最小修复仅在 `checkForUpdates()` 的只读 argv 加入字面参数 `--setopt=*.repo_gpgcheck=0`，仍保留 `--cacheonly`，不联网、不提权、不复制或保存第二份版本事实。它只读取 root 管理的已有缓存，不宣称本次查询重新验签；实际刷新、安装、升级没有该覆盖参数，也不使用 `--nogpgcheck`，源配置仍为 repo_gpgcheck=1 和 gpgcheck=1。精确 argv 回归先红灯，修复后控制器全部通过（6.19s）；刷新/升级的精确 argv 断言保证覆盖不泄漏到事务。

此前宿主第二次新克隆已完整退出 0：79 注册，73 通过、6 合法 GUI 跳过，195 项独立 GTest、full/final 执行合同、38 项合同自测、安装与卸载均通过。此基线不含刚发现的签名缓存查询修复，证据将单独保留；随后对更新后的最终树再次执行原始完整新克隆，不混合成同一轮通过。
