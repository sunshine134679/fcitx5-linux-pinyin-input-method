## 签名缓存连接处的额外修复（发布前发现）

DNF 4.16 的 `--cacheonly` 会强制使用系统缓存。启用 repo_gpgcheck=1 后，普通用户查询会试图读取 root 私有的仓库公钥目录并提示导入，最终报缓存不可用；普通用户另建缓存也不能改变该行为。已依据实机 Python DNF 实现和真实旧客户端复现，不能把 root 刷新成功等同客户端成功。

最小修复仅在 `checkForUpdates()` 的只读 argv 加入字面参数 `--setopt=*.repo_gpgcheck=0`，仍保留 `--cacheonly`，不联网、不提权、不复制或保存第二份版本事实。它只读取 root 管理的已有缓存，不宣称本次查询重新验签；实际刷新、安装、升级没有该覆盖参数，也不使用 `--nogpgcheck`，源配置仍为 repo_gpgcheck=1 和 gpgcheck=1。精确 argv 回归先红灯，修复后控制器全部通过（6.19s）；刷新/升级的精确 argv 断言保证覆盖不泄漏到事务。
