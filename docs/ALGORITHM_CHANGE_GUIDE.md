# ModernIME 算法变更指南

> 与 [算法架构与特性契约](ALGORITHM_ARCHITECTURE.md)、[算法演化手册](ALGORITHM_EVOLUTION.md) 配套。本文是维护流程；文中“拟建”验证能力尚未实现，不得在提交说明中宣称已经由 CI 自动执行。

## 1. 先确定改动类型

| 类型 | 必须说明 | 必须保护 |
|---|---|---|
| 新增 | 新契约 ID、默认是否启用、所在阶段、依赖、状态读写权限 | 新来源不能绕过学习资格、屏蔽、清空、中文保护和消费范围规则 |
| 调整 | 已有 ID、具体输入下的前后差异、参数用途与单位 | 无意图变化的场景保留既有断言，不能批量更新金样掩盖退化 |
| 重构 | 接口/职责移动、调用顺序是否变化、明确无意图的行为变化 | 固定词库、时间和事件流下的兼容结果；提前过滤等顺序调整要按行为变更处理 |
| 停用 | 禁用后的基线、依赖者如何降级、历史数据如何保留 | 关闭可选特性不关闭公共边界，不把禁用等同于删库 |
| 删除 | 退役 ID、替代行为、依赖迁移、旧数据读取和回退策略 | 不复用 ID，不删除历史说明，不静默清除用户词条或屏蔽记录 |

“算法 A 的指标提高了”不足以通过验收，还要说明它对其他契约的影响。成熟体验底线不可因新特性而削弱；若需求与底线冲突，应重新设计该特性的适用范围。

## 2. 固定七步变更流程

1. **读基线**：完整阅读演化手册的清单与不变量矩阵，再查架构文档中的契约目录、参数用途和交互表。核对当前工作区，不依赖旧设计推断现状。
2. **写影响说明**：用本文模板写清触发输入、预期行为、影响的 ID、未影响的理由、状态边界和数据兼容。放入本次设计/计划文档或变更说明，避免另建一份永久特性台账。
3. **先固定证据**：缺陷先建立可失败的回归用例；重构先固定关键输入的现有结果。新增行为同时覆盖新功能、关闭后基线和成熟场景组合。不能拿敏感用户原文做测试夹具。
4. **小步实现**：每次只改变一种政策或提取一种职责。保持时间、数据世代、页代次和来源角色语义明确，不同时重写公式、索引与持久格式。
5. **验证交互**：运行对应契约的测试与跨模块输入回放；涉及热路径、容量和异步学习时运行 Benchmark；任何算法行为变更均执行完整 CTest、GTest 和 Benchmark，不能仅凭局部通过宣布完成。
6. **完成生命周期验证**：较大变更或架构调整按 `AGENTS.md` 执行隔离全新克隆安装/卸载；涉及依赖、构建、配置、设置项时同步 README、CMake 和安装脚本。
7. **更新长期文档**：契约目录更新当前职责/依赖；演化手册追加已验证实现、代码位置和体验变化。方案尚未实现只写在设计中，不登记成已发布能力。

## 3. 特性变更记录模板

下面的空字段供复制填写；不是尚待实现的产品需求。可选项不适用时写明理由，不能无说明略过。

```markdown
### 变更名称与类型
- 类型：新增 / 调整 / 重构 / 停用 / 删除
- 契约 ID：新增 ID 或涉及的既有 ID
- 状态：设计 / 实施 / 已验证 / 已退役；所属版本或提交
- 目标：具体解决什么输入场景的问题
- 行为前后：固定输入、上下文、词库、时间及事件序列下的差异
- 无意图变化的行为：明确列出需保持的成熟场景
- 涉及候选时：参照候选子系统契约，记录组内/混排后全局位置及实际页面；涉及学习时附重复选择曲线，不能只记录词频增加

### 归属与依赖
- 执行阶段、协调者、代码入口：
- 输入/输出：候选身份、角色、消费范围、时间单位
- 可读状态 / 可写状态 / 生命周期与失效条件：
- 依赖及消费者：契约 ID；需要联测的交互
- 资格及顺序：敏感、禁学、屏蔽、清空与排序如何约束本特性
- 开关与降级：现有设置或明确的默认策略；禁用后的行为

### 兼容与回退
- 旧格式及旧别名：是否读取、如何归一化、是否改变精确查询
- 持久数据：是否改 schema，容量/剪枝/上下文变体是否变化
- 故障与竞争：重试、队列满、清空、后台结果过期如何处理
- 回退：代码与数据分别说明；是否仍能用旧版本读取新数据
- 停用/删除：依赖如何迁移，用户数据如何保留，ID 如何退役

### 验证证据
- 新增失败用例及修复后结果：
- 既有契约和交互测试：名称、命令、通过/失败/跳过
- 差异回放：基线、数据/时间/事件、允许差异及原因
- 性能：构建模式、数据规模、场景、P99/最大值、门限
- 生命周期：完整 CTest、GTest、Benchmark、全新克隆验证
- 尚未覆盖的条件与限制：
- 文档：架构目录、演化记录、涉及的 README 内容
```

## 4. 示例：以后增加一个“领域词候选源”

这是应用流程的示例，**不是当前已实现或已承诺开发的特性**。

| 字段 | 示例填写 |
|---|---|
| ID / 类型 | `ALG-DOMAIN` / 新增，状态为设计 |
| 所在阶段 | 召回；输出候选及来源证据，Provider 统一协调 |
| 状态权限 | 读取静态领域词表和本次请求；不直接修改学习库、造词计数或候选页 |
| 依赖 | `ALG-PINYIN`、`ALG-ZHEN`、`ALG-RANK`、`ALG-SUPPRESS`、`ALG-IDENTITY` |
| 预期变化 | 领域长拼音可出现新候选；明确记录允许变化的输入集合 |
| 必须保持 | `de` 首选“的”；被屏蔽词不能从新来源重新出现；`nihaoma` 部分选择消费不变 |
| 学习 | 选择后沿既有 CommitEvent/资格/Writer 流程，不增加来源专用写库分支 |
| 降级 | 关闭来源只移除它提供的证据；同词若来自其他合法来源仍按既有规则处理 |
| 数据与性能 | 静态数据随仓库离线构建；限制召回数量；不能通过降低 200,000 容量换延迟 |
| 必测交互 | 敏感输入、学习关闭、重启屏蔽、候选去重、技术英文、混排与满容量学习 |

若该来源要求“忽略中文短码保护才能见效”，应调整它的放行范围，而不是删除 `ALG-ZHEN` 的已有保护。

## 5. 验证入口与通过标准

### 5.1 现有能力

测试注册以 [tests/CMakeLists.txt](../tests/CMakeLists.txt) 为准，不固定为历史的 47 项。GTest 和 Benchmark 当前由依赖探测条件注册，**`ctest` 没有注册某个测试，不等于它通过了**。

在仓库根目录执行，`build/fcitx5-debug` 可替换成实际已配置并构建的目录：

```bash
cmake --build build/fcitx5-debug --parallel 4
ctest --test-dir build/fcitx5-debug -N
ctest --test-dir build/fcitx5-debug --output-on-failure
./tests/verify_fresh_clone.sh
```

完整算法验收必须在列表中看到 `modernime_personal_engine_gtest`、`modernime_personal_engine_benchmark`、相关拼音/学习测试与安装测试；缺少时先修正验证环境。GUI 测试因无显示环境跳过必须记录，不能宣称已完成真实桌面体验。

`verify_fresh_clone.sh` 在隔离环境验证安装/卸载。不得用 `/tmp` 下无前缀的裸 `install.sh` 或 `uninstall.sh` 替代它；测试数据与配置须隔离，不能连接真实个人词库。基准单独运行，避免同时编译和其他重负载任务干扰测量。

| 检查层 | 当前入口 | 通过标准 |
|---|---|---|
| 拼音、排序、仲裁 | `modernime_pinyin_match`、`modernime_pinyin_quality`、`modernime_english_arbitration` | 原断言保留；新增或修复行为有独立断言 |
| Provider/Controller 与真实 LibIME 链路 | `modernime_pinyin_provider`、`modernime_pinyin_engine`、`modernime_pinyin_daily_simulation`、`modernime_engine_state` | 候选、提交、消费范围、学习状态和边界转换符合契约 |
| 个性化与后端回归 | `modernime_personal_engine_gtest`、`modernime_learning_store` | 同批原子性、旧数据、清空竞争、共享学习及快照不变性正确 |
| 热路径 | `modernime_personal_engine_benchmark` | 现有场景召回 P99 <1 ms，更新加召回 P99 <5 ms；后台并发场景另有最大值 30 ms 门禁 |
| 生命周期 | 完整 CTest、`verify_fresh_clone.sh` | 构建、安装、环境集成、卸载及用户数据保护正确；如实记录跳过项 |

性能门限对应基准内定义的工作负载，不表示整个桌面按键链路在任何机器上均有同样上限。必须记录构建模式、词库分布、50,000/200,000 规模、忙锁/并发状态、样本和计时范围；不能用召回耗时冒充整次学习提交耗时。

### 5.2 拟建的差异回放与 CI 门禁

候选链路的细化设计、已复现反例和晋升目标见[候选排序、混排与排版架构](CANDIDATE_PIPELINE_ARCHITECTURE.md)。涉及候选行为的差异回放必须覆盖该文档的子契约，不能只比较评分器输出而遗漏固定混排、宽度分页和选择映射。

当前已有针对性测试、日常输入模拟和性能门禁；尚没有覆盖全部契约的统一差异回放器，也没有自动检查每次变更是否声明全部依赖的 CI。架构迁移 M0/M4 应补齐这些能力：

1. 固定基线版本、LibIME/词库版本、时钟、初始数据和事件序列；分别运行基线与新实现。
2. 记录候选身份/顺序/消费范围、提交事件、可见屏蔽、学习频率、上下文、清空代次；不记录真实敏感原文。
3. 重构场景比较确定性行为；新增候选场景仅允许已声明的变化，同时保留成熟候选的必要相对顺序和首选约束，不盲目要求整个列表字节相等。
4. 三种学习路径（Snapshot、SQLite、LMDB）回放同一语义事件，比较共同字段；排序和剪枝的已知策略差异显式验证，禁止悄悄归一为某一后端。
5. 检查新增/退役 ID、依赖声明、必需测试注册与文档链接；这些检查只保证材料完整，行为正确性仍由回归与回放证明。
6. 隐私、屏蔽、清空、消费范围、默认容量或性能门禁失败时阻止合入；不得以平均分提高覆盖失败用例。

## 6. 停用、删除与回退

先标记“拟停用”，找到调用者、共享状态、配置、持久字段及契约消费者。验证停用后的基线，再逐步删除调用路径；存在依赖者时先迁移依赖者。

持久词条、历史拼音键和屏蔽记录不能因代码不再使用就立即清除。优先保留兼容读取与用户数据；确需改变持久格式时独立设计迁移，使用一致性备份，验证失败可恢复，并说明旧程序能否安全读取。不能把一次备份恢复当成可无损撤回后续用户输入的承诺。

回退优先撤销特性代码或关闭已有可选入口；不要先恢复旧数据库覆盖新学习。若格式不能向后兼容，需要配套程序版本和经过验证的数据恢复流程，明确恢复点之后输入的处理方式。

最后把契约标记“已退役”，保留原 ID、停用版本、替代契约和数据保留规则，并在演化手册追加记录。删除历史文档、减少测试断言或降低默认容量，都不属于合格的特性删除方案。

## 本轮已落地模块的增删定位（2026-10-15）

| 变更 | 实现入口 | 必须联动的验证 |
|---|---|---|
| 增减中文评分特征 | `candidate_features` + `CandidateScore` | 原生/纠错/学习三个来源；有界先验；冷启动和学习曲线 |
| 增减来源 | `candidate_pipeline` | 身份合并、原生位置、统一 Features、屏蔽与预算 |
| 调整近期意图 | `recent_choice` + Provider 生命周期 | 一次不夺位、连续纠正、强历史切换、共享/重置/敏感/禁学不泄露 |
| 调整前缀 / 中文席位 | `candidate_prefixes` / `candidate_mixer` | 自身证据、父词隔离、最终全局位置、前五配额及剩余输入 |
| 改分页与绘制 | `ui/fcitx5` | 固定语义顺序、全部页面覆盖、数字键和点击映射 |

新增特征不得分别在原生/纠错/召回循环复制计算；新增席位不得用 UI 重排实现。删除模块先移除调用与状态，再移除构建声明和文档；保留成熟契约测试，只有明确废弃的能力才连同验收一起删除。所有变更均遵守前文影响分析、演化台账和安装验证流程。
