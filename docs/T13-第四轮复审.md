## 2. U1 / P1：累计输出计数被错误当成资源预算

**定位：** `tools/settings/process_runner.cpp:652–660`，`parseStateFile()`。

T3 新增：

```cpp
if (soBytes < 0 || soBytes > 1073741824LL) return s;
if (seBytes < 0 || seBytes > 1073741824LL) return s;
```

`stdoutBytes/stderrBytes` 是 collector 排空过程中累计读到的字节数，代码持续增加该值并写入最终状态。它们不是驻留缓冲大小或诊断文件长度。原契约通过截断限制驻留与落盘资源，允许后台包事务持续排空，没有规定单流累计输出最多 1GiB。

因此，合法事务只要任一流超过 1GiB，即使任务退出码为 0，且 tail/diag 都严格在预算内，消费者也会拒收 collector 自己生成的终态：collector 尚活时表现为 Continuing，退出后会落入 Unknown，从而无法正常完成同 ID 操作。

**独立复现：** 用已登记引用、正确 PID/token、其余字段完整的合成 Exited/0 状态，仅改变累计计数：

```text
stdoutBytes=1073741824  -> state=Exited, exit=0
stdoutBytes=1073741825  -> state=Continuing, exit=-1
```

这是当前真实 `waitForOperation/parseStateFile` 的协议边界验证，没有实际生成 1GiB 输出，也不将合成计数说成吞吐实测。生产 producer 会生成这种累计值，可由其计数与状态写出路径直接确认。

**根因：** 把“转换前检查表示范围”扩展成未经授权的业务上限，混淆累计量与资源驻留量。修复安全转换不能改变可完成的事务集合。

**最小目标：**

- 保留 PID、退出码的已有效检查；累计字节数按协议数值表示能力与目标类型可表示范围校验，不新增 1GiB 业务上限。
- 明确累计字节、返回尾部、裁剪前 size 峰值、诊断文件峰值各自含义；峰值校验只依据已有预算与测量口径，不随手给所有数字同一魔数上限。
- 不增加内存/文件预算、不保留全量输出、不修改用户数据或状态文件字段格式，不另建解析框架。

**前置测试与完成标准：**

1. 先加 1GiB 边界、边界+1 和较大合法累计计数，分别覆盖 stdout/stderr，当前实现必须失败。
2. 同时保留负值、真正不可表示值、错误退出码、PID 越界的拒收测试。
3. 合法大累计计数的 Exited/0 必须可完成，错误输入不能授权完成或清目录；容量预算保持原样。
4. 用合成状态完成边界回归即可，不要求每次测试都真实输出数 GiB。

## 3. U2 / P1 验收缺口：安装检查仍可能挂住或误放行坏结果

**定位：** `tests/verify_fresh_clone.sh:96–109`。

### 3.1 握手后 wait 无截止

5 秒只限制 FIFO 的 read。收到 R 后，`wait "$t4_pid"` 没有期限。如果 collector 在握手后卡住，整条 clean-clone 门禁仍可无限等待。

独立执行原样检查段：私有假 binary 写出 R 后停滞，**超过 7 秒仍未退出，必须由探针外层看门狗回收**。原脚本没有自行按期限失败。

### 3.2 grep 不证明完整 JSON 或精确 ID

当前检查只搜索文本片段。其中 ID 检查 `"operationId": 98765` 也匹配 987650。独立假产物生成：

```text
not-json "state": "Exited"
"exitStatus": 0
"operationId": 987650
"token": "install-token-98765"
```

并写入预期双流标记、正常退出。**当前检查段返回 0**。这同时证明非 JSON 与错误 ID 可通过安装门禁；不能据此宣称“坏结果均非零拒绝”。

**最小目标与完成标准：**

- 给这个隔离合成任务建立覆盖握手、终态等待、子进程退出的总期限。超时必须使门禁非零，并只回收测试拥有的假进程/后代；不得将测试策略用于生产包事务。
- 用现有 Python 依赖读取受大小约束的 JSON，拒绝语法错误、重复关键字段和错误类型；精确比较 ID/token/state/exitStatus，检查预期双流标记、目录与文件权限及原资源预算。
- 保留真实安装产物成功任务。缺参数检查若报告“退出码 1”，就确切断言 1，不以任意非零代替。
- 加正向与负向测试：成功、启动失败、崩溃、握手后停滞、无终态、损坏 JSON、错误 ID/token、错误标记。坏结果必须非零，不能只检验脚本文本存在。
- 当前 `T13-T04` 单元只调用构建产物的缺参数和 version，不能替代安装后成功任务及这些负向分支。可让同一个小范围检查入口在私有假产物与真实安装产物上复用；不建立通用安装/进程 Manager。
