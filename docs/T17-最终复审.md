## 1. 四大核心生命周期行为核验

### 1.1 安装生命周期与 Inode 解绑保护 (Installation & Inode Unlink)
- **显式部署入口**：`scripts/install_lifecycle.sh` 实现了显式薄入口 `modernime_deploy_payload PAYLOAD PREFIX TRANSACTION_DIR` 与 `modernime_integrate PREFIX CONFIG_HOME DESKTOP_DIR MANAGED_STATE_DIR [DATA_HOME]`，彻底终结了历史隐式环境变量依赖。
- **运行中进程 Inode 保护**：部署覆盖前缀文件时，强制使用 `cp -a --remove-destination`（先 unlink 目标 inode 再写入新文件）。
  - *独立验证*：在 `install_lifecycle_prep_test.sh` 中，后台进程持有 `modernime_fcitx5.so` 的活动 `mmap` 读取映射；部署新版本后，旧进程的 `mmap` 读取内容未损坏（保持 `ELF-plugin-v0.1.7` 内容不变），前缀中的库文件分配了新 Inode（`new_so_inode != old_so_inode`），彻底杜绝了进程运行中覆写动态库引发的 SIGSEGV/SIGBUS 崩溃。
- **预检与碰撞拦截**：部署前遍历 `payload.list` 预检；若目标路径存在目录碰撞（如目标已存在同名目录），立即中止于预检阶段，生成 `FAILED_COLLISION` 状态，前缀保持 100% 未触碰。
- **二进制安装包生成器重构**：`scripts/generate_binary_installer.sh` 废除了脆弱的 `awk` 文本切片逻辑，改由直接生成显式打包的薄安装脚本，完整打包 `install_lifecycle.sh`、`install_state.sh`、`modernime-data-guard` 与 `modernime-migrate-channel`，在 `install_runtime_test.sh` 中全流程打包与安装验证通过。

### 1.2 故障事务回滚 (Rollback Protocol)
- **受控备份与恢复**：`modernime_rollback_payload PREFIX TRANSACTION_DIR` 根据事务记录的 `changed.list` 逆序删除已部署新文件，并从 `backup/` 中恢复被替换的原版本文件（同样使用 `--remove-destination`）。
- **新建目录反向修剪**：从 `created_dirs.list` 逆序清理本次事务新增的空目录结构，不遗留孤立目录。
- **事务审计状态**：事务状态机严格流转（`PREPARING` → `DEPLOYING` → `COMMITTED` / `ROLLED_BACK` / `FAILED_BACKUP` / `FAILED_COLLISION`），异常终止现场留存日志可供审计。

### 1.3 并发数据保护与核心不变量 (Concurrent Data Protection)
- **核心不变量**：`RollbackPreservesConcurrentUserWrites`。
  - 回滚操作的作用范围被严格限制在 `changed.list` 所记录的前缀部署文件内，**绝对禁止触碰、覆盖或还原任何用户数据**（`$CONFIG_HOME/modernime/settings.conf`、`$DATA_HOME/modernime/learning.sqlite3` (+WAL/SHM)、`learning.lmdb` 及 `user-dictionary.txt`）。
  - *独立验证*：在 `install_rollback_concurrent_writes_test.sh` 与 `install_lifecycle_prep_test.sh` 中，注入部署失败（`MODERNIME_SIMULATE_INSTALL_FAILURE=1`）并在升级窗口期间发起并发学习词条提交（SQLite WAL 事务）与配置文件更改。回滚完成后：
    1. 前缀二进制与插件准确还原回旧版本；
    2. SQLite WAL 完整性检查（`PRAGMA integrity_check`）返回 `ok`，并发提交的词条（`并发WAL词条`、`新学词条`）100% 完整留存；
    3. 用户配置修改（`candidate.page_size=9`, `theme=dark`）与自定义词典原样保留。
  - *负向反例阻断*：`install_rollback_concurrent_writes_test.sh` 的 Test 1（Baseline Anti-Example）验证了缺陷回滚（快照还原用户目录导致并发写入丢失）会被测试夹具准确拦截并报错。
- **在线数据备份**：`scripts/modernime-data-guard` 使用 SQLite Online Backup API 与 LMDB 只读快照完成无停机平滑备份，在 `upgrade_data_protection_test.sh` 中验证通过。

### 1.4 卸载行为与系统所有权边界 (Uninstall Lifecycle)
- **临时目录防误伤**：`uninstall.sh` 增加运行根路径校验，若在 `/tmp` 或 `/var/tmp` 运行且未指定 `MODERNIME_PREFIX`，主动拒绝执行，防止误删用户主目录 `$HOME/.local`。
- **受控清单卸载**：严格依据 `$prefix/share/modernime/install-manifest.txt` 清理，严禁通配符整目录删除。
- **用户自定编辑保护**：对桌面快捷方式、环境变量条目、自启动项与 `.xprofile` 托管块，通过比较基线内容判断用户是否手动修改；若已被用户修改，则记录 `Preserving modified or unowned file` 并予以保留，不执行强制覆盖或删除。
- **系统包管理所有权边界**：当安装在前缀 `/usr` 等系统目录时，`uninstall.sh` 自动调用 `dpkg -S` 或 `rpm -qf` 探测所有权；若属于系统原生包，记录 `Preserving file managed by native system package` 并保留文件，在 `install_channel_collision_test.sh` 中验证通过。
