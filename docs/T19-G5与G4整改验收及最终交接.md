## 2. 生产与测试代码变更明细（`27ce1c9..eb34cc6`）

本次整改包含两个原子提交，严格遵循最小修改与所有权原则，未放宽任何 5ms/30ms 门禁、未修改学习政策、未变更数据结构容量：

### 2.1 提交 `f40270d`：LMDB 快照开销优化、敏感单测独占调度与未对齐引用消除
- **`core/include/modernime/core/personal_engine.h` 与 `core/src/personal_engine.cpp`**：
  - **根因**：原 `ResetRevision()` 在轮询 LMDB 版本快照时，每次均调用 `mdb_txn_begin(..., MDB_RDONLY, &txn)` 并紧接着 `mdb_txn_abort(txn)`。在 Linux/WSL2 内核的健壮 futex 机制下，频繁创建和中止只读事务引发 LMDB reader 槽位扫描与锁表互斥争抢，造成清空后首键事务延迟尖峰达到 2.5ms ~ 5.6ms。
  - **修复**：在 `PersonalEngine` 中引入持久读事务复用机制 `cached_read_env_` 与 `cached_read_txn_`。使用 LMDB 官方推荐的 `mdb_txn_renew` + `mdb_txn_reset` 事务周期复用模式。单次查询仅耗时约 170ns，彻底消除了读者槽分配开销与互斥锁竞争。
  - **UBSAN 对齐未定义行为修复**：`struct WordMeta` 声明了 `#pragma pack(push, 1)`。C++ 标准规定禁止将 `const T&` 引用绑定到紧凑结构体中非自然对齐的成员字段（如偏移 23 字节的 64 位 `last_selected_ms`）。原代码直接调用 `std::max`/`std::min` 引发 UBSAN `reference binding to misaligned address`。实现值传递辅助函数 `maxVal`/`minVal`，消除了引用绑定未定义行为。
- **`tests/CMakeLists.txt`**：
  - 为敏感性能单测 `modernime_personal_engine_gtest` 配置 `PROPERTIES RUN_SERIAL TRUE`。避免其在 `verify_fresh_clone.sh`（`ctest -j8`）高并发时与其他编译/测试进程争抢 CPU 时间片，消除 `provider.append("ceshi")` 出现的调度毛刺。

### 2.2 提交 `eb34cc6`：设置单测临时目录并发冲突消除与配置契约测试独占调度
- **`tests/core/settings_test.cpp`**：
  - **根因**：`settings_test.cpp` 原 `testDirectory()` 使用静态固定路径 `/tmp/modernime-settings-test`，并在初始化与析构中执行 `remove_all()`。当 `modernime_settings` 与 `modernime_configuration_contract` 并发执行时，发生跨进程目录删除冲突。
  - **修复**：改用 `mkdtemp` 动态唯一沙箱模板 `modernime-settings-test-XXXXXX`，保证每个测试套件与进程独占独立目录。
- **`tests/CMakeLists.txt`**：
  - 为多场景组合测试 `modernime_configuration_contract` 同样配置 `PROPERTIES RUN_SERIAL TRUE`，避免 runner 级调度碰撞。
