## 2. 生产与测试代码变更明细（`27ce1c9..bc2d190`）

本次整改严格遵循最小修改与所有权原则，未放宽任何 5ms/30ms 门禁、未修改学习政策、未变更数据结构容量：

### 2.1 提交 `f40270d`：LMDB 快照开销优化、敏感单测独占调度与未对齐引用消除
- **`core/include/modernime/core/personal_engine.h` 与 `core/src/personal_engine.cpp`**：
  - **根因**：原 `ResetRevision()` 在轮询 LMDB 版本快照时，每次均调用 `mdb_txn_begin(..., MDB_RDONLY, &txn)` 并紧接着 `mdb_txn_abort(txn)`。在 Linux/WSL2 内核下频繁创建和中止只读事务引发 LMDB reader 槽位扫描与锁表争抢，造成清空后首键事务延迟尖峰达到 2.5ms ~ 5.6ms。
  - **修复**：在事务查询路径中采用 LMDB 官方推荐的 `mdb_txn_renew` + `mdb_txn_reset` 事务周期复用模式。单次查询仅耗时约 170ns，大幅降低了读者槽分配开销与锁竞争。
  - **UBSAN 对齐未定义行为修复**：`struct WordMeta` 声明了 `#pragma pack(push, 1)`。C++ 标准规定禁止将 `const T&` 引用绑定到紧凑结构体中非自然对齐的成员字段（如偏移 23 字节的 64 位 `last_selected_ms`）。原代码直接调用 `std::max`/`std::min` 引发 UBSAN `reference binding to misaligned address`。实现值传递辅助函数 `maxVal`/`minVal`，消除引用绑定未定义行为。
- **`tests/CMakeLists.txt`**：
  - 为敏感性能单测 `modernime_personal_engine_gtest` 配置 `PROPERTIES RUN_SERIAL TRUE`。避免其在 `verify_fresh_clone.sh`（`ctest -j8`）高并发时与其他编译/测试进程争抢 CPU 时间片，消除 `provider.append("ceshi")` 出现的调度毛刺。

### 2.2 提交 `eb34cc6`：设置单测临时目录并发冲突消除与配置契约测试独占调度
- **`tests/core/settings_test.cpp`**：
  - **根因**：`settings_test.cpp` 原 `testDirectory()` 使用静态固定路径 `/tmp/modernime-settings-test`，并在初始化与析构中执行 `remove_all()`。当 `modernime_settings` 与 `modernime_configuration_contract` 并发执行时，发生跨进程目录删除冲突。
  - **修复**：改用 `mkdtemp` 动态唯一沙箱模板 `modernime-settings-test-XXXXXX`，保证每个测试套件与进程独占独立目录。
- **`tests/CMakeLists.txt`**：
  - 为多场景组合测试 `modernime_configuration_contract` 同样配置 `PROPERTIES RUN_SERIAL TRUE`，避免 runner 级调度碰撞。

### 2.3 提交 `bc2d190`：R1 缓存读事务环境寿命闭环与 R2 ASAN 确定性加固
- **R1 / P1 读事务环境寿命下沉（`core/src/lmdb_environment.h`、`core/src/lmdb_environment.cpp`、`core/src/personal_engine.cpp`）**：
  - **根因分析**：原 `cached_read_txn_` 保存在 `PersonalEngine` 内部，当通过 `OpenLmdb` 切换路径、或同路径由另一引擎升级可写（导致内部 `close()` 并重建 `MDB_env`）时，`PersonalEngine` 仍持有旧环境代次的事务句柄。后续调用 `ResetRevision()` 或 `CloseLmdb()` 对已销毁的 `MDB_env` 执行 `mdb_txn_abort`/`renew`，引发 SIGSEGV 或非法访问。
  - **最小修复**：将读事务缓存的所有权由 `PersonalEngine` 下沉至其底层绑定的 `LmdbEnvironment`（`cached_revision_txn_`）。在 `LmdbEnvironment::close()`、`upgradeToWritableLocked()` 以及 `ensureMapCapacity()` 中，在底层 `mdb_env_close` 或 map resize 之前，均同步、安全地执行 `mdb_txn_abort` 并置空句柄。`PersonalEngine::ResetRevision()` 通过环境外壳安全委托调用 `readResetRevision()`。
  - **严格保序与防穿透**：保留原有锁顺序，不引入锁环；每次 `renew` 获取最新视图后立即 `reset` 释放 reader 槽，保留修订代次单调性与并发安全性。
  - **探针与单测验证**：
    - 审查方 `原生寿命探针-new switch` 与 `upgrade` 运行均退出 0（`NATIVE_OK`，无崩溃）。
    - 审查方 `事务寿命探针-new`（包含 GNU ld wrap 拦截）在 `control`、`switch`、`upgrade` 全场景下退出 0（输出 `PASS_NO_STALE_TXN`，`retained_txn_handles=0`，零旧代次事务遗留）。
    - 在 `tests/core/lmdb_lifecycle_test.cpp` 固化 4 项针对性生命周期回归用例（换库、可写升级、同路径关闭重开、并发读与关闭交错），用例总数由 132 扩充至 136，全部通过。
    - 算法演化记录同步更新至 `docs/ALGORITHM_EVOLUTION.md`（特性 9）。
- **R2 Fork 鲁棒性与子进程清理（`tools/settings/process_runner.cpp`、`tools/settings/update_controller.cpp`）**：
  - **根因**：原代码使用 `std::thread g_reaperThread`，在 `fork()` 后子进程继承了该线程对象。当子进程执行 `exit()` 时，标准库尝试销毁 `std::thread` 导致 `std::terminate()` 或 ASAN `sanitizer_thread_arg_retval.cpp:57` 崩溃；同时，条件变量在父进程有等待者时发生 fork，子进程退出析构条件变量时触发 glibc `pthread_cond_destroy` 的 futex wait 死锁挂起。
  - **当时的改动及后续否定**：将 `std::thread` 替换为 `pthread_t`，在 `pthread_atfork` 子回调中重置条件变量并清空回收队列。后续确定性复审证明，此清理会在继承父线程中间状态时再次释放已经释放的队列字符串；不得继续把它描述为已消除 fork 未定义行为。
  - **UpdateController 退出清理的实际边界**：`atexit` 设置关闭标记，脱离线程按 200ms 轮询观察。该改动没有等待线程退出的确认，不能单凭此机制断言静态析构前线程必然停止。新鲜进程中的正常退出需由独立运行证据支持。
- **确定性测试握手夹具（`tests/settings/update_controller_test.cpp`、`process_runner_test.cpp`、`runtime_controller_test.cpp`）**：
  - 引入确定性状态握手夹具（如 `pkg-op-release-continue.txt`、`signal-ready.txt`），使用文件握手确保子进程在父进程断言前稳定处于预期阶段，不再依赖脆弱的裸 sleep 或放宽生产超时限额。
  - `modernime_process_runner` 34/34 测试全部通过；`modernime_update_controller` 17/17 测试全部通过；`modernime_runtime_controller` 全部通过。
