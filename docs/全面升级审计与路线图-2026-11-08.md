# ModernIME 全面升级：审计与路线图

日期：2026-11-08。主验收平台由用户明确为 **Ubuntu 24.04 + GNOME**。

状态（2026-11-09）：线上正式版为 v0.2.0，GitHub Release、官网及签名 APT/DNF 软件源已发布，真实旧版 Ubuntu 在线升级及数据保留已验证。后续两项冷启动语境首选、Qt6 实际退格补字及客户端主题改进已在本地交付，见第48–50节；v0.2.1 已生成本地安装包并创建草稿 PR，用户授权 CI 通过后完整发布。首轮 CI 的三项失败及定向修正见第51节，修正版1973602的CI已通过；用户随后反馈的跨拼音夺首问题见第52节，其CI暴露的一项旧模糊音兼容问题已定向修正，见第53节；最终69268ac的CI已全部通过，按授权进入完整发布，见第54节。用户对 v0.2.0 首轮试用反馈“暂未发现日用问题”，新增补丁的长期日用仍需观察。第1–7节保留初审基线和原始问题，后续记录实际修复；不把图形跳过项或未执行项记为通过，也不替代既有 ALG/CAND 契约或算法演化记录。当前正式交付见 [v0.2.0 发布说明](releases/v0.2.0-发布说明.md)，待发布改进见 [v0.2.1 发布说明](releases/v0.2.1-发布说明.md)。

## 1. 结论

ModernIME 已具备完整的输入法、候选绘制、学习存储、八页设置客户端和安装事务基础。应保留现有职责与数据模型，通过可复现问题、真实消费者回归和质量数据逐步改进。

本轮发现的主要问题不是缺少界面卡片，而是长拼音原文污染英文学习、金额转换边界错误、上下文衰减接线遗漏、解码分数方向、GNOME 扩展所有权及版本状态反馈。双拼、可配置模糊音、原生 Wayland 光标定位等需求尚未完成。现有测试和历史报告不能证明这些边界已经可靠，也不能支持 README 的通用体验百分比。

实施顺序采用：**正确性与数据保护 → 可量化质量回放 → 输入能力 → 候选宿主适配 → 八页客户端 → 综合验收**。小型设置反馈修复可在正确性阶段独立交付。每批具备单独测试与程序文件回退；不自动清理既有学习记录，不把升级回退变成用户数据回滚。

## 4. 已复现或证据明确的问题

P1 表示优先安排的输入正确性/用户文件保护问题；P2 表示有明确影响、需要独立修复或验证的功能问题。优先级是本轮实施判断，不表示已发生在用户日常数据中。

### U01 / P1：长拼音原文被学习为英文

真实链路：`ModernIMEController::handleKey → commitRawPreedit → PinyinCandidateProvider::onCommitEvent → LearningWriter → decideCommitLearning`。`core/src/pinyin_match.cpp:122` 把超过 48 字节判为非拼音；学习政策和英文索引复用该判断，而组合输入支持更长文本。

真实 Controller 探针以隔离 SQLite 输入、回车、flush、销毁并重开：45 字节对照没有记录；50 字节拼音产生一条英文记录；自然长拼音 `qingbangwojianchayixiazhegedaimayoumeiyouwentiranhougaosuwo`（59 字节）也被 `recallEnglishWords("qin")` 召回。原文提交本身完整，错误发生在学习分类与持久召回。

修复要求：保留真正英文/代码的 Raw 学习；避免用分类预算耗尽推导“不是拼音”；覆盖长度边界、分隔符及 Ready/Reloading，两后端与重开。禁止一律禁学 Raw 或降低输入长度来绕过。

### U02 / P1：金额转换可直接提交错误值

`algorithm/pinyin/src/pinyin_candidate_provider.cpp:46–244` 的转换器只定义到“兆”，对更高分组没有单位；小数只取角、分，入口未检查范围。

真实 Controller 输入 `v10000000000000000`，首选及空格提交均为“壹元整”；`v1.001` 首选及提交为“壹元”。现有测试只覆盖至 15 位整数和两位小数。

第一批策略：明确金融大写支持 0–9999999999999999、至多两位小数，不静默截断或舍入；超范围保留原文提交能力，停止生成会改变数值的金融候选。标准中文数字转换单独明确范围，不能因金融候选不支持就丢原文。具体原文候选顺序和按键行为在实施测试中固定。

### U03 / P2：上下文时间衰减没有进入最终特征

`candidate_features.cpp:111` 调用 `LearningSnapshot::contextBoost` 时遗漏 `request.nowMs`，默认时间为 0。召回中曾计算的带时间结果随后被重算。

当前 Release 库探针中，第 0/30/300 天直接上下文增益为 `1.088629 / 1.053972 / 1.019382`，最终特征始终为 `1.088629`。修复应传同次请求时钟，保持普通学习和上下文各自衰减公式，补 Features/Provider 连接处回归；不能只测 Snapshot helper。

### U04 / P2：解码奖励方向与实际 LibIME 分数相反

LibIME 1.1.5 的 `nihao` 原生前三为 `你好 -13.2932`、`拟好 -15.3288`、`你号 -16.8236`，较高分更优。`core/src/candidate_ranker.cpp:77` 使用 `(max-score)/range`，在最终代价里减去该奖励，使较低分获奖。同先验合成排序已复现反向偏好。

该项权重仅 0.25，原生位置等先验仍占主要作用；本轮没有据此证明真实首选普遍错误。实施前必须同时核对补充解码 `+0.8/+2.0`、不同来源归一化与合并语义，再做候选质量前后回放，禁止只翻转一处符号后宣称整体提升。

### U05 / P1：GNOME 扩展覆盖用户副本且吞掉失败

`scripts/modernime-session-init:176–197` 直接 `cp -rf` 到用户 `kimpanel@kde.org`，没有使用已有内容基线/所有权保护。隔离 HOME、假 GNOME 命令、不存在的总线探针证实：原用户 `extension.js` 被覆盖；Schema 编译/启用/GSettings 分别返回 21/22/23 时，脚本仍退出 0 并报告初始化完成。设置 `MODERNIME_SKIP_FCITX_RESTART=1` 不会跳过这些操作。

卸载只处理 prefix 中资产，用户扩展副本与启用状态未形成对称生命周期。修复必须区分预先存在的第三方扩展、本工具创建且未修改的副本、用户修改后的副本；保护已有内容，错误可见，只撤销本工具拥有的改变。

### U06 / P1：fresh-clone 测试的宿主隔离不完整

`tests/verify_fresh_clone.sh:29–37` 设置 HOME/XDG/prefix/config/desktop，但继承 `MODERNIME_DATA_HOME`、`MODERNIME_BUILD_DIR` 和真实 DBus/GNOME 环境。传入这些变量时可进入宿主数据/构建路径，或通过 session-init 改真实扩展状态。这个条件路径由当前变量消费代码和 U05 探针支持；本轮没有执行会触碰宿主的反例。

脚本已经包含 HEAD、已跟踪未提交补丁和非忽略未跟踪文件，不能误报“只测试旧 HEAD”。后续应固定所有路径、隔离总线并加入宿主哨兵负向验证；专用验证强制 full 注册、执行和报告核验。完成前不直接裸跑该脚本。

### U07 / P2：更新页将缓存事实改写为远端最新结论

状态更新：本项已按第 14 节完成修复与隔离验收；以下保留初始审计事实。

`UpdateController` 使用 `apt-cache policy` / `dnf --cacheonly`，并设置 `cacheMayBeStale`、具体 `statusMessage`。`tools/settings/pages/updates_page.cpp:446–455` 丢弃这些事实，无更新时显示“已是最新版本”，失败时统一归为网络问题。本轮实际 GTK 更新页也显示该结论。

修复应呈现“本地软件源缓存中未发现更新”等准确状态及刷新命令；保留渠道差异和失败原因。不能暗中执行需要权限的系统更新来让文案成立。

### U08 / P2：设置的空状态与预览反馈不充分

- `settings_shell.cpp:633` 搜索无结果直接关闭 popover，输入 `不存在设置xyz` 没有“未找到设置”反馈，当前截图可复现。
- `learning_page.cpp:132–149` 将记录统计主要写入日志，空库页面仅显示禁用清空按钮；打开页的失败也可能不通知。应区分加载、0 条、读取失败、正在清空，不让用户猜测。
- `candidates_page.cpp:278` 将候选预览缩小适应宽度，但不显示预览缩放比。720×520 下相同 20pt 预览明显缩小，不能作为实际字号的直观确认。
