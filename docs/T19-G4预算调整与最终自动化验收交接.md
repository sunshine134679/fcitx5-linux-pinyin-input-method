## 3. 推荐的限定测试预算调整

### 3.1 唯一调整对象

文件：`tests/core/personalization_snapshot_regression_test.cpp`。

用例：`PersonalizationSnapshotRegression.FullCapacityInsertionEvictsLocallyAndKeepsOldSnapshot`。

当前该用例已经区分 TSAN 与普通构建预算。推荐仅将 ASAN 纳入相同的插桩预算分支：

| 构建模式 | 预算 | 约束 |
|---|---|---|
| 未插桩 Debug/Release | 严格小于 30ms | 保持现有断言 |
| TSAN | 严格小于 150ms | 保持已有 TSAN 预算 |
| ASAN，含同时启用 UBSAN | 严格小于 150ms | 本次建议新增的明确例外 |
| 其他情况 | 保持既有分支 | 不将例外泛化为所有调试或检测配置 |

实现需兼容 GCC 的 Sanitizer 宏及 Clang 的 `__has_feature`，沿用本文件已有的兼容处理，避免未定义的函数式宏导致预处理错误。

### 3.2 保持不变的契约

- 不修改其他用例的计时断言，不全局提高测试超时。
- 不改变 200,000 条容量、旧快照不变性、新词存在性及频次等功能断言。
- 不改变 Release Benchmark 的任何生产性能门限及 8 项负向拒绝自检。
- 不关闭 ASAN/UBSAN，不通过关闭泄漏检测、添加核心抑制或跳过用例使结果变绿。
