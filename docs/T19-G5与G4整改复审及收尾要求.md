## 2. R1 / P1：缓存事务越过环境关闭边界，原生换库调用已复现SIGSEGV

涉及：

- `PersonalEngine::ResetRevision()`、`OpenLmdb()`、`CloseLmdb()`。
- 新成员 `cached_read_env_` / `cached_read_txn_`。
- `LmdbEnvironment::upgradeToWritableLocked()` / `close()`。

### 2.1 原生最小复现

```cpp
PersonalEngine engine;
engine.OpenLmdb(pathA, false);
engine.ResetRevision();          // 创建并reset缓存只读事务
engine.OpenLmdb(pathB, false);   // 旧共享环境释放，缓存事务未先失效
engine.CloseLmdb();              // abort已关闭环境的旧事务
```

链接本次真实生产核心库、不使用诊断拦截的私有原生子进程：**exit=-11，即SIGSEGV**。

同一类问题也覆盖跨引擎只读升级：引擎A只读打开并调用ResetRevision产生缓存；引擎B同路径可写打开，LmdbEnvironment关闭旧MDB_env并重建。A下次读代次或关闭时仍持旧事务。

只比较 `cached_read_env_ != active_env` 不足以修复：发现不同后再abort旧事务，已经晚于环境关闭；分配器复用相同MDB_env地址时，指针相等也不代表同一环境代次。单纯给原始环境对象加shared_ptr也不能阻止共享LmdbEnvironment内部的RO→RW重建。

### 2.2 新旧对照与证据口径

诊断探针链接真实核心库，用GNU链接包装仅记录MDB_env创建代次与事务归属，在即将对已关闭环境的事务调用abort/renew前退出86，不继续执行危险操作。它不修改生产行为来制造交错，也不伪称exit86是ASAN报错。

| 同一探针场景 | 27ce1c9旧核心 | eb34cc6新核心 |
|---|---|---|
| 同环境反复读代次、clear、关闭 | exit0 | exit0 |
| RO读代次缓存→另一引擎RW升级→RO再读/关闭 | exit0，无遗留事务 | exit86，环境已关闭后abort旧代次事务 |
| A库读代次缓存→切B库→关闭 | exit0，无遗留事务 | exit86，环境已关闭后abort旧代次事务 |

新实现原生换库子进程进一步得到SIGSEGV；原生RO升级本次运行返回0，但诊断已证实非法寿命顺序，不能将一次未崩溃当成安全。没有据此宣称用户库已损坏。

本机LMDB头文件对mdb_txn_reset的说明明确：保留事务句柄及其关联reader槽，需abort释放；mdb_env_close要求事务、数据库和游标在关闭环境前已关闭。reset不是让事务独立于环境存活的许可。

### 2.3 最小修复目标与验收

- 将缓存事务的所有权和失效时点放到能控制环境重建/关闭的现有生命周期边界；可考虑由现有LmdbEnvironment管理缓存与必要同步，不新增通用Manager或多套状态源。
- 环境关闭/RO升级/替换前，关联缓存事务必须先释放；关闭后不得再abort或renew。环境身份不能只靠可复用的裸指针地址。
- 同一引擎换库和ResetRevision与Close交错也要有授权边界：已观察旧环境的调用不得在Close完成后又把旧事务写回引擎缓存。保持既有锁顺序，不引入engine mutex与lifecycle_gate锁环。
- 缓存仍应每次renew到最新视图并及时reset，clear的revision单调和新代学习权限不变；不得为性能固定旧视图或长期占读快照。
- 固化正式行为回归：上述换库、RO升级、同路径关闭重开，以及缓存已建立时读代次/关闭的确定性交错；断言无崩溃、能看到最新clear代次、其他持有人继续正常、资源安全释放。不要只测缓存地址相等。
- 使用本轮旧/新探针作为前后反证，先跑定向生命周期、Writer代次与必要Sanitizer，再跑性能。保留5ms/30ms与容量/事务/数据格式，不能简单删除性能门禁换取安全绿灯。
- 按AGENTS在既有算法演化特性中补充缓存事务的环境寿命、关闭/升级失效和性能口径。此次生产持久化路径变更尚未更新算法演化文档。
